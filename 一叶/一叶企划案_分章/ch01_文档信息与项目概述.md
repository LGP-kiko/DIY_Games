## 1.2　项目概述

### 1.2.1　一句话定位

**一片叶子上的四股势力**：世界树的一片叶面上，被逐入地底后与毒瘴熔岩融合的**原初**、来自凋零之叶的末世文明**主宰**、从叶底涌出的**侵蚀**，以及在夹缝中繁衍生息的**混沌**中立生物——三方争夺叶面，而伤害只有「轻型对单」与「重型对群」两种，护甲只有 0–5 级的两个维度，全部战斗结果都由一张**查表**决定。

### 1.2.2　对标目标与完成度定义

玩法骨架对标《红色警戒 2》的**基地建造手感、侧边栏建造 UI、采矿经济、电力机制**（在《一叶》中电力只属于主宰），操作与信息层对标《星际争霸》的**框选编队、战争迷雾、攻守姿态、科技树**；在此之上，用 `Input\一叶.docx` 的**原创战斗模型与四阵容非对称机制**替换掉一切「像某个已有游戏」的部分。

| 维度 | 本作必须达到 | 明确不做 |
| --- | --- | --- |
| 玩法闭环 | 采集源质 → 建造 → 出兵 → 交战 → 摧毁敌方基地 → 结算，可完整打完一局 | 双阵营以上的剧情分支、动态战役 |
| 战斗模型 | **两种伤害类型（轻型对单 / 重型对群）× 两个护甲维度（0–5 级）**，逐字实现设定给出的两条公式，并**以查表方式运行** | 更多伤害类型、命中率、弹道重力 |
| 建筑 | 32 种建筑（原初 10 / 主宰 11 / 侵蚀 10 / 混沌巢穴 1），网格吸附放置、施工蓝图、生产队列、集结点、主动回收 | 建筑进驻步兵、地形改造 |
| 单位 | 35 种单位（三个可选阵营各 10 + 混沌 5），含 4 种单位类型（一般 / 建筑 / 战争 / 奴役）、老兵等级、攻守姿态 | 单位改装、载具多炮塔独立控制 |
| 四阵容非对称 | 原初的再生与吞噬、主宰的奴役与护盾与电力、侵蚀的残骸经济与腐蚀掠夺、混沌的中立与中心强化，**四套机制都必须可被玩家观测到** | 阵容间的完全对称平衡 |
| 经济 | 源质采集 + **残骸经济**（所有阵营共享的战场资源）+ **主动回收**（返还造价 50%） | 多货币、股票式市场 |
| 指挥 | 框选、Shift 追加、双击选同类、Ctrl+数字编队、A 攻击移动、P 巡逻、S 停止、G 原地防守 | 阵型编辑器、路径点可视化编辑 |
| 地图 | 6 张内置地图 + 程序化随机地图 + 双层战争迷雾（黑幕 / 灰雾） | 地图编辑器（P2） |
| 对手 | 三档以上难度的人机 AI，具备三套阵营建造序列、波次进攻、防守反击，以及独立的**混沌中立行为层** | 多人联机（P2 预留 lockstep 接口） |
| 表现 | 等距 2D 渲染、程序化生成的单位与建筑精灵图、爆炸与弹道特效、程序化 WebAudio 音效与音乐、中文语音播报 | 过场动画、真人语音、3D 模型 |
| 模式 | 遭遇战（人机 1v1）+ 4 关战役（教学 / 防守 / 突袭 / 决战） | 联网大厅、成就系统、排行榜 |

### 1.2.3　核心体验支柱

1. **「查表式战斗」的清晰感**：玩家不需要背公式，但能凭直觉记住「重型护甲 4 级几乎免疫 AOE、5 级近乎完全免疫」。**抗性描述 `n/m` 必须直接显示在信息面板上**，让护甲成为可读、可规划的资源，而不是隐藏数值。
2. **「残骸就是战场」的经济感**：每一次击杀都留下 60 秒的残骸，残骸携带被击杀者的最大体力与初始造价。侵蚀靠它吃饭、混沌靠它回血、其他阵营靠它判断战况。**残骸让「打得好」直接等于「经济好」**。
3. **「三套文明，三种活法」的非对称感**：原初用再生把劣势拖成均势；主宰用奴隶把经济拉满、用护盾强攻；侵蚀把整张地图的尸骸变成资源并把敌人的科技抢过来。**三阵营的开局思路必须截然不同**，否则本作就退化成换皮 RTS。
4. **「看得见的战场」**：战争迷雾 + 小地图 + 播报音 + 残骸与混沌巢穴的持续标记，让玩家始终知道自己该做什么。

### 1.2.4　一局游戏的完整流程（目标时长 14–24 分钟）

| 阶段 | 时间 | 玩家在做什么 | 系统在做什么 |
| --- | --- | --- | --- |
| 落子 | 0:00–2:00 | 展开核心、放下第一座资源建筑、拉起采集单位（主宰额外先建聚变反应堆） | 出生点初始化；地图上的混沌巢穴开始按半径 18 格游荡 |
| 起势 | 2:00–6:00 | 建基础生产建筑与第一座防御塔、出第一批 4–6 个战斗单位；侵蚀开始派人去中央回收残骸 | AI 同步建造，双方开始互相侦察 |
| 摩擦 | 6:00–12:00 | 抢扩张矿、压制、试探性交火、用残骸补经济 | AI 第一波进攻（普通难度约 4:00），混沌开始被双方清理 |
| 升级 | 12:00–20:00 | 建高级生产建筑、解锁高级单位、原初开始吞噬混沌、侵蚀完成「腐蚀掠夺」 | AI 出兵规模与频率提升，尝试多线；混沌巢穴被摧毁后该区域不再刷新 |
| 决战 | 20:00+ | 战争单位登场（免疫一切特殊效果），编成混成部队推进 | AI 全力防守并反扑 |
| 结算 | — | 摧毁敌方全部建筑与单位 → 胜利面板 | 统计击毁、损失、采集、残骸回收、主动回收、最大人口与评价 |

### 1.2.5　设计红线（Negative Design）

以下行为会破坏《一叶》的核心乐趣，实施方**禁止**采用：

- **禁止实时套用伤害公式**：设定明确要求「优化：使用查表」。运行时必须查预计算表，不得在伤害结算里做浮点运算（否则不同平台的浮点差异会破坏确定性）。
- **禁止让战争单位受到任何正负面特殊效果**：`py_wrath`、`dm_warlord`、`er_core_unit` 不受老兵、护盾、再生、吞噬、腐蚀、解放、速度增减的影响。这是设定原文，不是可选优化。
- **禁止让玩家直接控制奴役单位**：奴隶只能查看，不能框选、不能下令、不能编队。
- **禁止给主宰以外的阵营加电力**：电力是主宰独有的维护机制，原初与侵蚀的界面**不得出现电力条**。
- **禁止把残骸做成纯视觉特效**：残骸必须携带「最大体力」与「初始造价」两项数据并可被悬停查询，且必须参与存档与状态哈希。
- **禁止用 `Math.random()` 驱动逻辑**、禁止用可变 `deltaTime` 驱动逻辑（见第 2 章）。
- **禁止把美术与音频外包给外部文件**：所有精灵与音效必须在运行时由代码产出。

## 1.3　术语表

| 术语 | 英文 / 键名 | 含义 |
| --- | --- | --- |
| 格 | tile | 地图最小方格，世界坐标 1 格 = 1 单位，渲染为 64×32 像素菱形 |
| tick | tick | 逻辑帧，1 tick = 50 毫秒，1 秒 = 20 tick；所有时间数值以 tick 计 |
| 源质 | Essence | 本作唯一的经济资源 |
| 源质矿脉 / 晶簇 | essence / crystal | 每格 400 / 800 源质的资源点 |
| 轻型 / 重型 | light / heavy | 两种伤害类型：对单 / 对群（AOE） |
| 轻型护甲等级 | lightArmor | 目标受到轻型攻击时使用的护甲等级，0–5 |
| 重型护甲等级 | heavyArmor | 目标受到重型攻击时使用的护甲等级，0–5 |
| 抗性描述 | — | 对外显示格式固定为「轻型护甲等级 / 重型护甲等级」，例如 `3/3` |
| 残骸 | corpse | 单位被摧毁后留下 60 秒的战场物件，携带该单位的最大体力与初始造价 |
| 回收 | salvage | 主动拆除己方建筑或单位，返还造价的 50% |
| 解放 | liberation | 摧毁奴役控制节点后，其半径内的敌方奴役单位转为摧毁者所有 |
| 效率 | efficiency | 实际产值 ÷ 初始设定值 × 100%，用于呈现各阵营的生产力加成 |
| 一般单位 | general | 玩家可正常控制的单位 |
| 建筑单位 | building | 建筑，可被主动回收，初始抗性 3/3 |
| 战争单位 | war | 基础数值强大、**免疫一切正负面特殊效果**的单位 |
| 奴役单位 | slave | 仅执行预设 AI 逻辑、玩家不可直接控制的单位 |
| 混沌 | Chaos | 地图中立生物，非玩家可选阵容；越靠近地图中心数值越高 |
| 控制节点 | controlNode | 被摧毁时触发「解放」的单位（收割者 / 督军 / 侵蚀之核） |
| 腐蚀掠夺 | plunder | 侵蚀的科技解锁方式：摧毁指定目标即解锁对应科技 |
| 战争迷雾 | fog of war | 双层迷雾：黑幕（未探索）+ 灰雾（探索过但当前无视野） |

## 1.4　术语与命名约定

- 游戏内文本全部使用**简体中文**；代码内标识符使用**英文小驼峰**；数据表键名使用**英文小写下划线**（如 `py_core`、`dm_extract`、`er_furnace`）。
- 阵营代号：**PRIMORDIAL** = 原初；**DOMINATOR** = 主宰；**EROSION** = 侵蚀；**CHAOS** = 混沌（中立，玩家不可选）。
- 单位与建筑的键名、中文名、全部数值**只能**来自第 8 章《权威数值表》，而第 8 章由 `Export\yiye_data_pack.json` 与 `Export\一叶_数值设定表.xlsx` 同源生成。实施方必须把 JSON 直接作为 `DATA` 常量载入，**禁止手工转写、禁止改名、禁止新增实体**。
- 伤害与护甲的英文键名固定为：`light` / `heavy`（伤害类型）、`lightArmor` / `heavyArmor`（护甲等级）、`armorDesc`（显示用的 `n/m` 字符串）。
- 资源键名固定为 `essence`（源质）。本作只有这一种经济资源。

## 1.5　数值与结构的唯一权威来源（冲突裁决规则，P0）

本文档篇幅极大，为便于按主题分章撰写，**同一个事实可能被多个章节从不同角度提及**。为避免实施方在遇到表述不一致时无所适从，特此规定**唯一权威来源**：

| 主题 | 权威来源 | 说明 |
| --- | --- | --- |
| 世界观、阵容设定、伤害公式、关键词定义（解放/回收/残骸/效率/抗性描述）、单位类型 | **`Input\一叶.docx`** | 原始设定是**最高权威**；正文任何与之冲突的表述都是错的 |
| 全部数值（建筑/单位/武器的造价、体力、抗性、速度、射程、伤害、射速、科技前置、经济系数、AI 难度参数） | **`Export\一叶_数值设定表.xlsx`** | 17 个工作表；其次是同源的 `Export\yiye_data_pack.json` 与本文档第 8 章 |
| 伤害与护甲的查表结果 | **Excel 的「03-轻型伤害查表」「04-重型伤害查表」** | 基础伤害 1–200 × 护甲等级 0–5，共 2×1200 格 |
| 地图与地形：`MapData` 结构、地形编码、通行性、建造合法性、每格资源 | **第 5 章** | 第 15 章只负责「具体某张地图长什么样」 |
| 技术规范：tick 率、固定步长、PRNG、坐标系统、渲染分层、性能预算 | **第 2 章** | 第 16 章把它扩展为存档 / 回放规格 |
| 玩家命令键名（逻辑层 API） | **第 4 章** | 第 16 章的回放枚举必须与第 4 章 **1:1 对应**；第 13 章的 UI 内部 kind 只是界面命名 |
| 存档与回放的数据结构、状态哈希、命令记录 | **第 16 章** | 第 20 章附录 C 是精简参考版，冲突时以第 16 章为准 |
| UI 布局与交互规则 | **第 13 章** | 但其中出现的任何数值仍以 Excel / 第 8 章为准 |
| 音频键名、合成配方、混音、音乐 | **第 14 章** | EVA 的间隔与音色以第 14 章为准，文案以第 13 章为准 |
| 具体地图与战役关卡内容 | **第 15 章** | 但其数据必须与 `Export\yiye_data_pack.json` 的 `maps` / `campaign` 字段逐字一致 |
| 电脑对手行为、难度参数、建造序列、波次 | **第 12 章** | 第 15 章的「AI 适配说明」是该地图的**覆盖值**，必须显式标注为覆盖 |
| 验收项与判据 | **第 19 章** | 第 18 章的阶段判据若与第 19 章冲突，以第 19 章为准 |

**执行规则（P0）**：

1. 实施方在实现过程中若发现两处表述不一致，**直接按上表的权威来源实现，并在 `SELFTEST.md` 中记录该冲突**，不需要停下来询问。
2. 上表未覆盖的主题，按「更具体的章节优先于更概括的章节」判断。
3. **任何章节都不得新增第 8 章数据表之外的单位、建筑或武器**。战役与地图如果需要特殊效果，只能用已有的实体 + 显式标注的「关卡覆盖参数」。
4. 单位与建筑的 **key 命名以第 8 章为准**；同一实体在不同章节出现多个中文名时，以第 8 章的中文名为准。
5. 本作只有**一种资源**（源质）、**三个可选阵容**（原初 / 主宰 / 侵蚀）与**一个中立势力**（混沌）。若在任何章节看到其他资源名、其他阵营代号或「通用电力」之类的表述，一律视为笔误并按本表裁决。
