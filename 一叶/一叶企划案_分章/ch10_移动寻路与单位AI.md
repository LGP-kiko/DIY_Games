## 10　移动寻路与单位AI

### 10.1　移动模型（P0）

| 参数 | 规定 |
| --- | --- |
| 单位半径 | 步兵 `0.25` 格；载具 `0.40` 格；建筑按外接矩形（不可推动，占地在第 8 章建筑表已固定，如 `py_core` 3×3、`py_maw` 3×4、`py_spike` 1×1） |
| 位置精度 | 内部用 `Number`（双精度）存储，但**同一 tick 内的移动结果必须可复现**（只用加减乘除与 `Math.round`，禁止三角函数参与位移计算） |
| 移动速度 | `每 tick 位移 = 单位速度(格/秒) / 20 × 地形系数`；速度取第 8 章单位表的「速度(格/秒)」列（`py_rock` 1.5、`py_runner` 3.4、`dm_mbt` 2.3、`dm_bomber` 4.6、`er_stalker` 3.2、`ch_behemoth` 1.4 等），地形系数见 10.2 通行性矩阵 |
| 加速模型 | 无加速度模型（瞬时到达目标速度），简化且便于平衡；仅转向有速率限制 |
| 转向 | 每 tick 最多改变 1 个 8 向档位（45°）；车体与炮塔分别记录朝向。180° 调头需 4 tick（0.2 秒），与第 8 章「每 tick 转向档位 1 档（45°）」一致 |
| 到达判定 | 与目标点距离 ≤ `max(0.20, speed / 20)` 视为到达 |
| 停止 | 收到 `stop` 后立即停止移动，但本 tick 的位移已发生（不回退） |
| 位移合法性 | 计算出的新位置若落入阻挡格，则**分轴测试**：先只移动 x，再只移动 y，都不行则原地停留并触发卡住检测 |
| 高度变化 | 移动进入不同高度格时，`z` 立即更新为格高度；渲染时按 `Z_STEP`（每层 12 像素）抬升 |
| 单位推挤 | 两个敌方/己方单位重叠时，每 tick 相互推开 `0.05` 格（仅对可移动单位），但不改变其移动目标；建筑不可被推动 |
| 战争单位 | `py_wrath`（原初之怒）、`dm_warlord`（督军）、`er_core_unit`（侵蚀之核）**不受任何速度增减影响**：地形系数、减速类效果、神速光环一律对其无效，位移恒为 `速度 / 20`（`air` 单位除外，见 10.5） |

> **本作的移动类型共 5 种**：`foot`（步兵）、`track`（履带）、`wheel`（轮式）、`hover`（悬浮）、`air`（飞行）。第 8 章单位表的「移动」列给出每个单位所属的类型。其中 **`hover`（悬浮）是为 P2 扩展保留的类型，第 8 章的 35 种单位中目前没有任何单位使用它**；它存在的意义是让「毒瘴 `miasma` 只被悬浮与飞行单位通行」这条地形规则在数据层面成立（见第 5.2、5.3 节）。

### 10.2　寻路系统（P0）

采用**格子 A***（8 方向），配合路径缓存与请求预算，保证 200 单位下的确定性。

| 要素 | 规定 |
| --- | --- |
| 网格 | 使用地图加载流程构建的 `blocked`（阻挡）与 `moveCost`（代价）两张 `Uint8Array`，尺寸 96×96 |
| 通行性 | 按单位的 `moveType` 查询 10.2 的通行性矩阵（5 种移动类型 × 12 种地形）；`air` 单位**不寻路**（直线飞行） |
| 代价 | 预计算整数代价（放大 100 倍避免浮点）：`stepBase = round(100 / speedMod)`。以 `foot` 为例：脉络 `vein` = 80、叶肉 `flesh` / 腐土 `rot` = 100、灰沙 `ash` = 105、源质矿脉 `essence` / 晶簇 `crystal` = 118、叶底裂隙 `rift`（高差 1）= 167、岩桥 `bridge` = 100；正交移动代价 = `stepBase`，对角移动代价 = `round(stepBase × 1.414)`；高差上升/下降 1 层额外 `+40` |
| 启发式 | 八方向距离（octile，与代价同量纲且**不高估**）：`h = 100 × max(dx, dy) + 41 × min(dx, dy)`（等价于 `100×(dx+dy) - 59×min`，约等于 `100×√(dx²+dy²)` 的上界） |
| 开放表 | 二叉堆（数组实现），以 `f` 为键，`f` 相同时以 `h` 较小者优先，再相同以节点索引较小者优先（保证确定性） |
| 关闭表 | `Uint8Array(w*h)` 复用缓冲区 + `generation` 计数避免每次清零 |
| 节点上限 | 单次寻路最多扩展 **2000** 节点；超出则放弃并返回「部分路径」（走到已探索区域中 `h` 最小的节点） |
| 请求预算 | 每 tick 最多处理 **8** 条寻路请求；队列上限 256，超出时丢弃最旧的非玩家请求 |
| 路径缓存 | LRU 缓存 256 条，键 = `(起点格, 终点格, moveType)`；**任何阻挡图变化都会递增 `blockVersion` 使全部缓存失效**——建筑建成/摧毁、**残骸出现或过期（残骸保留 60 秒 = 1200 tick，见第 8 章）**、混沌巢穴 `ch_lair` 被摧毁都会触发。残骸过期造成的批量失效按 tick 归并，同一 tick 内只递增一次 |
| 路径平滑 | A* 结果做「视线合并」：用 Bresenham 检查连续两路点之间是否无阻挡，可合并则删除中间点；合并后路径点上限 24 个，超出则按比例抽样 |
| 目标不可达 | 若终点格不可通行，则在终点周围 3 格内搜索最近的可通行格作为实际终点；仍失败则**返回空路径并给出「无法抵达」反馈** |
| 复用 | 同一单位重复下达同一目标命令时，若已有有效路径则直接复用 |
| 毒瘴绕行 | 终点位于毒瘴或浅毒滩上的矿点侧时，`track` / `wheel` 单位必须绕行至最近的岩桥 `bridge` 入口；若整簇资源点在该移动类型的连通块上不可达，则直接返回空路径并提示「该单位无法抵达此矿区」（不得让单位反复撞击毒瘴边缘） |

**A* 伪代码（P0）**

```js
function findPath(startTile, goalTile, moveType) {
  const cacheKey = key(startTile, goalTile, moveType);
  const cached = pathCache.get(cacheKey);
  if (cached && cached.version === blockVersion) return cached.path;

  const open = new BinaryHeap();          // 以 f 排序，f/h/index 三级确定性比较
  const gScore = scratch.gScore;          // Int32Array(w*h)，用 generation 标记复用
  const cameFrom = scratch.cameFrom;      // Int32Array(w*h)
  const gen = ++scratch.generation;

  const start = idx(startTile), goal = idx(goalTile);
  gScore[start] = 0; scratch.gMark[start] = gen;
  open.push({ node: start, f: heuristic(start, goal), h: heuristic(start, goal) });

  let expanded = 0, bestNode = start, bestH = heuristic(start, goal);
  while (!open.isEmpty() && expanded < 2000) {
    const cur = open.pop();
    if (cur.node === goal) return smooth(reconstruct(cameFrom, cur.node));
    expanded++;
    for (const dir of DIRS8) {
      const nb = neighbor(cur.node, dir);
      if (nb < 0) continue;
      // passable() 内部按 moveType 查 12×5 通行性矩阵：
      //   foot  可走 flesh/rot/ash/vein/shallow/essence/crystal/bridge + 高差 1 的 rift(×0.60)
      //   track 可走 flesh/rot/ash/vein/essence/crystal/bridge
      //   wheel 可走 flesh/rot/ash/vein/essence/crystal/bridge
      //   hover 可走除 strata 与 spore 以外的一切（含 miasma、shallow）
      if (!passable(nb, moveType)) continue;
      if (dir.diagonal && (blockedForDiagonalCorner(cur.node, dir))) continue; // 禁止穿角
      const step = stepCost(cur.node, nb, dir);
      const tentative = gScore[cur.node] + step;
      if (scratch.gMark[nb] === gen && tentative >= gScore[nb]) continue;
      scratch.gMark[nb] = gen;
      gScore[nb] = tentative;
      cameFrom[nb] = cur.node;
      const h = heuristic(nb, goal);
      open.push({ node: nb, f: tentative + h, h: h });
      if (h < bestH) { bestH = h; bestNode = nb; }
    }
  }
  // 未找到完整路径：使用「最接近目标」的部分路径
  const path = smooth(reconstruct(cameFrom, bestNode));
  pathCache.set(cacheKey, { path, version: blockVersion });
  return path;
}
```

| 规则 | 说明 |
| --- | --- |
| 禁止穿角 | 对角移动时若两个正交邻格中有任一不可通行，则该对角移动不合法（防止单位穿过建筑缝隙与毒瘴夹角） |
| 决定性 | 堆比较、邻居遍历顺序（固定 8 方向数组顺序）、起点终点都必须严格确定，不允许依赖对象键顺序 |
| 退化情况 | 起点 = 终点：返回单点路径；起点被阻挡：先在 1 格内找最近可通行格作为起点 |
| 岩桥必共享 | 岩桥 `bridge` 对 5 种移动类型全部可通行，是高差或毒瘴隔断两侧之间唯一的载具通道；A* 不得为 `track` / `wheel` 生成任何跨越毒瘴的捷径 |

### 10.3　局部避障与拥挤处理（P0）

A* 只负责长距离路径，短距离的互相挤撞必须靠**分离力（separation steering）**处理。

| 规则 | 规定 |
| --- | --- |
| 分离力计算 | 每 tick 对每个移动中的单位，遍历其 **1.0 格**内的其他可移动单位（用空间哈希网格加速，格子大小 = 1 格），对每个邻居施加 `push = (1 - d/1.0) × 0.06` 格的反向位移 |
| 分离力上限 | 单 tick 由分离力产生的总位移 ≤ `0.5 × 移动速度 / 20` 格（防止被推得比走路还快） |
| 不产生分离的对象 | 建筑、**钻地移动中的 `py_burrow` / `er_digger`**、隐形且未被侦测的 `er_stalker`、飞行与地面单位之间（空中/地面互不碰撞） |
| 友军通行 | 已停止的己方单位会主动让路：若被移动中的友军推挤超过 1 秒，静止方移动到相邻空格（P1） |
| 卡住检测 | 单位连续 **20 tick** 位移 < 0.05 格且仍有移动命令 → 判定卡住，执行下列恢复序列：① 清空路径并重新寻路（同目标）；② 若仍卡住，改用**相邻格**为目标（向目标方向偏移 1–2 格）；③ 若仍卡住，原地待机 1 秒后重试，最多重试 3 次，之后放弃命令并给出「无法抵达」反馈 |
| 死锁 | 多个单位互相卡在对角缝隙时，卡住检测会各自独立触发重寻路；实施方**不得**用随机抖动解决（会破坏确定性），只能按上述确定性序列处理 |
| 毒瘴边缘卡住 | `track` / `wheel` 单位在毒瘴或浅毒滩边缘反复触发「分轴测试失败」时，按卡住序列处理，并在第 ② 步把目标改成**最近的岩桥入口格**而不是简单偏移 1–2 格 |
| 奴役单位不参与 | `dm_slave` 不占用分离力预算的优先级队列，也不接受玩家框选产生的阵型槽位；其避障完全由自己的四态循环决定（见 10.6） |

**空间哈希（P0）**：每 tick 重建一次，格子大小 1 格，`bucket[tileIndex] = [entityId, ...]`。用于分离力、溅射命中、索敌粗筛。重建成本 O(n)，n ≤ 320，可接受。

### 10.4　阵型与群体移动（P0）

框选多个单位下 `move` 命令时，必须分配**阵型槽位**，否则单位会挤成一团。

| 规则 | 规定 |
| --- | --- |
| 槽位生成 | 以点击点为中心生成方阵：`cols = ceil(sqrt(n))`，列间距 `1.0` 格，行间距 `1.0` 格，按「从中心向外螺旋」的顺序生成槽位（保证前面的单位先占内圈） |
| 单位排序 | 参与分配的单位按「当前与目标点距离」升序排列，更近的单位分配更靠中心的槽位 |
| 槽位合法性 | 槽位若不可通行，则在 2 格范围内螺旋搜索最近的合法格；全部非法则该单位的目标点 = 点击点（直接前往）。**槽位合法性必须按该单位自己的 `moveType` 判定**：步兵槽位可以落在浅毒滩上，履带与轮式单位的槽位不能落在浅毒滩或毒瘴上，悬浮单位可以落在毒瘴上 |
| 地面/空中分离 | 飞行单位使用独立槽位（间距 1.2 格，且不参与地面槽位计算） |
| 建筑不可移动 | 框选中若包含建筑且下达了移动命令，建筑**忽略**该命令（不报错） |
| 奴役单位不可下令 | 框选中若包含 `dm_slave`，该奴隶**不占用槽位、不接收命令**，框选面板只显示其状态（这对主宰玩家是常态，见 10.6） |
| 战争单位单列 | `py_wrath` / `dm_warlord` / `er_core_unit` 各自占用独立槽位且不受地形系数影响，因此可以与其他单位同排行军而不会被挤开 |
| 到达行为 | 所有单位抵达槽位后各自 `guard`；`attack_move` 则在抵达后转为当前姿态 |
| 编队行进 | 不实现「保持队形同步移动」（那是《星际争霸 2》的高级特性）；单位各自走各自的路，允许被地形分散 |

| `track` 履带 | **不可通行浅毒滩 `shallow` 与毒瘴 `miasma`**；灰沙 `ash` 惩罚最大（×0.90）；过毒瘴只能走岩桥 `bridge` |
| `wheel` 轮式 | **不可通行浅毒滩 `shallow` 与毒瘴 `miasma`**；脉络 `vein` 加成最高（×1.25），灰沙 `ash` 最差（×0.85） |
| `hover` 悬浮 | **全作唯一可通行毒瘴 `miasma` 的地面移动类型**（×0.90）；同时可通行浅毒滩 `shallow`（×1.00）；不可通行岩层 `strata` 与孢子林 `spore`；不可爬叶底裂隙 |
| `air` 飞行 | **不寻路**：直线飞向目标点；忽略地形与建筑阻挡；不做分离力（空中单位之间也不碰撞）；不可被对地武器攻击；自身可以有 `z = 0.8`（`py_wing` / `er_bloat` / `ch_moth` 等扑翼单位）/ `1.2`（`dm_bomber` 固定翼）的悬停高度 |
| 飞行落地 | 空中单位不设停机坪，抵达目标点后直接悬停（`dm_bomber` 每次出击只携带 1 发集束炸弹，投弹后必须返回任一己方卸矿点或核心上方盘旋等待装填，见第 8 章 `ammo: 1`） |

### 10.6　单位 AI 状态机（P0）

每个单位持有 `state`、`orderQueue`（最多 8 条）与 `stance`。`stance` 的三种取值与「战争单位」的关系见本节末尾。

| 状态 | 键名 | 进入条件 | 每 tick 行为 | 退出条件 |
| --- | --- | --- | --- | --- |
| 待机 | `idle` | 无命令 | 索敌（按姿态）；炮塔回正 | 有命令 → 对应状态；有目标 → `attack` |
| 防守 | `guard` | 抵达目标且无后续命令 | 原地索敌（按姿态）；`Aggressive` 可追击 8 格 | 新命令 |
| 移动 | `move` | `move` 命令 | 沿路径移动；不主动攻击（仅 `Aggressive` 姿态下会停下还击，P1） | 抵达 → `guard`；新命令 |
| 攻击移动 | `attackMove` | `attack_move` 命令 | 沿路径移动；`acquireRange` 内有敌 → 停下进入 `attack`，目标死亡后继续前往终点 | 抵达 → 恢复原姿态 `guard` |
| 巡逻 | `patrol` | `patrol` 命令 | 在两个端点之间往返移动；端点间按 `attackMove` 逻辑接敌 | 新命令 |
| 攻击 | `attack` | 有锁定目标 | 若目标在射程内 → 开火；否则朝目标移动（不重寻路，直接朝目标方向走，每 20 tick 重寻路一次） | 目标死亡 → 队列下一条命令或 `guard` |
| 采集 | `harvest` | `harvest` 命令（仅采集单位） | 见 10.6「采集与奴役单位的四态循环」 | 新命令 |
| 修理 | `repair` | `repair` 命令（仅工程单位：`py_shaper` / `dm_drone` / `er_sporework`） | 移动到目标建筑边缘并进入 | 完成后自身删除 |
| 占领 | `capture` | `capture` 命令（仅工程单位） | 移动到目标建筑边缘并进入 | 完成后自身删除 / 目标血量回升 → 中止并 `guard` |
| 死亡 | `dead` | `hp ≤ 0` | 无 | 本 tick 结束时移除 |

| AI 规则 | 规定 |
| --- | --- |
| 索敌节流 | 单位索敌每 tick 执行，但**只对 `acquireRange` 内的候选做评分**（用空间哈希粗筛），实际开销与单位数成线性 |
| 决策分帧（P1） | 当单位数 > 120 时，把索敌分摊到 2 个 tick（按 `id % 2` 分组），保证 tick 预算 |
| 命令队列 | `Shift` 追加的命令进入队列；执行完一条后自动取下一条；`stop` 清空队列 |
| 命令中断 | 玩家新命令**立即清空队列**并执行（除非按住 Shift）。**例外：`dm_slave` 与任何 `kind = 'slave'` 的单位不接受玩家任何命令**（框选、右键、`stop`、`patrol` 全部无效，`?debug=1` 下应在命令面板显示「奴役单位：仅执行预设 AI」） |
| 目标合法性复查 | `attack` 状态下每 10 tick 复查目标是否仍合法（未死亡、仍在 `acquireRange × 1.3` 内） |
| 不可达目标 | 连续 3 次重寻路失败 → 放弃该目标并恢复 `guard`，播放一次「无法抵达」反馈 |
| **原初·再生** | 原初任何单位在**脱战 8 秒**（160 tick）后，每秒回复 **2%** 最大体力；原初建筑为每秒 **1%**。判定「脱战」= 该实体连续 160 tick 既未开火也未受到伤害。再生在 `idle` / `guard` / `move` / `harvest` / `repair` 状态下均生效，在 `attack` / `attackMove` 开火后立即停止计时 |
| **主宰·护盾回复** | `dm_reaper`（收割者）与 `dm_warlord`（督军）的护盾上限 = 最大体力 × 0.5，**脱战 5 秒**（100 tick）后按 **10%/秒** 回复。护盾优先吸收伤害；`dm_shield`（护盾发生器）半径 7 格内护盾上限 +50%、回复速度 +100% |
| **混沌·吞噬残骸** | 混沌单位体力不满且 6 格内存在残骸时，**优先中断当前状态**前往吞噬，按该残骸携带的**最大体力的 100%** 恢复体力（残骸同时被消耗）。体力回满后返回 `idle`。该行为优先于游荡与索敌，因此玩家可以用残骸「钓」混沌单位 |
| **侵蚀·自动回收** | `er_furnace`（残骸熔炉）半径 10 格内的残骸每 20 tick 被自动吸收一次，按残骸的**初始造价的 25%** 转化为源质（无熔炉时为 10%，但 10% 只对侵蚀玩家出现在视野内并主动回收的残骸生效）。熔炉吸收不需要任何单位参与 |
| **战争单位免疫** | `py_wrath` / `dm_warlord` / `er_core_unit` 不受任何正负面特殊效果影响：**速度增减、护盾、再生、老兵、腐蚀、吞噬、解放**全部对其无效；姿态开关对其无效（永远视为 `Aggressive` 好斗姿态，见下表） |

**姿态（stance）与战争单位（P0）**

| 姿态 | 键名 | 行为 | 对战争单位 |
| --- | --- | --- | --- |
| 好斗 | `Aggressive` | 索敌半径 = `acquireRange`，可追击 8 格 | **永远为此姿态**，玩家点击「防守 / 固守」无效（UI 置灰） |
| 防守 | `Defensive` | 索敌半径 = `acquireRange`，不追击 | 无效 |
| 固守 | `HoldFire` | 不主动索敌，只在被攻击后还击 | 无效 |

**采集与奴役单位的四态循环（P0）**

| 规则 | 规定 |
| --- | --- |
| 奴隶 AI 四态 | `dm_slave`（`kind = 'slave'`）**永远只在这四个状态间循环，没有第五个状态**：① `toMine`（前往最近的源质矿脉 / 晶簇格）→ ② `harvest`（采集至 240 容量上限或该格采空）→ ③ `toDrop`（返回最近的己方卸矿点：`dm_extract` 矿产中心）→ ④ `unload`（以 240/秒 卸货）。卸完立刻回到 ①，目标矿点每次重新选择「最近的未采空格」 |
| 奴隶不可控 | 玩家**无法通过框选、右键、编队或快捷键改变奴隶行为**；奴隶不出现在框选结果中，即使被框选也不进入 `orderQueue`。主宰的矿产中心每 20 秒自动生成 1 名奴隶（不占人口、不花源质） |
| 奴隶采集速率 | 主宰奴役单位生产力 ×1.4，即 40 × 1.4 = **56 源质/秒**；原初 `py_gatherer` 为 40 × 1.2 = **48 源质/秒**；侵蚀 `er_drinker` 与基准相同为 40 源质/秒（靠残骸回收补足） |
| 被解放后 | 当敌方摧毁 `dm_reaper` / `dm_warlord` / `er_core_unit`（奴役控制节点）时，以其为中心 **10 格**内（侵蚀建成 `er_assimil` 同化塔后 **20 格**）的敌方奴隶**立即转为摧毁者所有**。被解放的奴隶**立刻退出上述四态循环，转入普通采集单位逻辑**（`state` 重置为 `idle`，进入框选集合，接受玩家 `move` / `harvest` / `stop` 命令），保留当前体力与携带的源质，且仍不占人口 |
| 回收站压榨 | 主宰的 `dm_recycler`（回收站）可对已解放或敌方的奴隶执行「压榨」：立即销毁该奴隶并返还其造价的 50% 源质（奴隶造价为 0，因此压榨的实际收益来自已解放奴隶携带的源质与其占领的资源位置） |
| 战争单位不参与 | 若被解放者是战争单位（实际不可能，因为战争单位免疫解放），该规则不触发；实施方必须显式跳过 `kind === 'war'` 的实体 |

### 10.7　移动与 AI 的性能预算（P0）

| 项目 | 预算 |
| --- | --- |
| 寻路 | ≤ 8 条/tick，单条 ≤ 2000 节点扩展，合计 ≤ 3 ms |
| 分离力 | 200 移动单位 × 平均 3 邻居 = 600 次计算，≤ 0.6 ms |
| 索敌评分 | 200 单位 × 平均 4 候选 = 800 次评分，≤ 0.5 ms |
| 空间哈希重建 | O(n)，≤ 0.2 ms |
| 路径跟随 | 200 单位 × 常数，≤ 0.4 ms |
| 再生 / 护盾 / 吞噬扫描 | 原初脱战计时 200 项 + 主宰护盾 20 项 + 混沌 6 格残骸查询（复用空间哈希，≤ 12 个混沌单位），≤ 0.3 ms |
| 侵蚀熔炉吸收 | 每座 `er_furnace` 每 20 tick 扫描半径 10 格（≈ 314 格）内的残骸表，残骸总数上限 256，≤ 0.2 ms |
| 合计 | ≤ 5.2 ms（低于第 2 章 8 ms 总预算） |

### 10.8　移动相关的表现反馈（P0）

| 事件 | 表现 |
