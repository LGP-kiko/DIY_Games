## 2　交付与技术规范

本章是**最高优先级约束**。任何与本章冲突的设计都以本章为准；本章未要求的自由发挥不作限制，但**禁止引入第三方库、外部素材文件与构建工具链**。《一叶 / One Leaf》的全部画面与声音都必须在运行时由代码生成：地形是路径填充，单位是矢量图元，音效是 WebAudio 振荡器与噪声，**没有任何一张图片、没有任何一个音频文件**。

### 2.4　时间与循环规范（P0）

游戏逻辑必须运行在**固定步长**上，与渲染帧率无关。基准：**1 逻辑 tick = 50 毫秒，即 20 tick/秒**（与第 8 章全局常量表的 `TICK_MS` 逐值一致）。所有游戏时间量（建造时间、射速、护盾回复、残骸保留、科技解锁计时）均以 tick 为单位存储，禁止以秒或毫秒存储逻辑时间。

```js
// ===== 主循环（P0，必须按此实现） =====
const TICK_MS = 50;              // 20 Hz，见第 8 章全局常量表
const MAX_CATCHUP_TICKS = 5;     // 单帧最多追 5 个 tick，防止卡顿雪崩
let accumulator = 0;
let lastFrameTime = 0;

function frame(now) {
  requestAnimationFrame(frame);
  if (lastFrameTime === 0) { lastFrameTime = now; return; }
  let elapsed = now - lastFrameTime;
  lastFrameTime = now;
  if (elapsed > 1000) elapsed = 1000;          // 切标签页回来不要补一百帧
  accumulator += elapsed * gameSpeed;           // gameSpeed ∈ {0.75, 1, 1.5, 2}
  let steps = 0;
  while (accumulator >= TICK_MS && steps < MAX_CATCHUP_TICKS) {
    simulateOneTick();                          // 只在这里推进世界状态
    accumulator -= TICK_MS;
    steps++;
  }
  if (steps === MAX_CATCHUP_TICKS) accumulator = 0;
  const alpha = accumulator / TICK_MS;          // 渲染插值系数 0..1
  render(alpha);                                // 渲染只读世界，不改世界
}
```

| 规则 | 规定 |
| --- | --- |
| 逻辑与渲染分离 | `simulateOneTick()` 内**禁止**出现任何绘制调用；`render()` 内**禁止**修改任何游戏状态（镜头除外） |
| 渲染插值 | 单位与弹道按 `prevX + (x - prevX) * alpha` 插值绘制；建筑与地形不需要插值 |
| 暂停 | 暂停时**不推进**累加器，`accumulator = 0`，防止恢复瞬间追帧抖动 |
| 倍速 | 通过 `elapsed * gameSpeed` 实现，逻辑本身不变；**禁止**修改 `TICK_MS` |
| 追帧上限 | 单帧最多 5 tick；超出后丢弃剩余时间，宁可慢一点也不要卡死 |
| 后台标签 | `document.hidden` 为真时暂停逻辑（单机模式），并在恢复时清零累加器 |
| 残骸计时 | 残骸保留时长是 `CORPSE_TTL_SEC = 60` 秒 = **1200 tick**，必须作为整数 tick 倒计时存在实体上，禁止用 `Date.now()` 计算 |

### 2.5　确定性伪随机（P0）

战斗、AI、地图生成、混沌巢穴的初始布点、特效**禁止**使用 `Math.random()`。必须实现两条以上独立随机流，互不干扰，且状态可序列化（供存档/回放）。

```js
// mulberry32：状态为单个 32 位整数，便于存档
function createRng(seed) {
  let s = seed >>> 0;
  return {
    next() {                       // [0,1)
      s = (s + 0x6D2B79F5) >>> 0;
      let t = s;
      t = Math.imul(t ^ (t >>> 15), t | 1);
      t ^= t + Math.imul(t ^ (t >>> 7), t | 61);
      return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
    },
    int(n) { return Math.floor(this.next() * n); },          // [0,n)
    range(a, b) { return a + this.next() * (b - a); },       // [a,b)
    chance(p) { return this.next() < p; },
    getState() { return s >>> 0; },
    setState(v) { s = v >>> 0; }
  };
}
// 五条独立流：地图 / 战斗 / AI / 特效 / 环境（后两条为纯表现，不参与逻辑哈希）
const RNG = {
  map:     createRng(seed ^ 0x9E3779B9),
  combat:  createRng(seed ^ 0x85EBCA6B),
  ai:      createRng(seed ^ 0xC2B2AE35),
  fx:      createRng(seed ^ 0x27D4EB2F),   // 表现层：粒子角度、音高抖动
  ambient: createRng(seed ^ 0x165667B1)    // 表现层：环境音、装饰动画
};
```

| 随机流 | 是否参与逻辑与状态哈希 | 用途 |
| --- | --- | --- |
| `RNG.map` | 是 | 地图生成、源质矿脉与晶簇的富集度抖动、混沌巢穴布点与倍率、装饰物（加载时一次性消耗） |
| `RNG.combat` | 是 | 重型溅射的落点微扰、弹道散布、吞噬与解放的结算顺序打散 |
| `RNG.ai` | 是 | AI 决策抖动、目标选择、建造序列超时判定、奴隶采矿点的分配 |
| `RNG.fx` | **否**（表现层专用） | 粒子、爆炸火花、音高抖动 |
| `RNG.ambient` | **否**（表现层专用） | 环境音、孢子林与毒瘴的装饰动画 |

> 只有 `map` / `combat` / `ai` 三条流的内部状态需要写入存档与状态哈希；`fx` / `ambient` 允许自由消耗，不影响确定性（第 16 章会给出「额外消耗 10 万次 fx 随机数后逻辑哈希不变」的测试用例）。

| 规则 | 规定 |
| --- | --- |
| 分流 | 四个流必须彼此独立；不允许一个系统消耗另一个系统的随机数 |
| 逻辑内随机 | 仅允许用于：伤害溅射落点微扰、AI 决策抖动、地图生成、混沌巢穴倍率 |
| 表现层随机 | 特效粒子、音效音高可用 `RNG.fx`；若为纯表现可降级使用 `Math.random()`，但必须与逻辑隔离 |
| 存档 | **三条逻辑流**（`map` / `combat` / `ai`）的状态必须写入存档；两条表现流（`fx` / `ambient`）不入存档 |
| 遍历顺序 | 所有实体的迭代必须基于**有序数组 + 稳定排序键（entity.id 升序）**，禁止 `for...in` 遍历对象来驱动逻辑 |
| 查表禁止随机 | 伤害结算必须**纯查表**（第 8 章轻型/重型伤害表），查表结果不得再叠加任何随机 |

### 2.6　坐标系统与数学约定（P0）

| 名称 | 定义 | 取值范围 |
| --- | --- | --- |
| 格坐标 `(tx, ty)` | 地图格索引，整数 | `0 ≤ tx < mapW`，`0 ≤ ty < mapH` |
| 世界坐标 `(x, y)` | 1 格 = 1 单位，格中心 = `(tx + 0.5, ty + 0.5)`，浮点 | `[0, mapW]` |
| 层高 `z` | 离散整数高度层（叶底裂隙与年轮高台） | `0 ≤ z ≤ 4` |
| 屏坐标 | 等距投影结果，像素 | 画布内 |

```js
// 等距投影（P0）：菱形瓦片 64×32 像素，每层高度抬升 12 像素
const TILE_W = 64, TILE_H = 32, Z_STEP = 12;
function worldToScreen(x, y, z) {
  return { sx: (x - y) * (TILE_W / 2), sy: (x + y) * (TILE_H / 2) - z * Z_STEP };
}
function screenToWorld(sx, sy) {           // 用于鼠标拾取（z=0 平面）
  const a = sx / (TILE_W / 2), b = sy / (TILE_H / 2);
  return { x: (a + b) / 2, y: (b - a) / 2 };
}
```

| 数学规则 | 规定 |
| --- | --- |
| 距离比较 | 一律使用**平方距离** `dx*dx + dy*dy` 与 `range*range` 比较，避免 `Math.sqrt` 的跨平台浮点差异 |
| 射程单位 | 第 8 章武器表的「射程（格）」必须以**格**为单位参与上述平方比较；例如 `w_py_rock` 射程 4.5 格 → `4.5 * 4.5 = 20.25` |
| 混沌中心距离 | 计算 `clamp(1.6 - 1.2 × (d / dMax), 0.8, 1.6)` 时需要 `sqrt`，这是**唯一允许开方**的地方，且必须用整数格坐标计算并缓存结果 |
| 朝向 | 存为 8 向枚举 `0..7`（0=正东，逆时针每 45° 一档）用于精灵选择；炮塔朝向单独存储 |
| 角度插值 | 用 8 向整数做转向，**每 tick 最多转 1 档（45°）**，开火角度容差 22.5°（见第 8 章战斗与状态参数） |
| 定点化 | 存档时所有浮点坐标乘以 1000 取整（`Math.round(x*1000)`）存储 |
| 颜色 | 阵营主色取自第 8 章阵营总览：原初 `#4a8f3c`、主宰 `#3f6fd0`、侵蚀 `#8a4bd0`、混沌 `#c08a2e`；每方再派生暗/亮两档用于描边与高光；敌我识别统一由「己方 = 阵营主色描边 / 敌方 = `#ff4d4d` 描边」承担 |
| 弹药与计时 | 一律以 tick 整数计数，例如射速 55 tick = 2.75 秒；`CORPSE_TTL_SEC = 60` → 1200 tick |

### 2.7　渲染管线规范（P0）

| 层序 | 层名 | 内容 | 每帧重建 |
| --- | --- | --- | --- |
| L0 | 地形底图 | 预渲染到 **16×16 格的离屏分块 canvas**（每块 1024×512 像素），12 种地形（叶肉/腐土/灰沙/脉络/岩层/毒瘴/浅毒滩/叶底裂隙/源质矿脉/晶簇/岩桥/孢子林）只在地形变化时重绘 | 否 |
| L1 | 迷雾层 | 一张地图尺寸的离屏 canvas（96×96 → 240×240 像素），黑幕/灰雾，每 5 tick 更新一次 | 是（低成本） |
| L2 | 贴花层 | 弹坑、**残骸**（携带所属单位的原始轮廓与阵营色，60 秒后淡出）、矿脉减少痕迹，画在 L0 之上，分块缓存 | 否 |
| L3 | 实体层 | 建筑 + 单位，按 `(x + y)` 升序绘制，同值时建筑在前；影子先画；施工中的蓝图以 55% 透明绘制 | 是 |
| L4 | 特效层 | 弹道、爆炸、毒雾、孢子、护盾六边形波纹、解放冲击环 | 是 |
| L5 | 选择层 | 选择圈、血条与护盾条、集结点连线、建造网格、**残骸悬停信息气泡** | 是 |
| L6 | UI 层 | 另起一张 canvas（`#ui`）叠加在游戏 canvas 之上，仅在有变化时重绘 | 条件 |

| 渲染规则 | 规定 |
| --- | --- |
| 裁剪 | 每帧先计算可视矩形，跳过完全在屏幕外的实体（用 `(x+y)` 与投影包围盒粗判） |
| 精灵缓存 | 每种「单位类型 × 阵营 × 8 向 × 2 动画帧」预渲染为一张离屏 canvas，运行时只 `drawImage`；单个精灵尺寸 ≤ 48×48 |
| 缩放 | 镜头缩放只改变 `ctx.setTransform` 的缩放与平移，不重新生成精灵（最近邻放大以保持像素硬边） |
| 像素对齐 | 缩放 ≥ 1 时所有绘制坐标 `Math.round`，避免半像素模糊 |
| DPR | `canvas.width = innerWidth * devicePixelRatio`，但 DPR 上限取 2，防止 4K 屏性能崩坏 |
| 免疫的视觉表达 | 战争单位（`py_wrath` / `dm_warlord` / `er_core_unit`）身上**不得**出现老兵角标、护盾环、再生辉光、腐蚀变色中的任何一种；这是「免疫一切正负面特殊效果」在画面上的唯一正确表现 |
| 奴役单位的视觉表达 | 奴隶（`dm_slave`）不绘制选择圈；悬停时只绘制信息气泡与脚下高亮环，**不得绘制绿色可选中高亮** |

### 2.8　性能预算（P0）

| 项目 | 预算 | 说明 |
| --- | --- | --- |
| 单 tick 逻辑耗时 | ≤ 8 ms（200 单位 + 120 建筑 + 30 弹道 + 200 残骸） | 超出时按 tick 预算降级寻路请求 |
| 单帧渲染耗时 | ≤ 12 ms | 1080p、缩放 1.0、200 单位 |
| 寻路请求 | ≤ 8 条/tick，队列上限 256，超出丢弃最旧的非玩家命令请求 | 玩家命令的请求优先级最高 |
| 视野更新 | 每 5 tick 全量重算一次（96×96 = 9216 格，位运算） | 不使用增量复杂度 |
| 伤害结算 | **每 tick ≤ 0 次公式运算**：全部走预计算查表，查表本身是数组索引 | 见第 8 章「优化要求」 |
| 残骸表 | 同时存在的残骸 ≤ 200；超过时按「最先到期」淘汰并立即释放占位 | 残骸是四套机制的载体，禁止无限增长 |
| 对象数量 | 单位 ≤ 200、建筑 ≤ 120、弹道 ≤ 300、粒子 ≤ 400 | 使用对象池复用，禁止每帧 new |
| 内存 | 稳态 ≤ 150 MB | 精灵缓存 ≤ 20 MB |
| 启动时间 | ≤ 1.5 秒（含地形预渲染与 `DATA` 解析） | 首屏先出加载遮罩与进度 |
| 存档体积 | ≤ 512 KB | 见第 16 章 |

**对象池规定（P0）**：弹道、粒子、飘字、残骸记录、临时数组必须使用池化（`acquire()` / `release()`），池容量达到上限时复用最旧对象而不是扩容。

### 2.9　编码规范

| 规则 | 规定 |
| --- | --- |
| 命名 | 变量/函数 `camelCase`；类 `PascalCase`；常量 `UPPER_SNAKE`；数据键 `lower_snake`，且**建筑/单位/武器的键名必须与第 8 章逐字相同**（如 `py_core`、`dm_extract`、`er_furnace`、`ch_lair`、`w_er_core`） |
| 注释 | 每个函数上方一行注释说明用途；所有与本文档数值对应的常量必须标注来源章节，例如 `// 见 8.4 单位数据表`、`// CORPSE_TTL_SEC 见 8.9 经济与效率` |
| 禁止 | 禁止 `eval`、禁止字符串拼接生成代码、禁止在逻辑中专用 `try/catch` 吞异常、禁止全局变量污染 |
| 断言 | 提供 `assert(cond, msg)`，默认仅 `?debug=1` 时启用；用于校验不变量（如「源质不为负」「实体 id 唯一」「建筑数量 = 32」「单位数量 = 35」「查表尺寸 = 200×6」） |
| 日志 | 提供 `LOG.levels = {error, warn, info, debug}`，`?debug=1` 时输出到控制台并写入屏幕角落的调试行 |
| 可读性 | 单函数 ≤ 120 行；单文件区之间不得循环依赖 |

### 2.13　常见失败模式与规避（P0）

| 失败模式 | 后果 | 规避方式 |
| --- | --- | --- |
| 用 `deltaTime` 驱动逻辑 | 高帧率下单位移动更快、平衡崩坏 | 严格使用本章「时间与循环规范」的固定步长循环 |
| 用 `Math.random()` | 存档/回放不可复现，AI 行为不可调试 | 使用 `RNG` 五流（三条逻辑流 + 两条表现流） |
| **实时套伤害公式而不查表** | 伤害与第 8 章两张表出现 1 点级偏差，全盘数值失效；且每 tick 数百次 `Math.pow`/阶乘导致 tick 超时 | 启动时用第 8 章的公式**一次性生成** 120 基础伤害 × 6 档护甲的两张表，运行时只做数组索引（`table[armorLevel][x]`），并用第 8 章节选表逐行断言 |
| **把四阵容简化为同一套数值** | 原初的再生、主宰的电力与护盾、侵蚀的残骸回收与腐蚀掠夺、混沌的中心强化全部退化成换皮，四阵容的差异化机制消失 | 四套机制必须**各自独立实现并各自自检**：原初脱战 8 秒后单位 2%/秒、建筑 1%/秒；主宰建筑全部带电力字段且断电惩罚生效；侵蚀悬停任意残骸即可回收；混沌按 `clamp(1.6 - 1.2 × d/dMax, 0.8, 1.6)` 缩放数值 |
| 每帧重建地形 | 帧率掉到 10 FPS | 地形分块预渲染，仅地形变化时重绘 |
| 单位直接吸到目标点 | 单位重叠成堆，观感极差 | 实现第 10 章的避障与分离力，履带/轮式单位不可进入浅毒滩 |
| 选中与命令用 DOM 元素实现 | 200 单位下 DOM 卡顿 | 全部自绘到 canvas |
| 寻路每 tick 全量重算 | tick 超时，游戏变慢 | 寻路预算 8 条/tick + 路径缓存 |
| 用 `setInterval` 驱动逻辑 | 后台标签页被节流、逻辑不稳 | 用 `requestAnimationFrame` + 累加器 |
| 单位图标用 emoji | 风格不统一、跨平台不一致 | 程序化矢量绘制 |
