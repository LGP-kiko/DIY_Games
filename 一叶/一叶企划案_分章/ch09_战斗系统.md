## 9　战斗系统

《一叶》的战斗模型是**极简但不平凡**的：只有两种伤害类型、两个护甲维度、一张查表，却因为重型护甲的**阶跃式**减伤（3 级剩 45%、4 级剩 17%、5 级剩 4%）而在编成层产生了大量取舍。实施方必须理解这一点，否则很容易把本作调成「所有单位互相换血」的平庸 RTS。

### 9.1　每 tick 模拟管线（P0，全局顺序）

战斗的确定性依赖**固定的系统执行顺序**。每个 tick 必须按下列顺序执行，实施方不得调整顺序（顺序会改变结算结果，从而破坏回放一致性）：

| 序号 | 阶段 | 内容 | 是否消耗逻辑随机数 |
| --- | --- | --- | --- |
| 1 | 命令结算 | 消费本 tick 的玩家命令队列（**奴役单位不接收任何玩家命令**） | 否 |
| 2 | 生产与建造 | 推进队列进度、生成单位（含主宰的奴隶自动生成）、推进蓝图施工 | 否 |
| 3 | 经济结算 | 采集单位状态机、卸货入账、维修扣费、**主动回收计时** | 否 |
| 4 | 残骸结算 | 残骸寿命递减与过期移除、**侵蚀的残骸回收判定**、**混沌的残骸吞噬判定** | 是（`RNG.ai`） |
| 5 | 电力重算 | **仅主宰**：重算产出 / 占用，更新 `powerRatio` 与 `lowPower` | 否 |
| 6 | 单位 AI 决策 | 状态机转移、索敌、姿态判定、**混沌中立行为层** | 是（`RNG.ai`） |
| 7 | 移动 | 路径推进、转向、避障、位置更新 | 否 |
| 8 | 状态结算 | **护盾回复（主宰）**、**再生（原初）**、隐形与钻地计时 | 否 |
| 9 | 开火 | 冷却递减、对准检查、生成弹道或瞬时命中 | 是（`RNG.combat`） |
| 10 | 弹道更新 | 投射物移动、命中检测、溅射结算 | 否 |
| 11 | 死亡结算 | 体力与护盾归零的实体移除、**生成残骸**、**触发解放**、经验分配 | 否 |
| 12 | 视野与迷雾 | 每 5 tick 更新一次视野位图与迷雾状态 | 否 |
| 13 | AI 玩家决策 | 建造 / 生产 / 进攻决策（见第 12 章） | 是（`RNG.ai`） |
| 14 | 触发器 | 战役触发器检查 | 否 |
| 15 | 统计与胜负 | 更新统计、检查胜负条件 | 否 |
| 16 | 表现事件 | 把本 tick 产生的事件推入表现队列（音效 / 特效 / UI） | 否（表现层自行消耗 `RNG.fx`） |

| 管线规则 | 规定 |
| --- | --- |
| 迭代顺序 | 阶段 6–11 中所有实体按 `entity.id` 升序迭代（实体数组按 id 单调递增维护） |
| 新增 / 删除 | 实体的删除只在阶段 11 统一执行；其他阶段只能标记 `dead = true` |
| 事件缓冲 | 音效 / 特效事件必须先入队，由表现层消费；**不得在逻辑阶段直接播放声音或创建粒子** |
| **残骸的生成时机** | 残骸必须在阶段 11（死亡结算）与实体移除**同一 tick** 生成，保证「死亡即残骸」不会出现 1 tick 的空窗（否则侵蚀的回收判定可能漏掉） |
| **解放的结算时机** | 控制节点（`dm_reaper` / `dm_warlord` / `er_core_unit`）的死亡在阶段 11 处理时，**先结算解放再移除残骸**：遍历半径内的敌方奴役单位并改换归属 |
| 时间预算 | 阶段 6–10 合计必须 ≤ 8 ms（200 单位规模）；超预算时降级为「每 2 tick 做一次 AI 决策」 |

### 9.2　索敌与目标选择（P0）

| 规则 | 规定 |
| --- | --- |
| 索敌频率 | 每个单位每 tick 检查一次（目标有效则跳过） |
| 索敌半径 | `acquireRange = 武器射程 × 1.15 + 2 格` |
| 合法性筛选 | 敌对阵营；`dead === false`；目标可见（在己方视野内）；武器 `air` 与目标移动类型匹配；目标距离 ≥ 武器 `minRange`；**侵蚀不把混沌视为敌对**（除非侵蚀先攻击） |
| 目标评分 | `score = dist − typeBonus − threatBonus`，取最小者 |
| 类型权重 | 若「本武器的伤害类型 × 目标的对应护甲等级」造成的伤害 ≥ 基准伤害的 70%，则 `typeBonus = 3 格`；若 ≤ 30% 则 `typeBonus = -4 格`（等价于几乎不选）。**这是《一叶》特有的评分依据**——单位会倾向于攻击自己「打得动」的目标 |
| 威胁权重 | 目标若在本 tick 内攻击过己方单位 → `+4 格`；目标为工程单位 / 采集单位 / 奴隶 → `+1 格`（优先清理） |
| 混沌的索敌 | 混沌单位只在**巢穴半径 18 格内**索敌，且**不主动攻击侵蚀单位**；一旦被侵蚀攻击，则该混沌单位永久转为敌对侵蚀 |
| 目标锁定 | 一旦锁定，只要目标仍合法且距离 ≤ `acquireRange × 1.3` 就不切换 |
| 目标丢失 | 目标死亡或离开范围 → 冷却保留，立刻重新索敌 |
| 建筑索敌 | 防御建筑使用相同逻辑但不移动；`acquireRange` 固定为射程 + 1 格 |
| 优先级排序 | 多种目标同时合法时，按「正在攻击己方 → 打得动 → 距离近」排序；本作**没有**「优先打空中」的硬编码（对空武器本来就只能打空中） |

### 9.3　开火流程与冷却（P0）

```
每个单位每 tick：
  1. 若 cooldown > 0 → cooldown--（主宰在低电力时防御建筑每 2 tick 才 -1）
  2. 若无目标 → 索敌；无目标则炮塔缓慢回正（每 3 tick 转 1 档）
  3. 若 cooldown === 0 且目标在射程内：
       a. 计算期望朝向 = 目标的 8 向档位
       b. 若炮塔（或车体）朝向 ≠ 期望朝向 → 转向（每 tick 最多 1 档），本 tick 不开火
       c. 若朝向一致 → 开火：cooldown = rof；进入连发序列（burst 发，间隔 gap tick）
  4. 连发序列进行中：每到间隔 tick 打出一发（不重新判定射程与朝向，目标死亡时保留指向原坐标）
```

| 开火规则 | 规定 |
| --- | --- |
| 转向速率 | 每 tick 最多转 1 档（45°），即 180° 转向需 4 tick = 0.2 秒 |
| 开火角度容差 | 与目标方向夹角 ≤ 22.5° |
| 连发语义 | `w_dm_peace`（3 发）、`w_dm_striker`（3 发）、`w_dm_sentry`（3 发）、`w_py_runner` / `w_py_spore` / `w_dm_aa` / `w_dm_reaper` / `w_er_rot` / `w_er_spitter` / `w_er_cloud` / `w_py_spike` / `w_py_sporetower` / `w_dm_aegis`（2 发）；第一发在朝向对齐当 tick 打出 |
| 移动惩罚 | 移动中开火 → 伤害 ×0.6（`py_wing` / `dm_bomber` / `er_bloat` / `ch_moth` 等空军不受惩罚） |
| 冷却语义 | `rof` 是「开火动作」之间的最小 tick 数；连发内部的间隔不额外增加 `rof` |
| 低电力 | **仅主宰**：防御建筑（`dm_sentry` / `dm_aegis`）在 `lowPower` 时冷却递减速度减半（等效 rof ×2） |
| 强制攻击 | `Ctrl + 右键` 指定目标时忽略敌我与免疫限制（可以对己方单位、孢子林、地面开火），仍受射程与朝向限制 |
| 战争单位 | `py_wrath` / `dm_warlord` / `er_core_unit` 永远处于「好斗」行为，不响应姿态切换，但可以接受移动与攻击命令 |
| 开火音效 | 每种伤害类型 + 单位族对应一个音效键（见第 14 章），同 tick 内同一音效键最多播放 3 个 |

### 9.5　伤害结算公式（P0）

**这是全文最重要的一段代码。** 设定给出了两条公式，并明确要求「优化：使用查表」。实施方必须：① 在初始化时用公式生成 `LIGHT_TABLE` 与 `HEAVY_TABLE`（**基础伤害 1–200 × 护甲等级 0–5**，覆盖全部 33 种武器，最大 `x = 190` 即督军的轨道炮）；② 运行时**只查表**，不做任何浮点运算。

```js
/* ① 初始化：用设定给出的公式预计算两张表（只在启动时执行一次） */
const FACT = [1, 1, 2, 6, 24, 120];          // 0!..5!
function buildTables() {
  const LIGHT = {}, HEAVY = {};
  for (let n = 0; n <= 5; n++) {
    LIGHT[n] = {}; HEAVY[n] = {};
    for (let x = 1; x <= 200; x++) {                      // 1–200 覆盖全部武器（最大 190）
      // 轻型：max( min(6-n, x), x*(1-0.1n) - n )
      const a = Math.min(6 - n, x);
      const b = x * (1 - 0.1 * n) - n;
      LIGHT[n][x] = Math.max(1, Math.floor(Math.max(a, b)));
      // 重型：0 级取 x；n>=1 取 x * 5 / (5 + n!)
      HEAVY[n][x] = n === 0 ? x : Math.max(1, Math.floor((x * 5) / (5 + FACT[n])));
    }
  }
  return { LIGHT, HEAVY };
}
const { LIGHT, HEAVY } = buildTables();

/* ② 运行时：只查表 */
function armorLevelOf(target, damageType) {
  if (damageType === 'light') return target.lightArmor;   // 0..5
  return target.heavyArmor;                               // 0..5
}
function baseDamage(weapon, target) {
  const table = weapon.type === 'light' ? LIGHT : HEAVY;
  const n = armorLevelOf(target, weapon.type);
  return table[n][weapon.damage];                         // 表已覆盖 1–200，直接命中
}
function computeDamage(attacker, weapon, target) {
  if (target.kind === 'war') return baseDamage(weapon, target); // 战争单位不吃任何加成/减成
  let dmg = baseDamage(weapon, target);
  dmg *= VET_DMG_MUL[attacker.veterancy];      // 1.00 / 1.15 / 1.32
  if (attacker.moving && !AIR_UNITS.has(attacker.type)) dmg *= 0.6;
  if (target.z - attacker.z >= 2) dmg *= 0.85; // 低打高惩罚
  if (attacker.faction === 'PRIMORDIAL' && target.faction === 'CHAOS') dmg *= 2.0; // 原初对中立 ×2
  return Math.max(1, Math.floor(dmg));
}
```

| 结算规则 | 规定 |
| --- | --- |
| 护盾优先 | 主宰带护盾的单位（`dm_reaper` / `dm_warlord`）先用护盾吸收伤害：`shield -= dmg`，溢出部分才扣体力 |
| 溅射 | 对命中点半径内**每个**单位分别调用 `computeDamage`，再乘以距离衰减 `1 − 0.75 × (dist / radius)`（边缘 25%） |
| 友军溅射 | 对己方**单位**按 50% 计算；对己方**建筑不结算** |
| 建筑受伤 | 建筑的 `kind` 为「建筑单位」，抗性统一 3/3；建筑不参与溅射的「边缘 25%」下限（按外接矩形最近点算距离） |
| 原初对混沌 | 原初的任何伤害对混沌单位 ×2.0（含溅射与吞噬附带的伤害） |
| 吞嗤 | 吞噬**不是伤害**，是删除目标：只对体力 ≤ 25% 的混沌单位生效，且要求施法者在 1.5 格内 |
| 记录伤害源 | 每次结算后记录 `target.lastAttackerId`、`target.lastHitTick` |
| 击杀归属 | 造成致命伤害的实体获得击杀与经验；建筑击杀计入该建筑所属玩家的 `kills` |
| 溢出伤害 | 不做溢出传递 |
| **数值边界** | 表已完整覆盖 `x ∈ [1, 200]`，本作最大基础伤害为 `w_dm_warlord` 的 190，**所有武器都能直接命中表项，不需要任何运行期公式补算**。若将来新增武器且 `x > 200`，必须重新生成两张表（不得在运行期套公式） |

> **实施方最容易犯的错**：把 `min(6-n, x)` 误读成「伤害上限」。它实际上是**保底值**（因为外层是 `max`）。它的作用是保证「小伤害打高护甲目标时不会被削到 0」，例如 x=3 打 5 级轻型护甲仍然造成 `min(1,3) = 1` 点伤害。

### 9.6　特殊战斗机制（P0）

| 机制 | 使用者 | 精确规则 |
| --- | --- | --- |
| **重型溅射** | 全部重型武器 | 命中点全额，半径边缘 25%，中间线性；**这是重型武器唯一的命中方式**（没有单体重型武器） |
| **护盾** | `dm_reaper`（护盾上限 = 380 × 0.5 = 190）、`dm_warlord`（1800 × 0.5 = 900） | 优先吸收伤害；脱战 5 秒（100 tick）后按护盾上限的 10%/秒 回复；`dm_shield` 在半径 7 格内把上限 +50%、回复速度 +100%；护盾归零时播放破碎特效并播报 |
| **再生** | 全部原初单位与建筑 | 脱战 8 秒（160 tick）后，单位每秒回复最大体力 2%、建筑 1%；`py_regen` 在半径 8 格内额外 +1.5%/秒 |
| **吞噬** | `py_carapace`、`py_wing`（需建成 `py_devour`） | 右键指定 1.5 格内体力 ≤ 25% 的混沌单位 → 900 ms 动画 → 目标被删除，施法者永久 +10% 最大体力、+1 轻型护甲等级（上限 5）；每个单位最多 3 次；**不产生残骸** |
| **隐形** | `er_stalker` | 静止满 40 tick（2 秒）后 `stealthed = true`；移动或开火立即取消并进入 40 tick 显形冷却；隐形单位在敌方视野外不可见、不可被索敌；**本作没有探测器**（P2 可加） |
| **钻地** | `py_burrow`、`er_digger` | 主动切换（`D` 键或技能按钮）：钻地状态下不可被选中、不可被攻击、不提供视野，也不能攻击；移动速度 ×0.8；钻出需要 20 tick |
| **解放** | 摧毁 `dm_reaper` / `dm_warlord` / `er_core_unit` 的一方 | 控制节点被摧毁的同一 tick：以该点为中心 10 格（若摧毁者是已建成 `er_assimil` 的侵蚀则为 20 格）内的**敌方奴役单位**全部改为摧毁者所有；被解放的奴隶保留体力与携带源质，转为可被玩家直接控制的采集单位；播放 `liberation` 特效与播报 |
| **腐蚀掠夺** | 侵蚀 | 不是战斗机制而是科技解锁条件：摧毁指定目标后立即解锁对应科技（见第 8 章科技树表最后一列），并播报「科技已掠夺」 |
| **混沌中心强化** | 全部混沌单位 | 开局按 `scale = clamp(1.6 − 1.2 × (d / dMax), 0.8, 1.6)` 计算每个混沌单位的倍率（`d` = 到地图中心的距离，`dMax` = 中心到角落的距离），并把该倍率**同时乘到体力、伤害与护甲等级**（护甲等级按 `round(基础等级 × scale)` 后夹取到 0–5） |
| **混沌残骸吞噬** | 全部混沌单位 | 体力不满且 6 格内有残骸时，优先前往吞噬；按该残骸记录的**最大体力 × 100%** 回复（不超过自身上限）；残骸立即消失 |
| **混沌巢穴** | `ch_lair` | 被摧毁时给摧毁者一次性源质奖励 `1600 × scale`（向下取整到 10；倍率 0.8–1.6 → 1280–2560 源质），该区域的混沌不再重生 |
| **战争单位免疫** | `py_wrath` / `dm_warlord` / `er_core_unit` | 老兵加成、护盾、再生、吞噬、腐蚀、解放、速度增减、姿态对其**一律不生效**；但可以被治疗类效果以外的正常伤害击杀 |

| **战争单位** | 姿态按钮对其**禁用**（UI 显示为灰色并提示「免疫」），行为恒定为 `Aggressive` |
| **奴役单位** | 没有姿态概念，其行为由预设 AI 决定；玩家无法切换 |
| 攻击移动 | `A + 左键` 下达的 `attack_move` 临时视为 `Aggressive`，抵达终点后恢复原姿态 |
| 巡逻 | `P` 命令在两个点之间往返，途中遇敌按当前姿态响应 |
| 返回原位 | `Aggressive` 追击超出 8 格时，返回命令下达时的原始坐标 |

**战斗设计红线（P0）**

1. **步兵必须在全程有用**：本作的反装甲步兵不存在；步兵的价值是**拆建筑（轻型对 3/3 建筑依然有 45%–65% 效率）与打步兵**，而**完全打不动重甲载具**（`py_rock` 对 `dm_mbt` 需要 39 发 / 38 秒）。这条红线不得被「加强步兵反装甲」破坏。
2. **重型护甲的阶跃式减伤必须完整体现**：4 级重甲只受 17%、5 级只受 4%。因此高级单位的 `heavyArmor` 是它的核心资产，实施方**不得**为了「平衡」把公式线性化。
3. **AOE 是清群手段不是拆家手段**：全部重型武器对 3/3 建筑只有 45% 效率，拆家要靠轻型单位或数量。
4. **战争单位是「数值墙」不是「机制怪」**：它们免疫一切特殊效果，因此唯一的应对方式是**用足够的数量与正确的伤害类型磨死它**（`py_wrath` 1800 体力 / 4/3 抗性，用轻型单位需 1800 ÷ 26 ≈ 70 发）。
5. **不允许出现「无解单位」**：每个单位都必须至少被 2 种手段克制。例如 `dm_reaper`（护盾 + 高输出）被「大量轻型单位」（护盾不抗轻型）与「高护甲单位拖住」克制；`er_stalker`（隐形）被「溅射盲打」与「逼它移动」克制。
