## 13　UI与交互

本章定义《一叶》（One Leaf）全部界面几何、交互状态机、反馈规则与实现约定。交付形态为单文件 `OneLeaf.html`，纯原生 JavaScript 与 Canvas 2D 等距渲染，零第三方依赖、零外部图片素材。所有图标、头像、光标、臂章与状态标记一律使用离屏 canvas 程序化绘制（矢量路径 + 像素风格平涂）。

#### 13.1.3　缩放适配与坐标换算

`scale = min(canvasW / 1920, canvasH / 1080)`，并夹取到区间 `[0.5, 3.0]`。`offsetX = floor((canvasW - 1920 * scale) / 2)`，`offsetY = floor((canvasH - 1080 * scale) / 2)`。letterbox 填充色 `#0A0C0F`，不绘制任何条纹或边框。

| 场景 | canvasW × canvasH | scale | offsetX | offsetY | 逻辑可见比例 |
| --- | --- | --- | --- | --- | --- |
| 标准 16:9 全屏 | 1920×1080 | 1.000 | 0 | 0 | 100% |
| 2K 全屏 | 2560×1440 | 1.333 | 0 | 0 | 100% |
| 超宽 21:9 | 3440×1440 | 1.333 | 320 | 0 | 100%（左右各 320 px letterbox） |
| 4:3 窗口 | 1280×960 | 0.666 | 0 | 60 | 100%（上下各 60 px letterbox） |
| 小窗极限 | 800×600 | 0.500 | 0 | 30 | 100% |

坐标换算（P0）：鼠标设备像素 `(mx, my)` → 逻辑坐标 `lx = (mx - offsetX) / scale`，`ly = (my - offsetY) / scale`。所有 UI 命中测试与战场拾取都在逻辑坐标系内进行，换算只在事件入口做一次。渲染时 `ctx.setTransform(scale, 0, 0, scale, offsetX, offsetY)` 后按逻辑坐标绘制，禁止逐元素手工乘 scale。

用户可调 UI 缩放 `uiScale ∈ {0.75, 1.0, 1.25}`，它缩放 UI 分区矩形本身，战场视口自动吸收差额（P1）。

| `uiScale` | 顶栏高 | 侧边栏宽 | 小地图 | 信息面板高 | 战场视口 w×h | 正文字号 |
| --- | --- | --- | --- | --- | --- | --- |
| 0.75 | 30 | 180 | 180×180 | 90 | 1740×960 | 12 逻辑 px |
| 1.00 | 40 | 240 | 240×240 | 120 | 1680×920 | 14 逻辑 px |
| 1.25 | 50 | 300 | 300×300 | 150 | 1620×880 | 16 逻辑 px |

字号阶梯固定为 `12 / 14 / 16 / 20 / 24 / 32` 逻辑像素，取整规则 `round(base * uiScale)`，最小不小于 12。命中区最小尺寸 `24×24` 逻辑像素（P0），次级按钮不得小于 `16×16`（P1）。

### 13.3　选择与框选交互

选择系统对齐《星际争霸》：左键点选、双击选同类、拖拽框选、Shift 增删、Ctrl+数字编队、双击数字键镜头居中、Tab 循环同类。选择状态是全局唯一的 `selection` 数组，UI 只读该数组渲染，修改一律通过命令队列。**奴役单位永不进入选择集合**（第 8 章：奴役单位仅执行预设 AI，玩家不可直接控制）。

#### 13.3.1　可选中单位判定规则

| 条件 | 判定 | 说明 | 优先级 |
| --- | --- | --- | --- |
| `owner === player` 且 `kind !== '奴役单位'` | 可选中 | 己方建筑、一般单位、战争单位 | P0 |
| `owner === player` 且 `kind === '奴役单位'` | **不可选中** | `dm_slave` 奴隶由矿产中心自动生成，玩家只能悬停查看，不能下令 | P0 |
| `owner !== player` 且可见 | 可选中（仅信息查看） | 敌方/中立单位可被点选查看，但不接受指令 | P0 |
| 混沌单位（任何情况） | 可选中（仅信息查看） | 显示其数值倍率；不显示姿态与命令按钮 | P0 |
| 处于战争迷雾中 | 不可选中 | 迷雾内即使有点击也不产生选择 | P0 |
| `isProjectile` / 弹道 / 特效 | 不可选中 | 完全跳过拾取 | P0 |
| 残骸（`corpse`） | 不可选中，但**可悬停** | 残骸不是实体，只有悬停提示与（侵蚀的）回收交互，见「残骸与回收」段 | P0 |
| `isUnderConstruction`（蓝图） | 不可选中 | 但可被修理与点击查看进度 | P1 |
| `hp <= 0` / 已阵亡 | 不可选中 | 死亡动画期间不可选 | P0 |
| `isCloaked` 且未探测 | 不可选中 | `er_stalker` 静止 2 秒后隐形；己方隐形单位对己方始终可选 | P0 |
| `kind === '战争单位'` | 可选中，但姿态按钮与老兵臂章不绘制 | 战争单位免疫一切正负面特殊效果 | P0 |
| 混编选择 | 允许 | 不同类型可同时选中，指令按类型过滤下发 | P0 |

#### 13.3.2　框选优先级与拾取顺序

拖拽框选只选己方单位且**跳过奴役单位**（P0）。框出多个类别时按下列优先级排序，且只保留**最高优先级类别**，其余忽略——这是《星际争霸》手感的关键，禁止全选混合。

| 优先级 | 类别 | 判定 | 框选行为 |
| --- | --- | --- | --- |
| 1 | 具武装的一般单位与战争单位 | 职能 ∈ {步兵-轻、步兵-重、载具-轻、载具-重、空军、防空、高级} 或 `kind === '战争单位'` | 若框内存在此类，只选此类 |
| 2 | 采集单位 | 职能 `采集`（`py_gatherer` / `er_drinker`；`dm_slave` 被排除在外） | 无第 1 类时选采集单位 |
| 3 | 工程与侦查单位 | 职能 ∈ {工程、侦查} | 并入第 1 类一同选中（与原作一致，支援单位随主力行动） |
| 4 | 建筑单位 | `kind === '建筑单位'` | 仅当框内无前三类时选建筑 |

点选拾取（P0）：在光标半径 8 逻辑像素内收集候选，按「屏幕绘制顺序倒序」取最上层；等距深度相同时按 `y` 大的优先（更靠前）。建筑拾取使用其占地包围盒，选中后显示选区角标。**残骸不参与点选拾取**，只参与悬停拾取，且悬停优先级低于一切实体（P0）。

### 13.4　命令与光标状态机

光标状态由「当前选择 + 悬停目标 + 待定模式」三者共同决定，每 tick 求值一次，渲染 60 FPS 直接读缓存状态。状态切换必须伴随一次状态变更事件（用于播放提示音与气泡），且同一状态持续不重复触发。光标统一绘制在 UI 层最顶（z = 70），尺寸 32×32 逻辑像素，热点在 `(4, 4)`（P0）。

- **`A`**：有己方单位被选中时 = 攻击移动，光标悬停敌方目标时优先执行攻击（等价右键）；无选中单位时仅平移镜头。**`S`**：有己方单位被选中时 = 停止；无选中单位时仅平移镜头。**`D`**：有选中单位且其中含核心建筑时 = 打包核心（等价 `pack_conyard`），否则无绑定；无选中单位时 `D` 仅平移镜头。**`W`** 恒为平移镜头，不绑定任何游戏命令。

- **`R`**：游戏内 = 主动回收（进入 `salvage` 态，或直接回收光标下的残骸）；结算面板内 = 重开本局。两义以「当前是否处于结算面板」为唯一判据，上下文互斥。`R` **不与**第 4 章的 `repair`（右键 + 工程单位）冲突，也不占用 `Ctrl + R`。
- **`1`–`9`**：仅用于编队（`Ctrl + 1..9` 设定、`1..9` 调用、双击 `1..9` 居中），不用于其他命令；建造网格上的 `1`..`9` 角标只在建造网格获得键盘焦点时生效，与编队调用不会同时响应（见「建筑标签页条目」的角标说明）。
- **`M`** / **`R`**：结算面板内 `M` = 换图再战、`R` = 重开本局（与第 15 章一致）；游戏内 `M` = 静音开关、`R` = 主动回收（第 14 章是音频键名的权威来源）。

```text

effAvg  = 平均效率（采集、生产、卸货三类效率的算术平均，单位 %）
essence = 采集源质总量（不含残骸回收与主动回收）

score = 0.40 * min(1, kd / 6)
      + 0.35 * min(1, effAvg / 140)
```

### 13.12　UI 实现规范

#### 13.12.1　渲染分层

UI 必须绘制在一个独立的 UI 层，与战场渲染完全分离。采用**第二张 canvas**：`#game`（战场，等距渲染）与 `#ui`（界面，逻辑坐标 1920×1080 后备缓冲）两张 canvas 叠放，`#ui` 位于上层且 `pointer-events: auto`。DOM 覆盖层仅用于一个场景：存档命名输入（`input` 文本元素），其余一律 canvas 绘制。理由：零依赖前提下，第二张 canvas 便于整体变换与整体 clear，且避免战场重绘时重复绘制 40 个面板元素（P0）。

| 层 | id | CSS z-index | 后备缓冲尺寸 | 内容 | 优先级 |
| --- | --- | --- | --- | --- | --- |
| 战场层 | `#game` | 0 | `canvasW × canvasH` | 地形、单位、建筑、残骸、特效、世界血条 | P0 |
| UI 层 | `#ui` | 10 | `1920 × 1080`（按 scale 变换） | 分区、侧边栏、信息面板、小地图、通知、光标 | P0 |
| 模态层 | `#modal` | 20 | `1920 × 1080` | 主菜单、设置、暂停、结算 | P0 |
| DOM 覆盖 | `#overlay` | 30 | — | 仅文本输入 | P2 |

UI 层每帧只重绘「脏区」的最小集合：静态面板（顶栏除数值区、侧边栏标签条、信息面板边框）绘制到一张离屏 `1920×1080` 静态缓存 canvas，仅当布局或 `uiScale` 变化时重绘；动态元素（数值、进度条、小地图、通知、光标）每帧绘制（P1）。光标必须绘制在最后一帧的最顶层，且使用 `globalCompositeOperation = 'source-over'`（P0）。

#### 13.12.2　图标程序化绘制统一约定

| 约定项 | 规定 | 优先级 |
| --- | --- | --- |
| 源画布 | 统一 `64×48` 离屏 canvas，DOM 外创建，不插入文档 | P0 |
| 绘制方式 | 纯矢量路径（`moveTo/lineTo/arc/rect`），禁止 `drawImage` 外部资源 | P0 |
| 描边 | 统一 2 像素 `#14181C`，`lineJoin = 'miter'`，`lineCap = 'butt'` | P0 |
| 填充 | 平涂色块，禁止渐变与阴影 | P0 |
| 主色 | 由 `tint(baseColor, faction)` 计算，见下 | P0 |
| 高光 | 单条 2 像素 `#FFFFFF`（α=0.20）斜线，位置固定为从 `(8,8)` 到 `(8,40)` | P1 |
| 阵营着色 | 四个阵容各一套色，取值见本章开头的阵营色板，禁止另建色值 | P0 |
| 电力角标 | 主宰建筑图标的一体化组件，`+N` / `−N` / `±0` 三态，颜色见「电力小角标规范」 | P0 |
| 残骸图标 | 独立 `48×36` 源画布，按原单位剪影的 60% 缩放 + 断裂缺口 + 灰白平涂，缓存键含原单位 `type` | P0 |

| 禁止事项 | 不得引用任何图片文件、data URI 图片、SVG 外部文件 | P0 |

阵营着色函数（P0，实现方必须原样采用该签名与语义）：

```javascript
// base: 0xRRGGBB 基础色, faction: 'PRIMORDIAL' | 'DOMINATOR' | 'EROSION' | 'CHAOS'
function tint(base, faction) {
  var f = faction === 'PRIMORDIAL' ? { r: 74,  g: 143, b: 60  }   // #4a8f3c
        : faction === 'DOMINATOR'  ? { r: 63,  g: 111, b: 208 }   // #3f6fd0
        : faction === 'EROSION'    ? { r: 138, g: 75,  b: 208 }   // #8a4bd0
        :                            { r: 192, g: 138, b: 46  };  // #c08a2e 混沌
  var r = (base >> 16) & 255, g = (base >> 8) & 255, b = base & 255;
  var w = 0.45; // 阵营色权重，固定值，不得改动
  return ((r * (1 - w) + f.r * w) << 16)
       | (((g * (1 - w) + f.g * w) & 255) << 8)
       | ((b * (1 - w) + f.b * w) & 255);
}
```

#### 13.12.3　UI 事件与游戏逻辑解耦

UI 只发命令，不直接改状态（P0）。UI 层禁止读写 `units`、`buildings`、`essence` 等模拟状态对象；所有输入统一写入 `pendingCommands` 数组，逻辑层在每个 tick 开头一次性消费。

| 规则 | 规定 | 优先级 |
| --- | --- | --- |
| 命令队列 | `pendingCommands` 为 FIFO 数组，逻辑层每 tick 开头 `splice(0)` 全部消费 | P0 |
| 只读快照 | UI 每帧读取 `uiSnapshot`（逻辑层每 tick 生成的只读视图），残骸只以 `{kind:'corpse', typeKey, maxHp, cost, ttlTick, x, y, reclaimRatio}` 的只读结构出现 | P0 |
| 禁止直接写 | UI 不得直接修改任何 `hp`、`essence`、`power`、`shield` 字段 | P0 |
| 合法性复核 | 逻辑层复核每条命令，非法则丢弃并回推一条 `uiEvent` 说明原因 | P0 |
| 幂等 | 同一条命令重复消费只生效一次（带 `seq` 序号去重） | P0 |
| 反馈闭环 | 逻辑层通过 `uiEvent` 通知 UI，UI 不预测结果 | P0 |
| 帧率无关 | UI 不使用 `deltaTime` 影响模拟，动画只用 tick 计数 | P0 |

命令对象结构（P0）：

```javascript
// 由 UI 层构造并推入 pendingCommands
{
  seq: 1043,              // 自增序号，用于去重
  tick: 5820,             // 发出时刻的逻辑 tick
  kind: 'build' | 'move' | 'attack' | 'attackMove' | 'harvest'
      | 'repair' | 'sell' | 'salvage' | 'rally' | 'stance' | 'train'
      | 'deploy' | 'enter' | 'stop' | 'patrol' | 'formGroup',
  actorIds: [12, 13],     // 施令单位 id 列表
  target: { x: 34, y: 57, id: 88, type: 'essence' }, // 目标点或目标实体
  payload: { building: 'dm_heavy', stance: 'HoldGround' }
}
```

`salvage` 命令的对象形状固定为（P0）：

```javascript
{
  seq: 1044,
  tick: 5820,
  kind: 'salvage',
  actorIds: [],                          // 主动回收不需要施令单位
  target: { id: 88, type: 'building' }   // 或 { id: 214, type: 'corpse' }
  ,payload: { confirmToken: 0x51F3 }     // 返还额 ≥ 1000 源质时的二次确认令牌
```

#### 13.12.5　性能与实现红线

| 红线 | 规定 | 优先级 |
| --- | --- | --- |
| UI 绘制预算 | 单帧 UI 绘制不超过 3 ms（1080p，参考机型集成显卡） | P1 |
| 静态缓存 | 顶栏、侧边栏框架、信息面板框架缓存为一张离屏 canvas | P1 |
| 图标缓存 | 所有图标首次使用即缓存，单帧内同一图标最多绘制一次 | P0 |
| 角标预算 | 电力角标与快捷键角标共用图标缓存条目，不单独建 canvas | P1 |
| 小地图 | 底图与迷雾均为离屏 canvas，迷雾 4 Hz 更新，禁止每帧逐格绘制；混沌巢穴标记绘制在迷雾之上，用同一个 `drawImage` 后的单点绘制调用完成 | P0 |
| 文本 | 每帧 `fillText` 调用不超过 400 次；数值变化时才重绘文本 | P1 |
| 事件 | UI 使用单一 `pointerdown/pointermove/wheel` 监听器 + 命中测试分发 | P0 |
| 悬停拾取 | 残骸悬停只在光标半径 8 逻辑像素内做一次线性扫描，禁止每帧全表遍历残骸数组 | P0 |
| 内存 | 图标缓存条目上限 512，超出按 LRU 淘汰 | P2 |
| 禁止 | 不得使用 `eval`、`new Function`、外部 CDN、图片元素引用 | P0 |
