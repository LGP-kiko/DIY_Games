## 14　音频系统

本章定义《一叶》（One Leaf）全部声音的产生、调度、混音与降级规则。工程为单文件 `OneLeaf.html` 交付，运行时只允许使用原生 JavaScript 与 Canvas 2D，禁止引入任何第三方音频库，禁止加载 .mp3 / .wav / .ogg 等音频素材文件。所有音效、音乐、UI 提示音一律在运行时由 WebAudio API 的振荡器、噪声缓冲、双二阶滤波器与增益包络实时合成；唯一例外是 EVA 语音播报，它由 SpeechSynthesis 合成，接口约定见本章「语音播报与音频优先级」一节。音频系统与 20 Hz 的逻辑帧完全解耦：逻辑层只负责向事件总线发布事件，音频层只监听事件总线并消费事件，任何音频侧的异常都不得反向影响模拟结果、不得抛出未捕获异常、不得阻塞逻辑帧。

本章的每一个频率、时长、增益、阈值、复音上限、重触发间隔都是强制实现参数，不是参考值。实现者不得以「手感更好」为由自行改写数值；如需调整，必须在本章表格中同步修订并重新标注优先级。

**三个阵营的声音性格必须在合成层就分开，不能靠同一套音色加均衡器糊弄**（P0）：

| 阵营 | 音色倾向 | 武器音走法 | 爆炸与建筑尾音 | 音乐层性格 |
| --- | --- | --- | --- | --- |
| 原初 `PRIMORDIAL` | **有机质 / 低频脉动** | `noiseBurst(brown)` 的湿润包裹 + `sineSweep(sub)` 的亚低层；基频整体 −180 音分，并叠加 ±7 音分、周期 1.7 s 的缓慢漂移（模拟生物膜振动） | 用 `fmHit(ratio 1.6)` 的骨壳闷响替代金属余响，尾部必挂一层 `sineSweep(90→40)` | 湿润、幽暗、有呼吸感；膜振琶音 + 手鼓 |
| 主宰 `DOMINATOR` | **金属 / 电子 / 机械节拍** | `squareBlip` 上扫 + `fmHit(ratio 3.1~4.2)` 的金属-电子音；基频整体 +40 音分，并常驻一层 90 Hz 的机械节拍基座 | 统一带 `metalClank(base 128~192)` 的厚重金属尾；护盾类事件额外叠 `sineSweep(1800→900)` 的六边形共振 | 冷硬、精准、节拍化；16 分电子琶音 + 机械底鼓 |
| 侵蚀 `EROSION` | **腐蚀 / 湿润 / 失真** | `noiseBurst(brown, lowpass 900→180)` 的高阻尼湿润音 + `chainZap` 的低频变体；基频整体 −90 音分，并施加 `drive` 失真 | 无金属余响，改用 `noiseBurst(lowpass 300, 900ms)` 的黏稠拖尾，并叠一层反向包络的 `sawSweep(200→40)` | 病态、失真、黏稠；失真和弦 + 腐蚀琶音不解决 |
| 混沌 `CHAOS`（中立） | **野生 / 无调性** | 全部走 `noiseBurst` + `fmHit(ratio 2.4)`，不带任何阵营标志层；音量随「区域倍率」线性缩放 | 兽类低吼 + 骨裂 | 不参与音乐层 |

`drive ∈ [0, 1]` 是侵蚀专属的失真开关，**不引入第 9 个原语**：实现方式是在信号链第 3 级的 biquad 组里串一个 `peaking` 滤波器（`frequency = 1200`、`Q = 1.1`、`gain = 6 * drive`），再在 `envGain` 之前加一个 `highpass 120 Hz` 阻断直流，用两级滤波的过冲近似波形削顶。同一事件键在三阵营间共用配方骨架，只在「低音层是否存在」「基频偏移」「滤波器截止」「`drive`」四处按阵营切换，由 `AudioEngine.faction` 一次性决定，不在每次 `play()` 里判断。

### 14.1　设计目标与硬约束

音频设计围绕一个核心场景展开：**一屏 30 个战斗单位同时交火**。该场景下必须同时满足「有层次」「不刺耳」「不爆音」三条主观验收标准，以及「总复音数受限」「CPU 预算受控」两条客观验收标准。为保证可验证性，把主观标准换算成可测量的工程指标，见下表。

| 指标 | 目标值 | 测量方法 | 优先级 |
| --- | --- | --- | --- |
| 同时活跃 AudioNode 总数 | 峰值 ≤ 64，稳态 ≤ 48 | `AudioEngine.stats.activeNodes` | P0 |
| 每帧新建 AudioNode 数 | ≤ 12 | 帧内节点创建计数器 | P0 |
| 音频更新 CPU 耗时 | 平均值 < 1.8 ms，P95 < 3.0 ms | `performance.now()` 包裹 `AudioEngine.update()` | P0 |
| 主输出峰值 | ≤ -1.0 dBFS，永不出现削波 | 限幅器输出分析仪峰值保持 | P0 |
| 母线听感一致性 | 同屏 30 单位交火时 sfx 总线短期平均 ≤ -14 dBFS | 500 ms 窗口 RMS | P1 |
| 单音效最大响度差 | 同类音效随机音高偏差 ≤ ±10% | 参数断言 | P1 |

### 14.2　音频架构

#### 14.2.1　AudioContext 单例与生命周期

全局唯一入口为 `AudioEngine`，模块级立即执行函数（IIFE）封装，对外只暴露 `init()`、`update(dtMs)`、`play(key, opts)`、`setFaction(f)`、`setVolume(bus, v)`、`setMuted(bool)`、`getSettings()`、`stats`。`AudioContext` 只允许创建一次，创建时机必须晚于首次用户手势，见下表的状态机。

| 状态 | 触发条件 | 动作 | 副作用 | 优先级 |
| --- | --- | --- | --- | --- |
| `uninitialized` | 页面加载 | 绑定一次性手势监听（`pointerdown`/`keydown`/`touchstart`，`{capture:true, passive:true}`），显示「点击以启用音频」角标 | 不创建 AudioContext，逻辑照常运行 | P0 |
| `creating` | 首次手势 | 用 `window.AudioContext`（不存在时回退到 `window.webkitAudioContext`）创建上下文，参数 `{latencyHint:'interactive'}`，建总线、建预置噪声缓冲、建限幅器，并按玩家阵营预生成该阵营的失真与漂移参数表 | 记录 `ctx.sampleRate`（预期 48000，允许 44100） | P0 |
| `resuming` | 创建后 `ctx.state === 'suspended'` | 调用 `ctx.resume()`，最多重试 3 次，间隔 250 ms | 播放 60 ms 的 `sfx.ui.click` 验证通路 | P0 |
| `running` | `ctx.state === 'running'` | 正常合成，启动音乐前瞻调度 | 移除角标 | P0 |
| `suspended` | `document.hidden` 持续 5000 ms | `ctx.suspend()`，停止音乐调度时钟累积，并强制淡出全部循环音（引擎 / 再生蠕动 / 反应堆嗡鸣 / 腐蚀云） | 恢复时 `resume()` 并把 `nextNoteTime` 重置为 `currentTime + 0.1` | P1 |
| `failed` | 创建抛错或 3 次 resume 后仍非 running | 置 `enabled=false`，进入静默降级 | 记录 `AudioEngine.failReason` 供调试模式显示 | P0 |

创建参数固定为：`sampleRate` 不显式指定（跟随设备）、`latencyHint = 'interactive'`、不使用 `OfflineAudioContext` 生成素材（所有噪声缓冲在主上下文内用 `AudioBuffer` 手工填充 Float32 数据，不经过渲染）。

#### 14.2.2　节点图与信号链

每个音效实例的信号链固定为七级，顺序不可调换。顺序调换会破坏包络与滤波的相互作用（例如把 gain 放到 filter 之前会导致扫频时响度随截止频率漂移）。侵蚀的 `drive` 失真在**第 3 级内部**完成（`peaking` + 高通串联），不新增级。

```text
source(s)  ->  envGain  ->  biquadFilter(0~2)  ->  panner  ->  duckGain  ->  bus.gain  ->  master.gain  ->  limiter  ->  destination
```

| 级 | 节点类型 | 职责 | 关键参数 | 必须遵守 | 优先级 |
| --- | --- | --- | --- | --- | --- |
| 1 | `OscillatorNode` / `AudioBufferSourceNode` | 波形或噪声源 | 振荡器 `detune` 承接随机音高与阵营基频偏移；噪声源用共享 `AudioBuffer` | 每实例新建，禁止复用 source | P0 |
| 2 | `GainNode` | ADSR 包络 | 起音用 `linearRampToValueAtTime`，衰减/释音用 `exponentialRampToValueAtTime` | 终值不得为 0，用 `1e-4` | P0 |
| 3 | `BiquadFilterNode` ×0~2 | 音色塑形、扫频与阵营失真 | `type` ∈ lowpass/bandpass/highpass/peaking；`Q` 见原语表；侵蚀追加 `peaking 1200Hz / Q1.1 / gain = 6*drive` | 扫频用 `exponentialRampToValueAtTime` | P0 |
| 4 | `StereoPannerNode` | 水平定位 | `pan ∈ [-0.8, 0.8]` | 中央死区 ±0.08 时强制置 0 | P0 |
| 5 | `GainNode`（duckGain，共享） | EVA 闪避 | 三条 sfx/音乐子链各一个共享 duck 节点 | 由语音状态机驱动 | P1 |
| 6 | `GainNode`（bus.gain） | 分类音量 | sfx / music / voice 各一 | 滑条直接写 `setTargetAtTime` | P0 |
| 7 | `GainNode` + `DynamicsCompressorNode` | 主音量与限幅 | master 0.8；限幅 threshold -6 dB、knee 6、ratio 6、attack 0.004 s、release 0.18 s | 限幅器不可旁路 | P0 |

总线级的共享节点（bus、master、duck、limiter、分析仪）在 `init()` 中创建一次，生命周期与 AudioContext 相同，永不 `disconnect`。音效级节点（source、envGain、filter、panner）每实例创建、播完销毁。

**阵营参数注入点（P0）**：`play()` 在装配阶段一次性施加三处阵营差异，此后不再判断阵营：

```text
detune  += FACTION[f].detuneBias     // 原初 -180 音分 / 主宰 +40 / 侵蚀 -90 / 混沌 0
filter.frequency *= FACTION[f].cutoffScale  // 原初 0.82 / 主宰 1.12 / 侵蚀 0.75 / 混沌 0.95
sub 层  =  FACTION[f].sub            // 原初 true（必挂 sineSweep(sub)）/ 主宰 'mech'（90 Hz 机械基座）/ 侵蚀 false / 混沌 false
```

#### 14.2.3　AudioBus 总线结构

四条总线各自持有一个 `GainNode`，均直连 `master.gain`。总线不做串联，避免音乐被音效闪避链二次衰减。

| 总线名 | 节点变量 | 默认值 | 取值范围 | 步进 | 受静音影响 | 受 EVA 闪避 | 承载内容 | 优先级 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `master` | `bus.master` | 0.80 | 0.00 – 1.00 | 0.01 | 是（M 键写 0） | 否 | 全部声音 | P0 |
| `sfx` | `bus.sfx` | 0.90 | 0.00 – 1.00 | 0.01 | 是 | 是（-4.5 dB） | 武器、命中、爆炸、残骸、单位应答、UI | P0 |
| `music` | `bus.music` | 0.45 | 0.00 – 1.00 | 0.01 | 是 | 是（-2.5 dB） | 三段程序化音乐 | P0 |
| `voice` | `bus.voice` | 1.00 | 0.00 – 1.00 | 0.01 | 是 | 否（自身优先） | EVA 替代提示音、无线电杂音 | P0 |

`voice` 总线有一个必须说明的实现事实：SpeechSynthesis 的音频输出由浏览器直接送往系统混音器，**不经过 WebAudio 图**，因此 `bus.voice` 这个 GainNode 无法控制真正的 EVA 语音音量。真正的 EVA 音量写入 `SpeechSynthesisUtterance.volume = settings.voice`，`bus.voice` 只控制 `sfx.ui.evaFallback` 与无线电杂音等 WebAudio 合成内容。`settings.master` 也无法作用于 EVA 语音，这一点必须在设置界面以文字说明「主音量不影响语音播报」，并由 `settings.voice` 独立承担，见「混音默认值与设置界面」一节。

线性的 dB 换算统一使用 `lin = Math.pow(10, dB / 20)`，全局不得使用除 `20 * Math.log10` 之外的其他换算方式。基础音量在事件表里以 dB 给出，最终写入 `envGain` 的峰值是 `lin * gDist * gZoom * gScale * gChaos`，其中 `gChaos` 只对混沌单位生效（等于第 8 章的混沌区域倍率 `clamp(1.6 − 1.2 × d / dMax, 0.8, 1.6)` 归一到 `[0.8, 1.6]`），其余阵营恒为 1.0。

#### 14.2.4　音量、静音与存档

音量写入一律走 `setVolume(busName, value)`，内部执行：

```text
now = ctx.currentTime
target = muted ? 0 : clamp(value, 0, 1)
bus[b].gain.cancelScheduledValues(now)
bus[b].gain.setTargetAtTime(target, now, 0.02)
```

`setTargetAtTime` 的时间常数固定 0.02 s，等价于约 60 ms 内完成 95% 变化，既不会产生拉链噪声，也不会让玩家觉得反应迟钝。禁止使用 `linearRampToValueAtTime` 处理滑条拖动，因为拖动会以 60 Hz 频率取消并重排斜坡，导致增益跳变爆音。

M 键静音规则（P0）：M 键为一个切换动作，切换后把 `muted` 写入 settings，并在 80 ms 内把 `bus.master.gain` 降到 0。**静音不得调用 `ctx.suspend()`**，原因有二：一是 `suspend()` 会让音乐调度器的 `nextNoteTime` 与 `currentTime` 失步，恢复时造成整拍错位；二是部分浏览器在 `suspend`/`resume` 之间存在 100 ms 级静默延迟，玩家按 M 键取消静音时会有明显「迟到」。静音只写增益，音频图保持运行。

存档规则（P0）：settings 变更后延迟 400 ms 防抖写 `localStorage`；写入失败（隐私模式 `QuotaExceededError`）时静默忽略并把 `AudioEngine.storageOk` 置 false，调试模式下显示。页面加载时同步读取并立即应用，不做渐入。

#### 14.2.5　自动播放策略与降级

自动播放策略的处理遵循「不阻断游戏、不强弹窗、不丢事件」三原则。手势之前逻辑与渲染照常运行，音频事件进入环形缓冲（容量 256 条），`init()` 成功后**全部丢弃而非补播**——补播会造成一次性的声音雪崩，且与当前战场状态无关。

降级阶梯如下，逐级判断，命中即停。

| 级别 | 判定条件 | 行为 | 玩家可见反馈 | 逻辑影响 | 优先级 |
| --- | --- | --- | --- | --- | --- |
| L0 | `AudioContext` 存在且 `state==='running'` | 全功能 | 无 | 无 | P0 |
| L1 | `AudioContext` 存在但 `state==='suspended'` | 只入队不发声，等待手势 | 右上角「点击以启用音频」角标 | 无 | P0 |
| L2 | `AudioContext` 构造抛错 | `enabled=false`，全部音效静默 | 设置界面显示「音频不可用」灰色提示 | 无 | P0 |
| L3 | `StereoPannerNode` 缺失 | 声像层直通（跳过 panner） | 无 | 无 | P1 |
| L4 | `DynamicsCompressorNode` 缺失 | 用固定 `bus.master.gain = 0.62` 替代限幅 | 无 | 无 | P1 |
| L5 | `SpeechSynthesis` 缺失或中文语音包不存在 | EVA 全部走 `sfx.ui.evaFallback` | 设置中「语音播报」置灰 | 无 | P1 |
| L6 | 音频更新连续 30 帧单帧耗时 > 8 ms | 自动降级到 `qualityTier='low'`（复音上限减半、关闭侵蚀 `drive` 与残骸循环音） | 无 | 无 | P2 |
| L7 | `BiquadFilterNode` 不支持 `peaking` | 侵蚀 `drive` 降级为 `bandpass 1200 Q 1.4` 固定增益 | 无 | 无 | P2 |

`enabled=false` 时所有 `play()` 走同一个早退分支：`if (!E.enabled) return;`，事件总线照常派发，逻辑帧不产生额外分支开销。这一条是 P0，因为音频故障导致游戏卡死或崩溃的代价远高于静音。

### 14.3　合成原语库

原语库为 **8 个**可复用函数，全部返回「一组已接线、已 `start()`、已排定 `stop()` 的节点」，注册到 `AudioEngine.voices` 统一回收。每个原语只负责波形与包络，不负责总线、声像、距离衰减与阵营偏移，这四项由 `play()` 统一施加，保证同一事件在不同位置、不同阵营下的听感一致。

| 函数名 | 波形 | 起始 → 终止频率 (Hz) | 包络 A / D / S / R (ms) | 滤波类型与截止 (Hz) | 建议增益 (dB) | 典型用途（《一叶》） | 优先级 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `noiseBurst` | 白噪 / 粉噪 / 棕噪 Buffer（共享，各 2 s，循环） | 无基频；带通中心 2000 → 2000 | 1 / dur / 0 / 8 | bandpass Q=0.9 默认；可选 lowpass 6000 → 120、highpass 1200 | -24 ~ -3 | 尖刺入肉、腐蚀喷溅、枪口脉冲、爆炸主体、残骸碎裂 | P0 |

各原语的强制实现细节如下，参数缺省即为表内数值。

- `noiseBurst(t0, {dur, filter, f0, f1, q, gain, curve, drive})`：P0
  - 噪声 Buffer 在 `init()` 时预生成三份：白噪 2 s、粉噪 2 s（一阶 IIR 近似）、棕噪 2 s（积分-泄漏），全部用 `Float32Array` 手工填充，`Math.random()*2-1` 起手，避免每次播放 `createBuffer` 造成 GC 抖动。**棕噪是原初与侵蚀两族的默认噪声源**，白噪只用于主宰与 UI。
  - 每实例只 `createBufferSource()`，`buffer` 指向共享 Buffer，`loop = true`，`start(t0)`，`stop(t0 + dur/1000 + 0.02)`。
  - 包络用 `gain.setValueAtTime(0.0001, t0)` → `linearRampToValueAtTime(peak, t0 + 0.001)` → `exponentialRampToValueAtTime(0.0001, t0 + dur/1000)`。
  - 扫频时 `f1` 必须 > 0，且使用 `exponentialRampToValueAtTime`；`f1 === f0` 时跳过扫频，只设固定值。
  - `drive > 0` 时追加一个 `peaking`（`frequency = 1200`、`Q = 1.1`、`gain = 6 * drive`）与一个 `highpass 120`；`drive = 0` 时不创建这两个节点，保证原初/主宰的节点预算不被侵蚀占用。
- `squareBlip(t0, {f0, f1, dur, gain})`：P0。方波经 `lowpass 1800` 后 3 次谐波被压掉约 12 dB，这是「不刺耳」的关键：裸方波在 2 kHz 以上的能量会在 30 个单位同屏时累积成噪声墙。默认 `f1 = 0.75 * f0`。该原语**是主宰的族标志音**，原初与侵蚀只在与机械/系统相关的事件（UI、采集提示）中使用。
- `sineSweep(t0, {f0, f1, dur, gain, sub})`：P0。`sub=true` 时在 `f1/2` 处再挂一路正弦，增益为主路 -6 dB。**原初的每一次武器与爆炸事件都必须带 `sub`**（生物的低频脉动），主宰只在建筑倒塌与战争单位开火时使用，侵蚀从不使用。
- `sawSweep(t0, {f0, f1, dur, gain, q})`：P0。默认 `q = 6`，共振峰随截止频率同步上扫；`q > 10` 会产生啸叫，禁止在武器类音效中使用（`chainZap` 内部的 `sawSweep` 层是唯一例外，它本身就在 `q = 12` 的带通之后）。
- `fmHit(t0, {fc, ratio, index, dur, gain})`：P1。调制器 `index` 从 6 指数衰减到 0，衰减时间 = `dur * 0.5`；`ratio` 建议 1.6 / 2.4 / 3.1 / 4.2 四档，分别对应「骨壳闷响（原初）」「兽类（混沌）」「金属（主宰）」「电子（主宰高级）」。**`ratio` 是单位音色差异的主旋钮**，见「单位音色变体表」。
- `impulseExplosion(t0, {scale, dur, sub, crack})`：P0。三层时间线固定：第 0 ms 起噪声 lowpass 扫 6000 → 120；第 0 ms 起 sine 90 → 28；第 0 ms 起 bandpass 1400 Q=1.2 只持续 120 ms 制造碎裂感。`scale` 线性缩放 `dur` 与低频层振幅，`scale ∈ [0.3, 1.4]`。**`crack ∈ [0, 1]` 是残骸碎裂层的强度**，由 `sfx.corpse.*` 三条事件独占使用。
- `chainZap(t0, {bursts, dur, gain, detuneSteps})`：P0。`bursts ∈ [3, 5]`，每次击穿间隔 35 ms ± 8 ms 随机，每次击穿由「square 1400 → 900 / 60 ms」+「bandpass 3200 Q=12 / 45 ms」组成，最后一跳叠加 `sawSweep 3000 → 200 / 180 ms`。`detuneSteps` 是**解放**事件的专用参数：给每一跳施加一组递增音分（`[0, +300, +700, +1200]`），制造「控制权上移一个八度」的电子转调感。
- `metalClank(t0, {base, dur, gain, bright})`：P1。4 个分音用 `detune` 实现，不用 4 个独立振荡器频率，节省参数写入。`bright=true` 时基频乘 2.2。该原语只服务主宰与系统音效；原初与侵蚀的「金属感」事件一律以 `fmHit(ratio 1.6)` 替代。

所有原语的**单实例节点数**必须 ≤ 6；`impulseExplosion` 为唯一例外，允许 7 个节点（3 source + 2 filter + 2 gain）；侵蚀带 `drive` 的实例允许 +2 个滤波节点。节点数超限会在 64 节点总预算下把并发数压到不足 10，破坏层次感。

### 14.4　音效事件总表

事件键名采用 `sfx.<域>.<名>` 命名空间，全小写驼峰。触发时机一栏描述的是「逻辑层发布的事件」，音频层不得主动轮询游戏对象。合成配方一栏中 `+` 表示并行叠加，`>>` 表示延迟串接，括号内为覆盖默认参数。基础音量为**满增益峰值**，最终响度还要乘以距离衰减、缩放补偿、合流补偿与混沌区域倍率。音高随机范围为在 `detune` 上施加的均匀随机量，±x% 换算为 `detune = 1200 * log2(1 + r)`，实现时直接预计算查找表避免每帧 `log2`。

### 14.5　三维定位、声像与同 tick 去重

#### 14.5.1　声像计算

世界坐标为格（tile），单位为浮点格；相机中心 `(cx, cy)` 单位同为格；缩放 `z ∈ [0.5, 2.0]`；画布逻辑尺寸 `W × H`（**默认 1920 × 1080**，与第 2/13 章的逻辑分辨率一致）。等距投影固定为 64 × 32 的菱形格。

```text
sx = W/2 + ((wx - cx) - (wy - cy)) * (TILE_W/2) * z
sy = H/2 + ((wx - cx) + (wy - cy)) * (TILE_H/2) * z

nx = (sx / W) * 2 - 1                    // -1 左边缘, +1 右边缘
a  = Math.abs(nx)
pan = (a <= 0.08) ? 0
    : Math.sign(nx) * 0.80 * Math.min(1, (a - 0.08) / 0.92)
```

参数与理由：

- 中央死区 0.08（P0）。屏幕中央 8% 宽度内的所有事件强制 `pan = 0`。没有死区时，30 个单位在中央混战时每一个的 `pan` 都在 ±0.15 之间随机跳动，主观听感是「左右乱甩」而不是「立体」。死区把中央战场压成稳定的单点声源，两侧才展开。
- 上限 0.80（P0）。禁止使用 ±1.0 全声像。全声像会让一只耳机完全没有信号，玩家会误判为「该侧没有战斗」；0.80 仍保留约 20% 的交叉泄漏，足以在单耳中保留存在感。
- 变化平滑（P1）。单位移动时 `pan` 不直接写值，而是 `panner.pan.setTargetAtTime(target, now, 0.05)`，时间常数 50 ms。60 帧内跨越整个屏幕的快速平移如果不平滑，会产生可闻的「拉链」。
- 屏幕外方向的 `pan` 由外推坐标计算后同样夹到 ±0.85（P1），用于离屏提示音指示方向。
- **残骸的 `pan` 取固定值 0**（P0）：残骸是静止的、价值与位置无关的**全局资源信号**，不让它随镜头左右摇摆。侵蚀的 `sfx.corpse.salvage` 同样 `pan = 0`，玩家永远从正中听到自己「吸」到了多少源质。

| 屏幕归一化位置 `nx` | 计算出的 `pan` | 主观定位 | 说明 |
| --- | --- | --- | --- |
| -1.00（左边缘） | -0.80 | 明显偏左 | 上限截断，非全左 |
| -0.50 | -0.365 | 左中 | 线性区 |
| -0.08 | 0.00 | 中 | 死区边界 |
| 0.00 | 0.00 | 正前 | 死区 |
| +0.08 | 0.00 | 中 | 死区边界 |
| +0.50 | +0.365 | 右中 | 线性区 |
| +1.00（右边缘） | +0.80 | 明显偏右 | 上限截断 |
| +1.60（屏外右侧） | +0.85 | 方向感 | 仅离屏提示音 |

#### 14.5.2　距离衰减

距离使用相机中心到单位的格距离，而不是屏幕像素距离，原因是屏幕像素距离随缩放变化会让「同一场战斗在放大后突然变响」。

```text
Rvis = W / (TILE_W * z)                  // 屏幕水平半宽对应的格数
Raud = Rvis * 2.0                        // 可听半径 = 2 倍可视半径
d    = Math.hypot(wx - cx, wy - cy)      // 格
n    = d / Rvis                          // 归一化距离, n=1 即屏幕边缘

gDist = (n >= 2.0) ? 0 : Math.max(0.10, Math.pow(1 - n / 2.0, 1.6))
gZoom = 0.62 + 0.38 * clamp((z - 0.5) / 1.5, 0, 1)

outGain = 10^(dB/20) * gDist * gZoom * gScale * gChaos
```

数值验算（W = 1920，TILE_W = 64，z = 1.0）：`Rvis = 30` 格，`Raud = 60` 格。`d = 0` 时 `gDist = 1.00`；`d = 30`（屏幕边缘）时 `n = 1.0`，`gDist = 0.5^1.6 = 0.33`；`d = 45` 时 `n = 1.5`，`gDist = 0.25^1.6 = 0.109`，被下界抬到 0.10；`d = 60` 时 `gDist = 0`，事件被剔除。

`gZoom` 的存在是为了修正一个直觉反例：玩家缩小视角（`z = 0.5`）时可视格数翻倍，若无补偿，屏幕内 40 个单位全部按 `gDist ≈ 0.5` 发声，总线能量翻两倍以上。`gZoom` 在 `z = 0.5` 时给 0.62、在 `z = 2.0` 时给 1.00，把这场「缩小时的音量膨胀」压回 ±1.5 dB 内。该条为 P1。

`gChaos`（P0，仅混沌单位）：取第 8 章「混沌·中心强化」的数值倍率 `clamp(1.6 − 1.2 × (d_center / dMax), 0.8, 1.6)`。地图中央的混沌巨兽与混沌领主因此**听着就比外围的同类更有压迫感**，这是玩家判断「这块区域能不能打」的听觉线索，必须与玩法层的倍率同源、同值。

#### 14.5.3　离屏提示音规则

- 仅当事件优先级 ≥ 7，且 `n > 1.35` 时触发。
- 播放 `sfx.ui.offscreenPing`，音量 = `基础线性增益 * 0.45 * clamp(1 - (n - 1.35) / 1.0, 0, 1)`。
- `pan` 由外推屏幕坐标算得并夹到 ±0.85。
- 同一事件键 250 ms 内只提示一次；全局同时最多 3 个离屏提示在飞；每 100 ms 全局最多新建 1 个。
- 提示音下沉：`sfx.ui.offscreenPing` 挂到 `bus.sfx` 的独立 `duckGain` 子链，不参与主 sfx 的距离衰减，避免二次衰减后听不见。

#### 14.5.4　同 tick 去重与轮播

逻辑帧 20 Hz，一帧 50 ms。一次大规模交火在同 tick 内可能产生 40 个 `sfx.weapon.heavyCannon`。直接全播会导致：总振幅线性相加产生削波、40 个几乎同相的 260 Hz 锯齿叠加产生强拍频、64 节点预算瞬间击穿。处理流程固定为四步（P0）：

1. **分桶**：按键名分组，同组内按 `(priority, -distance)` 排序。
2. **削顶**：每组最多保留 `min(复音上限, ceil(组内数量 / 2))` 个候选，其余直接丢弃（不延迟、不补偿）。
3. **合流补偿**：设保留数为 `k`，则该组每个实例的增益乘以 `gScale = clamp(1 / Math.sqrt(k), 0.28, 1.0)`。`k = 1` 时 1.00，`k = 4` 时 0.50，`k = 8` 时 0.354，`k ≥ 13` 时截断在 0.28。
4. **展开与失谐**：第 `i` 个实例（`i` 从 0 起）施加 `detune = [-38, -13, +13, +38][i % 4]` 音分与 `startDelay = i * 11 ms`，把同时发声撒成 0 / 11 / 22 / 33 ms 的小簇。这一步是「层次感」的主要来源：同样的 4 门炮，同相叠加听起来像 1 门响 4 倍，失谐 38 音分后听得出是 4 门。

**抢占（voice stealing）**：当某组已满，且新实例的得分高于组内最低分实例时，执行抢占。得分与迟滞固定为：

```text

若 newScore > victimScore + 15 则抢占，否则丢弃新实例
```

`n` 为归一化距离，`ageMs` 为受害实例已播放时长。迟滞量 15 分（等价 15% 优先级差）用于防止两个同优先级、同距离的事件在相邻 tick 内反复互相抢占造成的「断续」。抢占执行方式为：对受害实例的 `envGain` 施加 25 ms 指数淡出后 `stop()`，而不是立即 `disconnect`，立即断开会产生咔哒声（P0）。

全局层面还有一道兜底：`activeNodes > 64` 时，任何 `priority < 5` 的新事件在 `play()` 入口直接丢弃，`priority ≥ 5` 的事件可以抢占优先级最低的活跃实例；`activeNodes > 80` 时进入「紧急降档」，`bus.sfx.gain` 在 200 ms 内降到 0.65 并保持 1.5 s（P1）。

### 14.6　限流与性能预算

音频性能风险不在单个音效，而在「一帧内同步创建几百个节点」造成的长任务。因此所有创建动作集中在 `AudioEngine.update()` 内，并受三级配额约束。

| 配额名 | 限制值 | 统计窗口 | 超限行为 | 优先级 |
| --- | --- | --- | --- | --- |
| 每帧新建节点数 | ≤ 12 | 单个 rAF 帧 | 剩余事件按优先级降序推入下一帧队列，队列容量 32 | P0 |
| 每秒新建节点数 | ≤ 96 | 1000 ms 滑动窗口 | 丢弃 `priority ≤ 3` 事件 | P1 |
| 总活跃节点数 | ≤ 64 | 实时计数 | 丢弃 `priority < 5`；可抢占最低分实例 | P0 |
| 音乐保留节点 | 16 | 常驻 | sfx 实际可用 48 | P0 |
| 循环音保留节点 | 8 | 常驻（引擎 4 / 再生 2 / 反应堆 3 / 同化塔 2 共享池） | 超出时按「距镜头距离」升序截断，只保留最近的 | P1 |
| 单事件节点数 | ≤ 7 | 单实例 | 断言失败进调试面板 | P1 |
| 侵蚀失真节点 | ≤ +2 | 单实例（`peaking` + `highpass`） | 超出则强制 `drive = 0` | P2 |
| 每帧事件消费数 | ≤ 40 | 单逻辑帧 | 按优先级截断，剩余丢弃 | P1 |
| 每帧音频总耗时 | < 3.0 ms | 单逻辑帧 | 连续 30 帧超 8 ms 则降到 low 档 | P0 |

节点回收必须显式，禁止依赖 GC。每个 source 节点在 `start()` 之前就绑定：

```text
src.onended = function () {
  try { src.disconnect(); } catch (e) {}
  try { envGain.disconnect(); } catch (e) {}
  try { filter && filter.disconnect(); } catch (e) {}
  try { driveFilter && driveFilter.disconnect(); } catch (e) {}
  try { panner && panner.disconnect(); } catch (e) {}
  E.stats.activeNodes--;
  E.voices.delete(id);
};
src.stop(t0 + dur / 1000 + 0.02);
```

必须执行 `stop()` 的理由有三：一是 `AudioBufferSourceNode` 与 `OscillatorNode` 是一次性节点，不 `stop()` 会永久占用一个音频线程槽位；二是 Chrome 对活跃源节点有数量上限，超过后新建的源会静默失效，表现为「打着打着没声音了」；三是 `onended` 是唯一可靠的回收触发点。此外每 500 ms 运行一次看门狗，扫描 `AudioEngine.voices` 中 `startTime + dur + 200 ms < currentTime` 的僵尸实例（**循环音除外**，循环音由残骸/建筑的生命周期回调显式结束），强制 `disconnect()` 并计数（P1）；该计数在调试面板显示，正常应恒为 0。

避免 GC 抖动的措施（P1）：预生成三份共享噪声 Buffer（白 2 s / 粉 2 s / 棕 2 s），全部音效复用；音高随机与距离衰减查表预计算（256 项）；事件队列与候选数组在 `init()` 时一次性分配并循环复用，不在热路径 `push`/`splice`；丢弃的实例不产生任何新对象；`detune` 与 `pan` 使用 `Float32Array` 常量池；三套阵营参数（`detuneBias` / `cutoffScale` / `sub` / `drive`）与 33 件武器的单位变体偏移在 `init()` 时合并成一张扁平表，热路径只做一次整数索引。

CPU 预算分解（P0，目标机 Chrome 90 / 4 核 2.4 GHz / 无独显）：

| 阶段 | 预算 (ms) | 典型实测 (ms) | 说明 | 优先级 |
| --- | --- | --- | --- | --- |
| 事件队列消费与分桶 | 0.60 | 0.35 | 40 事件以内 | P0 |
| 去重、排序、抢占决策 | 0.45 | 0.28 | 快排小数组 | P0 |
| 声像与距离衰减计算 | 0.30 | 0.18 | 查表 + 一次 `hypot` + 一次 `gChaos` 查表 | P0 |
| 音乐前瞻调度 | 0.40 | 0.22 | 每帧排 0–4 个音符 | P0 |
| 节点创建与接线 | 1.00 | 0.66 | 12 节点以内（含侵蚀失真的 2 个额外滤波） | P0 |
| 节点回收与看门狗 | 0.25 | 0.10 | 每 500 ms 全扫一次 | P1 |
| 合计 | 3.00 | 1.79 | P95 应 < 3.0 | P0 |

音乐调度器不得使用 `setTimeout` 或 `setInterval` 驱动音符时值——这两个 API 在后台标签页被节流到 ≥ 1000 ms，会造成音乐整段塌陷。正确做法是在已有的 rAF 循环里，用 `AudioContext.currentTime` 做前瞻调度，见下一节。

#### 14.7.4　音序器实现与动态切换

音序器禁止使用 `setTimeout` / `setInterval` 驱动音符。实现要求在 `AudioEngine.update()` 里每帧执行一次前瞻调度（P0）：

```text
LOOKAHEAD = 0.100                       // 100 ms
STEP = 0.125                            // 八分音符 = 60 / BPM / 2, 按当前 BPM 计算
while (nextNoteTime < ctx.currentTime + LOOKAHEAD) {
  调度 nextNoteTime 上需要发声的所有层
  nextNoteTime += 60 / currentBPM / 4    // 十六分音符步长
}
```

- 步长按十六分音符推进（`60 / BPM / 4`，132 BPM 时 = 113.6 ms），每步只排该步实际存在的音符。
- `nextNoteTime` 初值为 `ctx.currentTime + 0.1`；`document.hidden` 恢复时重置为 `ctx.currentTime + 0.1`，丢弃穿越期间的音符。
- 每帧最多排 6 个音符事件（P1），超出则丢弃本帧剩余步进，避免一帧内堆积。
- 音乐常驻节点数 ≤ 16，超出时优先砍 pad 的第三层，再砍琶音的交替声像层（侵蚀段落额外优先关闭 `drive`，因为它的每层要多花 2 个滤波节点）。

动态切换由「战场激烈度」`I` 驱动，公式固定（P0）：

```text
E10 = Σ 爆炸与高价值死亡权重     // 过去 10 秒
      权重：infantry 0.4, vehicleS 0.7, vehicleL 1.0, air 0.8,
            buildingS 1.2, buildingL 1.5, corpseWar 2.0, chaosLair 2.5
F10 = Σ 开火权重                 // 过去 10 秒
      权重：spike(轻) 0.25, kinetic(轻) 0.30, corrode(轻) 0.25,
            chaosMelee 0.20, heavyMortar/Grenade 0.7, heavyCannon/Ram 1.0,
            heavyShock/Acid 1.2, heavyRailgun/Burst/Stomp 1.4,
            clusterBomb 1.6, lordRoar 1.3
D10 = 己方建筑受击次数           // 过去 10 秒
C10 = 战场残骸数量（当前帧快照，按 60 秒生命周期自然衰减）

I = clamp01(0.45 * (E10 / 6) + 0.25 * (F10 / 20) + 0.15 * (D10 / 4) + 0.15 * (C10 / 12))
```

`C10` 是《一叶》新增的第四项：残骸在战场上堆积本身就是「这场仗打得很凶」的直接证据，把它计入激烈度后，音乐会在**大规模阵亡之后仍持续紧绷一段时间**（残骸 60 秒才消散），而不是随着开火停止立刻回落到建造段。

| 档位 | `I` 区间（含迟滞 ±0.06） | 音乐段 | 附加层 | 音量 (dB) | 交叉淡入 (ms) | 优先级 |
| --- | --- | --- | --- | --- | --- | --- |
| T0 | I < 0.12 | 《叶脉之下》 | 无 | -6（相对 music bus） | 1200 | P0 |
| T1 | 0.12 ≤ I < 0.32 | 《叶脉之下》加强 | 加手鼓与叶片沙锤全 16 分、加膜鸣 | -6 | 1200 | P0 |
| T2 | 0.32 ≤ I < 0.58 | 《钢铁奴役》低强度 | 无 | -6 | 1200 | P0 |
| T3 | 0.58 ≤ I < 0.80 | 《钢铁奴役》高强度 | 加双踩、加派生的高八度电子琶音、90 Hz 基座 +3 dB | -5 | 1000 | P0 |
| T4 | I ≥ 0.80 | 《钢铁奴役》极限 | 加失真式 sawtooth 铜管层、pad 提高 2 dB | -4 | 800 | P1 |
| — | 胜负判定触发 | 《叶底回响》 | 一次性，不循环，尾句延长 4 拍后进入静默 | -4 | 600 | P1 |

切换规则（P0）：档位变化必须同时满足「`I` 越过阈值 + 迟滞 0.06」与「上一档位驻留 ≥ 3.0 s」；切换时旧段在 1200 ms 内 `setTargetAtTime` 淡出到 0，新段从 0 淡入并**从第 1 小节起点开始**，不做中途对齐。不做节拍对齐是刻意的取舍：对齐需要保存旧段的步进相位并在新段跳进，实现复杂度高且听感上未必更好，而 1200 ms 交叉淡入已足以掩盖接缝。

《叶底回响》的触发与 `I` 无关，由对局结束事件（第 20 章附录 B 的 `match:victory` / `match:defeat` / `match:draw`）驱动，播放一次（含 4 拍延长）后进入静默 2 s，再循环《叶脉之下》作为结算界面背景（P1）。

### 14.8　语音播报与音频优先级

EVA 语音使用 `SpeechSynthesis`，接口约定如下（本章只给接口与键名，文案原文见第 13 章「中文播报（EVA）触发事件表」，两章必须逐格一致）：

```text
EVA.speak(key, params) -> void
  key    : 'eva.constructionComplete' | 'eva.unitReady' | 'eva.unitLost' |
           'eva.baseUnderAttack' | 'eva.lowPower' | 'eva.powerRestored' |
           'eva.corpseSalvaged' | 'eva.techPlundered' | 'eva.slaveLiberated' |
           'eva.shieldBroken' | 'eva.veteranPromoted' | 'eva.oreDepleted' |
           'eva.warUnitReady' | 'eva.insufficientFunds' | 'eva.chaosLairDestroyed'
  params : { faction: 'PRIMORDIAL' | 'DOMINATOR' | 'EROSION', unitName?: string,
             buildingName?: string, essence?: number }
```

EVA 内部规则（P0）：`SpeechSynthesisUtterance` 的 `lang = 'zh-CN'`、`rate = 0.95`（与第 13 章一致）、`pitch` 按阵营取**原初 0.92 / 主宰 0.88 / 侵蚀 1.06**、`volume = settings.voice`；同一时刻只允许一条在播，新播报若优先级 ≥ 正在播报者则 `speechSynthesis.cancel()` 后立即播，否则入队（队列容量 3，满时丢弃优先级最低者）；两条播报最小间隔 **1000 ms**（与第 13 章防刷屏节流表一致；具体每种播报的最小重触发间隔以本节下方 EVA 事件表为准）。`speechSynthesis` 不可用或中文语音包缺失时，全部改走 `sfx.ui.evaFallback`。

| EVA 事件 | 触发时机 | EVA 优先级 | 最小间隔 (ms) | 可打断他人 | 关闭语音时的替代 | 优先级 |
| --- | --- | --- | --- | --- | --- | --- |
| `eva.chaosLairDestroyed` | 混沌巢穴被摧毁 | 5 | 15000 | 否 | `sfx.chaos.lairDown` | P2 |
| `eva.baseUnderAttack` | 建筑受击（首次） | 8 | 8000 | 是 | `sfx.ui.evaFallback` + `sfx.alarm.baseUnderAttack` | P0 |
| `eva.warUnitReady` | 己方战争单位完成生产（`py_wrath` / `dm_warlord` / `er_core_unit`） | 9 | 5000 | 是 | `sfx.ui.evaFallback` + `sfx.build.unitReady`（`scale` 提到 1.2 并叠 `sineSweep(120→60, 600ms, sub)`） | P0 |
| `eva.shieldBroken` | **仅主宰**：己方单位护盾被击穿 | 7 | 6000 | 是 | `sfx.unit.shieldBreak` | P0 |
| `eva.slaveLiberated` | 奴役控制节点被摧毁，10 格（同化塔后 20 格）内敌方奴役单位转为己方 | 7 | 10000 | 是 | `sfx.unit.liberate` | P0 |
| `eva.techPlundered` | **仅侵蚀**：满足「腐蚀掠夺」摧毁条件并解锁科技 | 6 | 10000 | 否 | `sfx.tech.plundered` | P0 |
| `eva.lowPower` | **仅主宰**：电力赤字出现 | 6 | 10000 | 否 | `sfx.ui.evaFallback` + `sfx.power.low` | P0 |
| `eva.powerRestored` | **仅主宰**：电力由负转正 | 5 | 5000 | 否 | `sfx.power.restored` | P0 |
| `eva.insufficientFunds` | 下单时源质不足 | 6 | 3000 | 否 | `sfx.ui.evaFallback` + `sfx.essence.insufficient` | P0 |
| `eva.constructionComplete` | 建筑完工 | 5 | 2000 | 否 | `sfx.build.complete`（不加 fallback 音） | P0 |
| `eva.veteranPromoted` | 单位升到老兵或精英 | 5 | 4000 | 否 | `sfx.unit.veteranUp`（精英用 `sfx.unit.eliteUp`） | P1 |
| `eva.unitLost` | 单位阵亡（30 s 内聚合播报） | 4 | 5000 | 否 | `sfx.explosion.vehicleL` | P1 |
| `eva.oreDepleted` | 源质矿脉或晶簇枯竭 | 4 | 8000 | 否 | `sfx.essence.depleted` | P2 |
| `eva.unitReady` | 单位出厂 | 3 | 1500 | 否 | `sfx.build.unitReady` | P1 |
| `eva.corpseSalvaged` | **仅侵蚀**：回收一份残骸 | 2 | 4000 | 否 | `sfx.corpse.salvage` | P2 |

**阵营专属播报（P0）**：`eva.lowPower` / `eva.powerRestored` / `eva.shieldBroken` 三条**只有主宰玩家会收到**（原初与侵蚀没有供电系统，也不拥有护盾单位）；`eva.techPlundered` / `eva.corpseSalvaged` 只有侵蚀玩家会收到；其余各条三方共用。逻辑层在派发前就按阵营过滤，音频层不做二次判断。

音量平衡约定（P0）：`settings.voice = 1.0` 对应系统 TTS 的 100% 音量，`settings.sfx = 0.9` 对应 `bus.sfx` 的 0.9 线性增益。EVA 说话期间，`bus.sfx` 通过共享 `duckGain` 在 120 ms 内降到 -4.5 dB，音乐降到 -2.5 dB；播报结束（`utterance.onend` 或 6 s 超时）后 400 ms 内恢复到 0 dB。语音自身不闪避，`bus.voice` 不参与闪避链。

播放被玩家关闭时的替代提示音（P1）：`settings.evaEnabled = false` 时，EVA 优先级 ≥ 6 的事件改播 `sfx.ui.evaFallback`（880→1320→880 Hz 双音，190 ms，-18 dB，优先级 8）；EVA 优先级 < 6 的事件直接用其对应的音效提示（见上表「关闭语音时的替代」列），不再叠加 fallback 音。该规则保证关闭语音后玩家仍能获知关键信息，且不会退化成全程蜂鸣。

### 14.9　混音默认值与设置界面

默认值与滑条范围固定如下，禁止在代码里散落硬编码，全部由 `AudioSettings.defaults` 单一来源提供（P0）。

| 控件 | 绑定字段 | 默认值 | 范围 | 步进 | 控件类型 | 生效方式 | 优先级 |
| --- | --- | --- | --- | --- | --- | --- | --- |

| 音效 | `sfx` | 0.90 | 0.00 – 1.00 | 0.01 | 水平滑条 | `bus.sfx.gain` | P0 |
| 音乐 | `music` | 0.45 | 0.00 – 1.00 | 0.01 | 水平滑条 | `bus.music.gain` | P0 |
| 语音 | `voice` | 1.00 | 0.00 – 1.00 | 0.01 | 水平滑条 | `Utterance.volume` + `bus.voice.gain` | P0 |
| 静音 | `muted` | false | true / false | — | 复选框 | `bus.master.gain` → 0 / 0.8 | P0 |
| 语音播报 | `evaEnabled` | true | true / false | — | 复选框 | 切换 EVA 通路 | P1 |
| 背景音乐 | `musicEnabled` | true | true / false | — | 复选框 | `musicScheduler.enabled` | P1 |
| 音频质量 | `qualityTier` | `'high'` | high / low | — | 下拉 | 复音上限 64 / 32，并关闭残骸循环音与侵蚀 `drive` | P2 |

设置界面的滑条标签必须以百分比显示（`0.80` → `80%`），拖拽时实时生效（不发防抖），`localStorage` 写入才做 400 ms 防抖。滑条拖动期间不得重新创建任何节点，只写增益。

`localStorage` 键名与结构固定为（P0）：

- 键名：`oneleaf.audio.settings.v1`
- 值为 JSON 字符串，结构如下：

```json
{
  "version": 1,
  "master": 0.8,
  "sfx": 0.9,
  "music": 0.45,
  "voice": 1.0,
  "muted": false,
  "evaEnabled": true,
  "musicEnabled": true,
  "qualityTier": "high",
  "corpseSfx": true
}
```

| 字段 | 类型 | 缺省回退值 | 校验规则 | 非法值处理 | 优先级 |
| --- | --- | --- | --- | --- | --- |
| `version` | integer | 1 | 必须等于 1 | 不等于 1 时整份配置丢弃，用默认值 | P0 |
| `master` | number | 0.80 | `[0, 1]` 有限数 | 越界夹紧，NaN 用缺省 | P0 |
| `sfx` | number | 0.90 | `[0, 1]` 有限数 | 同上 | P0 |
| `music` | number | 0.45 | `[0, 1]` 有限数 | 同上 | P0 |
| `voice` | number | 1.00 | `[0, 1]` 有限数 | 同上 | P0 |
| `muted` | boolean | false | 严格布尔 | 非布尔用缺省 | P0 |
| `evaEnabled` | boolean | true | 严格布尔 | 非布尔用缺省 | P1 |
| `musicEnabled` | boolean | true | 严格布尔 | 非布尔用缺省 | P1 |
| `qualityTier` | string | `"high"` | ∈ {`high`, `low`} | 其他值用 `"high"` | P2 |
| `corpseSfx` | boolean | true | 严格布尔 | 非布尔用缺省 | P2 |

读取必须在 `AudioEngine.init()` 之前完成，因为 `bus` 的初始增益要用存档值创建，避免「先按默认值建、再改一次」造成首帧的增益跳变。`localStorage` 读取本身包一层 try/catch，隐私模式下 `localStorage` 抛错时全用默认值（P0）。
