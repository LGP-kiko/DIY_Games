## 11　视野与战争迷雾

### 11.1　迷雾模型（P0）

采用**双层迷雾**（与《星际争霸》一致的经典模型）：

| 层 | 键名 | 含义 | 玩家看到什么 | 渲染 |
| --- | --- | --- | --- | --- |
| 黑幕 | `unexplored` | 从未被己方视野覆盖过 | 什么都看不到 | 完全不透明黑色 `#000000` |
| 灰雾 | `explored` | 曾经看到过，但当前无视野 | 地形（当前状态）+ 建筑轮廓（记忆） | 覆盖 `rgba(6,10,16,0.55)`；建筑用 `rgba(120,140,170,0.35)` 描边轮廓，不显示血量与朝向变化 |
| 可见 | `visible` | 当前在己方单位的视野内 | 一切（含敌方单位与建筑） | 无覆盖 |

**关键规则（P0）**

| 规则 | 规定 |
| --- | --- |
| 记忆的建筑 | 灰雾中的己方建筑正常显示；敌方建筑以「最后已知状态」显示轮廓，**若该建筑已被摧毁则轮廓在 10 秒后淡出消失**。混沌巢穴 `ch_lair` 是唯一的例外，见 11.7 |
| 记忆的单位 | 敌方**单位**在离开视野后**立即消失**（不保留记忆） |
| 地形记忆 | 灰雾中的地形显示为「探索时的状态」；若源质矿脉或晶簇被采空，灰雾区域也同步更新为采空后的地形（简化：直接查当前地形数组；采空格的 `terrain` 由 `essence` / `crystal` 改回 `flesh` 或 `rot`） |
| 己方单位 | 永远可见（即使在黑幕中，例如刚空投的单位） |
| 中立/友军 | 己方与盟友（P2）共享视野；**混沌单位不参与任何一方的视野共享**（见 11.4） |
| 钻地单位 | `py_burrow`（地脉行者）与 `er_digger`（掘地者）在钻地状态下**不为己方提供任何视野**（其`视野`值 12 格在钻地期间按 0 处理），出土后立即恢复 |
| 对称性 | 每个玩家维护一份独立的迷雾状态数组 |

### 11.2　数据结构（P0）

```js
// 每方一份；w×h = 96×96 = 9216 字节
class FogMap {
  constructor(w, h) {
    this.w = w; this.h = h;
    this.state = new Uint8Array(w * h);   // 0=unexplored, 1=explored, 2=visible
    this.sight = new Uint8Array(w * h);   // 本帧视野布尔（0/1），用于快速重算
    this.version = 0;                     // 每次可见集变化 +1

    // P0：灰雾中敌方建筑与残骸的「记忆表」，避免每帧重建
    this.ghostBuildings = new Map();      // entityId -> { type, tileX, tileY, lastSeenTick }
    this.ghostCorpses   = new Map();      // corpseId  -> { unitType, cost, maxHp, tileX, tileY, lastSeenTick }
    this.lairsRevealed  = false;          // 混沌巢穴是否已写入中立标记层
  }
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `state` | `Uint8Array(w*h)` | 累积状态，只增不减（`explored` 一旦获得就永久保留） |
| `sight` | `Uint8Array(w*h)` | 每 5 tick 全量清零重建 |
| `version` | number | 供渲染层判断是否需要重绘迷雾分块缓存 |
| `ghostBuildings` | `Map` | 敌方建筑离开视野后的「最后已知状态」，保留 10 秒（200 tick） |
| `ghostCorpses` | `Map` | 灰雾中残骸的轮廓记忆，**保留到该残骸过期或被重新看见为止**，不与建筑的 10 秒规则共用 |
| `lairsRevealed` | boolean | 混沌巢穴的中立标记只需写入一次（巢穴不移动、不重建） |

### 11.3　视野计算（P0）

| 规则 | 规定 |
| --- | --- |
| 视野来源 | 每个己方单位与建筑都提供视野半径 `sight`（见第 8 章数据表：`py_burrow` / `er_digger` 12 格、`py_wing` / `er_bloat` / `ch_moth` 9 格、`dm_bomber` 6 格、`ch_lord` 10 格、`ch_lair` 10 格、`py_pulse` 14 格） |
| 视野形状 | 以实体所在格为中心的**圆形**（欧氏距离 ≤ `sight`），不是方形 |
| 高度加成 | `effectiveSight = sight + min(2 × z, 4)`（每层 +2 格，上限 +4，与第 5 章 5.4 一致） |
| 老兵加成 | 老兵 +1、精英 +2（见第 8 章） |
| 隐形单位 | `er_stalker`（潜行刺）`stealthed === true` 时，**敌方**完全看不到它、索敌也不会选中它；但**己方**的隐形单位照常提供视野（隐形只影响「被看见」，不影响「自己能看见」）。同一格上若存在己方单位，该格对己方仍为可见 |
| 钻地单位 | `py_burrow` / `er_digger` 钻地时不提供视野，且不会被敌方视野「盖章」到（钻地单位自身所在格不产生任何可见性） |
| 建筑视野 | 建筑视野为其外接矩形向外扩展 `sight` 格 |
| 更新频率 | **每 5 tick** 全量重算（20 Hz 逻辑 → 4 Hz 视野更新）；重算时先清零 `sight`，再遍历所有己方实体并「盖章」 |
| 盖章算法 | 对半径 r 的圆，按行扫描：`for dy in -r..r: dxMax = floor(sqrt(r*r - dy*dy)); 填充 [cx-dxMax, cx+dxMax]`；使用整数平方比较避免开方 |
| 边界 | 超出地图范围的格直接跳过 |
| 状态更新 | 盖章到的格：`sight=1`；若 `state < 2` 则 `state = 2`。未被盖章的格：若 `state === 2` 则降为 `1` |
| 可见集变化 | 若本 tick 与上一 tick 的 `state` 数组有任何差异 → `version++` 并触发 UI 层「新发现敌人」检查，同时刷新 `ghostBuildings` 与 `ghostCorpses` |

| 性能预算 | 数值 |
| --- | --- |
| 单次全量重算 | 200 实体 × 平均 90 格盖章 = 18 000 次写入，≤ 1.5 ms（每 5 tick 分摊 = 0.3 ms/tick） |
| 幽灵表维护 | `ghostBuildings` ≤ 64 项、`ghostCorpses` ≤ 256 项，每 5 tick 只做过期剔除，≤ 0.1 ms |
| 渲染用迷雾位图 | 96×96 的 `ImageData`（240×240 像素，2.5 px/格），仅在 `version` 变化时重绘 |

### 11.4　迷雾对游戏逻辑的影响（P0）

| 系统 | 规则 |
| --- | --- |
| 玩家索敌 | 玩家单位**不能**攻击不可见的敌方单位（自动索敌会排除 `state !== 2` 的格上的敌人） |
| 强制攻击 | 允许对灰雾中的「最后已知位置」强制攻击（打空就浪费弹药，这是合理的信息战成本） |
| 右键点黑幕 | 视为移动到该点的命令（允许盲走） |
| 小地图 | 只在可见区域显示敌方单位；灰雾中的敌方建筑显示为半透明轮廓 10 秒后消失 |
| 电脑 AI | 简单/普通/困难难度的 AI **必须**受迷雾限制，只能基于己方视野做出决策；残酷难度可获得「全图建筑位置可见」特权（见 12.2） |
| 建筑选址（人类） | 黑幕区域不可建造（必须先用单位探索） |
| 源质矿脉可见 | 地形（含源质矿脉 `essence` 与晶簇 `crystal`）在探索后永久可见，即使无视野也能看到矿脉位置与剩余储量 |
| 敌方建造提示 | 若在己方可见区域探测到敌方新建建筑（蓝图），播报「发现敌方建造中」 |
| **混沌单位不参与视野共享** | `ch_wanderer` / `ch_spitter` / `ch_behemoth` / `ch_moth` / `ch_lord` 属于 `CHAOS`，**不属于任何一方**：它们不向任何玩家提供视野，也不从任何玩家获得视野，**更不参与任何一方的视野共享**。混沌单位自己的「视野」只用于它自己的索敌判定 |
| **侵蚀视角下的混沌** | 由于侵蚀「不被中立敌对」（混沌不会主动攻击侵蚀，除非侵蚀先动手），侵蚀玩家的迷雾中，**混沌单位显示为黄色中立点**（颜色取混沌主色 `#c08a2e`），而不是红色敌对点。该显示规则**只在侵蚀视角生效**；原初与主宰视角下混沌单位按普通敌方单位显示为红色点。黄色中立点同样遵守可见性规则：只有进入 `visible` 才显示，灰雾中不显示 |
| 残骸可见性 | 见 11.6（灰雾中的残骸只显示图标轮廓、不可交互） |
| 混沌巢穴 | 见 11.7（小地图上始终显示为固定中立标记，即使未探索） |

### 11.5　隐形与侦测（P0）

| 规则 | 规定 |
| --- | --- |
| 隐形单位 | 本作仅 `er_stalker`（潜行刺，侵蚀）具备隐形能力 |
| 隐形条件 | **静止满 40 tick（2 秒）→ `stealthed = true`**；移动或开火立即取消隐形 |
| 隐形表现（对己方） | 半透明（`globalAlpha = 0.45`）+ 轮廓虚线 |
| 隐形表现（对敌方） | 完全不可见、不可索敌、不出现在小地图；不参与分离力计算（敌方单位不会因为撞到它而被推开） |
| 唯一克制 | **本作没有探测器**。因此 `er_stalker` 的唯一克制方式是「逼它移动」（用溅射伤害或强制攻击逼它起身）或用重型武器盲打。雷达类建筑（`dm_radar`、`py_pulse`、`er_tendril`）只提供小地图显示，**不提供侦测** |
| 强度控制 | 由于无侦测，`er_stalker` 的强度必须靠数据控制：体力 360、单价 620、武器 `w_er_stalker` 穿刺为轻型（对单）基础伤害 55 / 射速 45 tick（DPS 约 24.4），不含任何对建筑的额外加成，不能单独拆家 |

**钻地（P0）**

| 规则 | 规定 |
| --- | --- |
| 钻地单位 | `py_burrow`（地脉行者，原初）与 `er_digger`（掘地者，侵蚀），第 8 章单位表中均标注 `burrow: true` |
| 钻地条件 | **移动中自动钻地**：单位一旦开始沿路径移动即进入 `burrowed = true`，抵达并静止后 20 tick（1 秒）出土 |
| 钻地时的状态 | **不可被选中**（玩家点击地面或框选都不会选中它）、**不可被攻击**（敌方无法索敌，也无法对其强制攻击），且**不能攻击、不能提供视野**——伤害列表中的 `—` 表示两者本就没有武器 |
| 钻地的代价 | 钻地不是隐身而是「暂离战场」：钻地期间单位**不能占领、不能修理、不能占领资源**，也不能作为视野来源；出土前有 20 tick 的暴露窗口，敌方可以在此窗口内集火 |
| 与隐形的区别（P0） | `er_stalker` 是**隐形**：静止 2 秒后隐身，但仍可被溅射盲打命中，且己方仍能看见它；`py_burrow` / `er_digger` 是**钻地**：移动中不可见也不可被攻击，但代价是丧失全部主动能力。两者不得混用同一套字段：隐形用 `stealthed`，钻地用 `burrowed` |

### 11.6　最后已知位置（P1）

| 规则 | 规定 |
| --- | --- |
| 记录内容 | 每次敌方实体离开己方视野时，记录 `{ entityId, type, tileX, tileY, tick }` |
| 保存时长 | 600 tick（**30 秒**）——仅适用于「小地图上的最后已知位置红点」 |
| 显示 | 小地图上以半透明红点显示；主画面不显示。**侵蚀视角下该红点不适用于混沌单位**，混沌单位在侵蚀的小地图上使用 11.4 的黄色中立点表示 |
| 过期 | 超过 30 秒自动清除；若该实体再次进入视野则刷新 |
| 用途 | 让玩家能推断敌方进攻方向，而不至于完全瞎打 |
| 与建筑轮廓的区别（P0） | **不要与 11.1 的「敌方建筑记忆轮廓」混淆**：灰雾中的敌方**建筑**轮廓在主画面保留 **10 秒**后淡出；建筑的最后已知位置在小地图上保留 **30 秒**；敌方**单位**离开视野后立即消失，不保留任何记忆 |
| 残骸不进入本表 | 残骸的位置记忆走 11.6 的 `ghostCorpses`，**不写入最后已知位置表**（否则小地图会被残骸红点淹没） |

### 11.7　残骸在迷雾中的表现（P0）

残骸（第 8 章：任意单位被摧毁后留下，携带**最大体力**与**初始造价**两项信息，保留 **60 秒 = 1200 tick**）是四套机制的公共载体，因此它在迷雾中的表现必须精确区分，否则玩家会误判侵蚀与混沌的行为。

| 迷雾状态 | 渲染 | 可交互性 | 数据来源 |
| --- | --- | --- | --- |
| `visible`（己方视野内） | **正常显示**：残骸模型 + 阵营色轮廓，悬停时显示完整信息面板 | **可悬停查看原始单位与造价**；可被工程单位或残骸熔炉回收；侵蚀玩家可主动回收（10%） | 实时残骸实体 `corpse` |
| `explored`（灰雾中） | **只显示图标轮廓**：残骸的 24×24 图标（第 13 章 `corpse_icon`）以 `rgba(120,140,170,0.35)` 描边，不绘制模型与阵营色 | **不可交互**：不可悬停查看信息、不可点击、不可被回收、不产生任何音效提示 | `FogMap.ghostCorpses` |
| `unexplored`（黑幕中） | 完全不显示 | 不可交互 | — |

| 残骸迷雾规则 | 规定 |
| --- | --- |
| 灰雾记忆的建立 | 残骸**必须在己方视野内出现过至少一次**，才会写入 `ghostCorpses`；从未被看见的残骸在灰雾中不显示任何东西 |
| 灰雾记忆的失效 | 残骸过期（1200 tick）时，其 `ghostCorpses` 条目立即清除；若残骸被吞噬或被回收，也在同一 tick 清除（因此灰雾中不会留下「幽灵残骸」） |
| 重新进入视野 | 残骸再次进入 `visible` 时，`ghostCorpses` 条目被实时实体覆盖，恢复完整显示与可交互性 |
| 与侵蚀回收的关系 | 侵蚀的自动回收**只在 `visible` 范围内成立**：`er_furnace` 半径 10 格的吸收本身是己方视野判定，灰雾中的残骸**不会**被自动吸收（玩家必须先夺取视野） |
| 战争单位的残骸 | `py_wrath` / `dm_warlord` / `er_core_unit` 的残骸**不产生可回收价值**（侵蚀回收为其造价 0%），但**仍会生成残骸供混沌吞噬**，因此它在灰雾中同样只显示轮廓（避免玩家误以为可以回收） |
| UI 文本 | 灰雾中悬停残骸轮廓时，若鼠标停在该格上，只显示一行灰字「未知残骸（需要视野）」；`visible` 状态下才显示「原始单位 / 初始造价 / 剩余时间」 |

### 11.8　小地图与迷雾的交互（P0）

| 规则 | 规定 |
| --- | --- |
| 底图 | 小地图的地形底图使用「已探索」并集预渲染到离屏 canvas，每 30 tick 或 `version` 变化时更新 |
| 迷雾遮罩 | 在小地图上叠加一层 240×240 的迷雾遮罩（黑=未探索，半透明=灰雾） |
| 视野框 | 用 1 像素白色矩形标出当前镜头可视区域 |
| 点击 | 左键点击 → 镜头跳到该位置（即使处于黑幕）；右键 → 对选中单位下达移动命令（同样允许盲走） |
| 闪烁警报 | 己方建筑被攻击时，小地图上该位置闪烁红点（每 500 ms 一次，持续 3 秒） |
| **混沌巢穴固定标记** | `ch_lair`（混沌巢穴）在小地图上**始终显示为固定的中立标记**（3×3 像素的 `#c08a2e` 菱形，外描 1 像素深色边），**即使该格仍处于黑幕中也必须显示**——因为它是全图的公共资源目标与全局威胁源，玩家必须在开局就知道自己在向哪个方向扩张会遇到混沌。该标记**不随迷雾遮罩被覆盖**，绘制在迷雾遮罩之上、视野框之下 |
| 巢穴标记的消亡 | `ch_lair` 被摧毁后，该标记改为 30 秒的闪烁「已清空」空心菱形后消失；该区域不再刷新混沌单位（见 12.11），标记不再出现 |
| 混沌单位标记 | 黄点（侵蚀视角）或红点（原初/主宰视角）只在 `visible` 时显示；灰雾中不显示。混沌巢穴标记与混沌单位标记**视觉上必须可区分**：前者是恒定尺寸的菱形，后者是 2×2 像素的圆点 |

### 11.9　迷雾相关的表现与音效（P1）

| 事件 | 表现 |
| --- | --- |
| 首次发现敌方建筑 | 播报「发现敌方建筑」，小地图上标记红点 |
| 首次遭遇敌方部队 | 播报「遭遇敌军」；若遭遇的是混沌单位且玩家为侵蚀，改为播报「中立生物（未敌对）」并使用中性音效 |
| 敌方单位进入视野 | 无播报（避免噪音），仅画面出现 |
| 侵蚀单位首次进入混沌巢穴视野 | 播报「发现混沌巢穴」，同时在主画面高亮巢穴轮廓 1 秒 |
| 迷雾探索推进 | 黑幕边缘有新地形揭示时无音效（雾效本身即为反馈） |
| 雷达站被摧毁 | 播报「雷达离线」，小地图立刻进入「仅显示最后已知位置」状态（主宰的 `dm_radar` 断电时同样触发此表现） |
| 残骸进入灰雾 | 无音效；残骸从完整显示淡出为轮廓，用 300 ms 交叉淡化过渡 |

### 11.10　实现检查清单（P0）

- [ ] 每方一份独立的 `FogMap`，互不干扰。
- [ ] 迷雾状态在每 5 tick 更新，且更新发生在移动与死亡结算**之后**（见第 9 章管线第 10 步）。
- [ ] 自动索敌严格排除非可见格上的敌人。
- [ ] 灰雾中保留地形与敌方建筑轮廓，但不保留敌方单位。
