## 19　验收标准

本章是《一叶 / One Leaf》**交付验收的唯一依据**。交付物是单文件 `OneLeaf.html`（纯原生 JS + Canvas 2D 等距渲染，零依赖零素材，`file://` 双击可玩）；数值的唯一来源是 `Export\一叶_数值设定表.xlsx`（17 个工作表）与 `Export\yiye_data_pack.json`，地形、地图与战役数据的唯一来源是 `yiye_maps.js`。实施方必须逐条自测并在 `SELFTEST.md` 中打勾；任何 **P0 项**不通过即视为交付失败。每条都给出「验证方法」与「通过判据」，验收者无需阅读其他章节即可执行。

### 19.17　验收执行顺序建议

1. 先跑 **A 组**（交付与运行），不通过则无需继续。
2. 再跑 **B、C 组**（框架与性能），这是后续一切的地基。
3. 按 S1–S8 阶段顺序逐组验收（D 组地形、E 组经济与残骸、F 组建造、G 组选择、H 组移动、I 组伤害查表、J 组迷雾、K 组 UI、L 组音频、M 组 AI、N 组地图与战役、O 组存档），每阶段完成后回归测试前面已通过的组。
4. 最后跑 **P 组**（平衡与体验），需要至少 5 局完整对局，并**必须包含三个可选阵容各至少 1 局**。
5. 全部 P0 项通过后，把 `SELFTEST.md` 与 `OneLeaf.html` 一并交付；`Export\一叶_数值设定表.xlsx` 与 `Export\yiye_data_pack.json` 作为数值审阅附件一并提交。

### 19.18　一票否决项（P0 红线）

出现下列任一情况，**无论其他项表现如何，均判定交付失败**：

- 游戏无法在 `file://` 下打开，或运行时报 Error。
- 存在 `Math.random()` 驱动战斗逻辑，或逻辑跑在可变步长上。
- **伤害未走查表而实时套公式**（在结算路径里现算 `max( min(6 - n, x), x * (1 - 0.1n) - n )` 或 `5 / (5 + n!) * x`），或两张伤害查表与 `Export\一叶_数值设定表.xlsx` 存在任何一格差异，或存在 x 超出 1–200 查表范围的武器。
- **战争单位受到特殊效果影响**（`py_wrath` / `dm_warlord` / `er_core_unit` 中的任意一个被老兵、护盾、再生、吞噬、腐蚀或解放改变）。
- **奴役单位可被玩家直接下令**（`dm_slave` 能被点选、框选或接收任何命令）。
- **残骸不携带最大体力与初始造价信息**，或残骸不保留 60 秒。
- **主宰以外的阵营出现电力资源条**（原初或侵蚀的 UI 中出现电力字段、电力条或「缺电」灰显）。
- AI 在简单 / 普通 / 困难难度下无视战争迷雾。
- 缺少完整的建造—生产—战斗—胜负闭环（例如无法真正摧毁敌方基地）。
- 缺少双层战争迷雾或缺少小地图。
- 美术或音频依赖任何外部文件（图片、音频、字体、CDN）。
- 出现「无解单位」（无法被任何手段有效克制）。
- 游戏在 200 单位规模下帧率低于 30 FPS。
