## 16　存档与回放

本章定义《一叶 / One Leaf》的**确定性模拟内核**、**状态哈希**、**存档格式**、**回放格式**、**自动存档与崩溃恢复**以及**多人 lockstep 预留接口**。本章是全项目唯一允许定义「一份游戏状态如何变成一串字节、又如何从字节恢复成一个可继续运行的世界」的地方；任何其它章节若与本规格冲突，以本章为准。

交付形态是**单文件 HTML**（`OneLeaf.html`），纯原生 JavaScript + Canvas 2D 等距渲染，**零第三方依赖**，因此持久化能力被严格限制为 `localStorage`（P0）与 File System Access API（P2 可选导出/导入 `.oleaf` 文件）。没有服务器、没有数据库、没有 IndexedDB（不作为 P0 依赖）。这意味着所有存档、回放、自动存档逻辑必须在**不超过 200 行核心代码**的规模内做到工业级可靠。

逻辑帧固定为 **20 Hz（1 tick = 50 毫秒）**，这是本章一切体积估算与耗时估算的分母：30 分钟一局 = 1800 秒 = **36000 tick**。等距投影按 `screenX=(x-y)*32`、`screenY=(x+y)*16-z*12` 换算，**1 格 = 世界 1 单位**；坐标系与投影只影响渲染，**不进逻辑、不进哈希、不进存档**（镜头字段除外，它们只用于还原界面）。

### 16.1　系统边界与优先级总览

| 子系统 | 目标指标 | 优先级 | 交付物 | 依赖 |
| --- | --- | --- | --- | --- |
| 确定性模拟内核 | 同一输入序列在任意机器上产生逐位相同的状态 | P0 | 固定步长循环、禁用项清单、可播种 PRNG | 无 |
| 状态哈希 | 单次计算小于 2 毫秒，覆盖全部逻辑字段 | P0 | FNV-1a 32 位实现 | 确定性内核 |
| 存档格式 | 单槽小于 512 KB，保存与读取各小于 100 毫秒 | P0 | JSON 模式 + deflate-raw 压缩 | 状态哈希 |
| 回放格式 | 单局小于 256 KB，可跳转、可校验 | P0 | lockstep 命令流 + 哈希检查点 | 存档格式 |
| 自动存档与崩溃恢复 | 每 60 秒落盘，崩溃后可恢复 | P0 | 环形自动槽位 + 心跳标记 | 存档格式 |
| 多机联机 lockstep | 2 tick 输入延迟、掉线不卡死 | P2 | 命令缓冲队列 | 回放格式 |

**关键设计决策（一次说清，后文不再重复论证）**：本作**不做状态同步（state sync），只做命令同步（lockstep command sync）**。存档保存的是**状态快照**，回放保存的是**种子 + 初始快照 + 命令流**。两者共用同一套序列化原语和同一套哈希校验代码，这是把代码量压到最低的唯一可行路径。

《一叶》比旧项目多出**四类必须进存档的状态**，本章全程以它们为主线：**残骸**（任意单位被摧毁后留下，携带最大体力与初始造价，保留 60 秒）、**混沌巢穴**（每处巢穴的存活状态、数值倍率、已刷新单位列表、是否已被清空）、**奴役单位与解放来源**（主宰的奴隶、被解放后的归属与控制节点）、**护盾与钻地**（主宰高级单位的脱战回复护盾、原初与侵蚀的钻地潜行状态）。任何一处遗漏都会让「同一存档读入两次」在 600 tick 后产生不同的世界。

### 16.2　确定性模拟总纲

#### 16.2.1　固定步长循环的正确写法

**P0**。渲染帧率与逻辑帧率必须彻底解耦。`requestAnimationFrame` 回调提供的 `nowMs` **只允许**用于计算「本次应该跑几个 tick」，**绝对不允许**进入任何游戏状态字段、任何伤害公式、任何 AI 决策。逻辑世界内部只认识一个单调递增的整数 `tick`。

必须实现三个保护：**累加器（accumulator）**、**追帧上限（catch-up cap）**、**积压丢弃（spiral-of-death guard）**。当浏览器标签页被切到后台、或玩家拖动窗口导致 rAF 停摆数秒时，若不加保护，`accumulatorMs` 会累积到上万毫秒，一帧内试图跑数百个 tick，导致下一次 rAF 更晚，形成死亡螺旋直至页面卡死。

```js
// ============================================================
// OneLeaf 固定步长主循环（P0）
// 逻辑：20 Hz 定步长；渲染：可变帧率 + 插值
// 唯一允许读取时间的地方就是这里，且只用于「跑几个 tick」
// ============================================================

var TICK_MS = 50;               // 1 tick = 50 毫秒，20 Hz
var MAX_CATCHUP_TICKS = 5;      // 单帧最多追 5 个 tick = 250 毫秒
var MAX_FRAME_DELTA_MS = 250;   // 单帧时间差上限，超出直接截断

var SimLoop = {
  accumulatorMs: 0,     // 残差累加器，不参与逻辑决策
  lastFrameMs: 0,
  started: false,
  droppedTicks: 0,      // 统计用：因追帧上限被丢弃的 tick 数
  frames: 0,
  rafId: 0
};

function simLoopFrame(nowMs) {
  SimLoop.rafId = requestAnimationFrame(simLoopFrame);
  SimLoop.frames++;

  if (!SimLoop.started) {
    SimLoop.started = true;
    SimLoop.lastFrameMs = nowMs;
    return;
  }

  var deltaMs = nowMs - SimLoop.lastFrameMs;
  SimLoop.lastFrameMs = nowMs;

  // 保护 1：单帧时间差截断（后台标签页恢复、断点调试）
  if (deltaMs < 0) { deltaMs = 0; }
  if (deltaMs > MAX_FRAME_DELTA_MS) { deltaMs = MAX_FRAME_DELTA_MS; }

  SimLoop.accumulatorMs += deltaMs;

  // 保护 2：追帧上限
  var steps = 0;
  while (SimLoop.accumulatorMs >= TICK_MS && steps < MAX_CATCHUP_TICKS) {
    SimLoop.accumulatorMs -= TICK_MS;
    steps++;
    World.tick++;                 // 全局 tick 计数器，逻辑时钟唯一来源
    simulateTick(World.tick);     // 纯函数式推进：输入 World + 本 tick 命令
    postTickHook(World.tick);     // 哈希检查点、自动存档计时、回放录制
  }

  // 保护 3：仍然积压则丢弃，防止死亡螺旋
  if (steps >= MAX_CATCHUP_TICKS && SimLoop.accumulatorMs >= TICK_MS) {
    var dropped = Math.floor(SimLoop.accumulatorMs / TICK_MS);
    SimLoop.droppedTicks += dropped;
    SimLoop.accumulatorMs -= dropped * TICK_MS;
  }

  // alpha 只用于渲染插值，禁止写回任何逻辑字段
  var alpha = SimLoop.accumulatorMs / TICK_MS;
  renderWorld(World, alpha);
}

function startSimLoop() {
  SimLoop.accumulatorMs = 0;
  SimLoop.lastFrameMs = 0;
  SimLoop.started = false;
  SimLoop.rafId = requestAnimationFrame(simLoopFrame);
}
```

| 参数名 | 取值 | 单位 | 说明 | 优先级 |
| --- | --- | --- | --- | --- |
| TICK_MS | 50 | 毫秒 | 逻辑帧长，永久固定，不可配置 | P0 |
| TICK_HZ | 20 | 赫兹 | 每秒逻辑帧数 | P0 |
| MAX_CATCHUP_TICKS | 5 | tick | 单帧追帧上限，等于 250 毫秒 | P0 |
| MAX_FRAME_DELTA_MS | 250 | 毫秒 | 单帧时间差截断阈值 | P0 |
| TICKS_PER_SECOND | 20 | tick | 时间换算常量 | P0 |
| TICKS_PER_MINUTE | 1200 | tick | 时间换算常量 | P0 |
| TICKS_PER_30MIN | 36000 | tick | 体积估算基准 | P0 |
| HASH_INTERVAL | 300 | tick | 状态哈希检查点间隔，等于 15 秒 | P0 |
| AUTOSAVE_INTERVAL | 1200 | tick | 自动存档间隔，等于 60 秒 | P0 |
| CORPSE_TTL_TICKS | 1200 | tick | 残骸保留时长，等于 60 秒（第 8 章 `CORPSE_TTL_SEC`） | P0 |
| SHIELD_REGEN_DELAY_TICKS | 100 | tick | 主宰护盾脱战 5 秒后开始回复 | P0 |

| SPEED_MULTIPLIER | {0.75, 1, 1.5, 2} | 倍率数组（4 档） | 游戏内速度档位，与第 2 章 `gameSpeed` 集合逐值相同：一帧多跑 tick（加速时向累加器注入虚拟时间） | P1 |

加速功能的正确实现方式是**向累加器注入虚拟时间**而不是缩短 `TICK_MS`：统一写成 `SimLoop.accumulatorMs += deltaMs * (gameSpeed - 1)`。1.5 倍速时为 `+= deltaMs * 0.5`，2 倍速时为 `+= deltaMs * 1`，0.75 倍速时为 `+= deltaMs * (-0.25)`（负值表示抽走时间，等价于降低推进速率）。这样 tick 长度永远是 50 毫秒，回放与存档不受加速影响。**P1**。

速度档位固定为 **{0.75, 1, 1.5, 2}** 四档（与第 2 章 `gameSpeed` 集合完全一致），存档字段 `speedSetting` 直接保存该浮点倍率本身，不保存挡位序号（序号会随档位数量变化，浮点值不会）。

**关于 D17 的强制写法（P0）**。`lightTable` / `heavyTable` 是**只读常量表**，由第 8 章的闭式公式在**载入时一次性构建**（720 个格子的两张表，见「统一 PRNG」之后的「伤害查表常量」小节），构建完成后立即 `Object.freeze`。它们**不是状态、不进存档、不进状态哈希**；读档时按公式重建即可，因此跨版本的存档不会因为表的内存布局不同而失配。伤害结算的唯一合法形式是：

```js
// 正确：查表 + 整数百分比，跨平台逐位一致
// x 为基础伤害（1..120 整数），n 为目标对应维度的护甲等级（0..5）
function resolveDamage(kind, x, n, targetIsChaos, attackerIsPrimordial) {
  var base = (kind === 'light') ? LIGHT_TABLE[x][n] : HEAVY_TABLE[x][n];
  var dmg = base;
  if (attackerIsPrimordial && targetIsChaos) {
    dmg = Math.floor(dmg * 200 / 100);        // 原初对中立伤害 ×2.0，整数百分比
  }
  return dmg < 1 ? 1 : dmg;
}

// 错误：连乘浮点系数，最后一位差异会翻转取整结果
// var dmg = base * 0.6 * 1.15 * 1.4;
```

**关于 D09 的强制写法**。所有「是否在射程内」「是否碰撞」「是否在建造半径内」「混沌是否进入 6 格吞噬范围」的判定必须写成整数平方距离比较：

```js
// 正确：整数平方距离，跨平台逐位一致
// 入参是「微格整数」= Math.round(运行时浮点坐标 * 1000)，不是运行时浮点坐标本身
function inRangeSq(ax1000, ay1000, bx1000, by1000, rangeTiles1000) {
  var dx = ax1000 - bx1000;          // 整数，量纲为千分之一格（微格）
  var dy = ay1000 - by1000;
  var d2 = dx * dx + dy * dy;        // 最大约 1.68e14，远小于 2 的 53 次方，安全
  return d2 <= rangeTiles1000 * rangeTiles1000;
}

// 错误：开方后再比较，最后一位差异可能翻转判定
// return Math.sqrt(dx * dx + dy * dy) <= rangeTiles1000;
```

**关于坐标量化与序列化的统一约定（P0）**：**运行时世界坐标 `x` / `y` 是浮点 `Number`**（量纲：格），但逻辑层每 tick 结束时必须把位置量化到千分之一格：`x = Math.round(x * 1000) / 1000`。所有距离、面积、点积判定都先把坐标转成**微格整数**（`Math.round(v * 1000) | 0`）再做整数运算，禁止在浮点值上直接比较，这样既跨平台逐位一致，又不会随 tick 累积漂移。**仅存档序列化时**才以 ×1000 的整数存储（`Math.round(x * 1000)`），读档时还原为浮点（`v / 1000`）。96×96 地图的序列化取值范围是 0 到 96000；128×128 地图是 0 到 128000。

速度字段的单位是**格每秒**，数值一律以第 8 章权威数据表为准：主宰主战坦克（`dm_mbt`）为 **2.3 格/秒**（第 8 章），折算成每 tick 位移为 `2.3 / 20 = 0.115` 格，即 `115` 微格——因此它的速度在逻辑层写作 `0.115`，在存档中写作 `115`。原初拾荒者（`py_gatherer`）为 2.1 格/秒即 105 微格；侵蚀潜行刺（`er_stalker`）为 3.2 格/秒即 160 微格。微格整数在乘方后最大约 `128000^2 * 2 ≈ 3.3e10`，远低于 2 的 53 次方（约 9.0e15）的安全整数上限，因此所有距离、面积、点积运算在双精度浮点中都是**精确整数运算**，不存在舍入误差。这是本作确定性的物理基础。

#### 16.2.3　统一 PRNG

**P0**。**唯一权威算法是 `mulberry32`（以第 2 章为准）：状态为单个 32 位整数，五条随机流一律使用它。**`mulberry32` 提供**状态快照（snapshot）与恢复（restore）**，因为逻辑流的 RNG 状态必须进存档。

`xorshift128` 在本章**已降级为「P2 可选替代实现」**，不是权威算法，P0 与 P1 不得使用；正文中不再存在第二套「权威」算法。若将来真的切换到别的 PRNG，必须同时满足两条硬性要求：**① 切换算法必须提升存档 `formatVersion`；② 存档必须记录算法标识（`rngStreams[].algo`），读档按标识恢复状态，不允许只靠 `formatVersion` 隐式推断算法。**

`mulberry32` 完整实现：

```js
// ============================================================
// mulberry32：32 位状态 PRNG，周期 2^32，单次调用约 4 纳秒
// 状态可整体序列化为一个 u32，进存档只需 4 字节
// ============================================================

var Mulberry32 = {
  create: function (seed) {
    return { s: seed >>> 0 };
  },

  nextU32: function (st) {
    st.s = (st.s + 0x6D2B79F5) >>> 0;
    var t = st.s;
    t = Math.imul(t ^ (t >>> 15), t | 1);
    t = (t ^ (t + Math.imul(t ^ (t >>> 7), t | 61))) >>> 0;
    return (t ^ (t >>> 14)) >>> 0;
  },

  nextFloat: function (st) {
    return this.nextU32(st) / 4294967296;
  },

  // 返回 0 到 n-1 的整数。存在极轻微模偏差（n 不整除 2^32 时），
  // 对游戏平衡无影响且完全确定，故不采用拒绝采样
  nextInt: function (st, n) {
    if (n <= 0) { return 0; }
    return this.nextU32(st) % n;
  },

  // 返回 lo 到 hi 闭区间整数
  nextRange: function (st, lo, hi) {
    if (hi <= lo) { return lo; }
    return lo + this.nextInt(st, hi - lo + 1);
  },

  // 千分比概率判定：permille 为 0 到 1000 的整数
  nextChance: function (st, permille) {
    return (this.nextU32(st) % 1000) < permille;
  },

  snapshot: function (st) {
    return st.s >>> 0;
  },

  restore: function (s) {
    return { s: s >>> 0 };
  }
};
```

**P2 可选替代实现（不是权威算法）**：`xorshift128` 的完整实现如下，仅供 P2 评估「更长周期」时参考；P0/P1 一律使用 `mulberry32`。它的种子扩展使用 `splitmix32`，避免当用户种子为 0 或低位稀疏时 4 个状态字同时为 0 导致输出恒为 0 的退化。**启用它必须递增 `formatVersion` 并在存档中记录 `algo = 1` 标识。**

```js
// ============================================================
// splitmix32：把单个 32 位种子扩展成高质量状态字
// 同时用于从主种子派生各随机流的子种子
// ============================================================

function splitmix32(x) {
  x = (x + 0x9E3779B9) >>> 0;
  var z = x;
  z = Math.imul(z ^ (z >>> 16), 0x21F0AAAD) >>> 0;
  z = Math.imul(z ^ (z >>> 15), 0x735A2D97) >>> 0;
  return (z ^ (z >>> 15)) >>> 0;
}

// ============================================================
// xorshift128：128 位状态 PRNG，周期 2^128 - 1
// 状态为四个 u32，进存档 16 字节
// ============================================================

var XorShift128 = {
  create: function (seed) {
    var x = seed >>> 0;
    var w0, w1, w2, w3;
    x = splitmix32(x); w0 = x;
    x = splitmix32(x); w1 = x;
    x = splitmix32(x); w2 = x;
    x = splitmix32(x); w3 = x;
    // 退化保护：四字全零则注入非零常量
    if (((w0 | w1 | w2 | w3) >>> 0) === 0) { w0 = 0x1BADB002; }
    return { a: w0, b: w1, c: w2, d: w3 };
  },

  nextU32: function (st) {
    var t = (st.a ^ (st.a << 11)) >>> 0;
    st.a = st.b;
    st.b = st.c;
    st.c = st.d;
    st.d = (((st.d ^ (st.d >>> 19)) ^ (t ^ (t >>> 8))) >>> 0);
    return st.d;
  },

  nextFloat: function (st) {
    return this.nextU32(st) / 4294967296;
  },

  nextInt: function (st, n) {
    if (n <= 0) { return 0; }
    return this.nextU32(st) % n;
  },

  nextRange: function (st, lo, hi) {
    if (hi <= lo) { return lo; }
    return lo + this.nextInt(st, hi - lo + 1);
  },

  nextChance: function (st, permille) {
    return (this.nextU32(st) % 1000) < permille;
  },

  snapshot: function (st) {
    return [st.a >>> 0, st.b >>> 0, st.c >>> 0, st.d >>> 0];
  },

  restore: function (arr) {
    return { a: arr[0] >>> 0, b: arr[1] >>> 0, c: arr[2] >>> 0, d: arr[3] >>> 0 };
  }
};
```

| 对比项 | mulberry32（权威，唯一可用） | xorshift128（P2 备选） | 本项目用法 |
| --- | --- | --- | --- |

| 周期 | 约 2 的 32 次方（43 亿） | 2 的 128 次方减 1 | 单局取数远小于 2 的 32 次方，够用 |

**伤害查表常量（P0，只读，不进哈希、不进存档）**。第 8 章要求「运行时禁止进行公式运算，必须查预计算表」。两张表在**载入时构建一次**并冻结，之后全程只读：

```js
// ============================================================
// lightTable / heavyTable：第 8 章伤害公式的预计算查表（P0）
// 维度：[基础伤害 x: 1..120][护甲等级 n: 0..5] -> 整数伤害
// 只读常量：不是状态、不进存档、不进状态哈希；读档时按公式重建
// ============================================================

var LIGHT_TABLE = buildLightTable();
var HEAVY_TABLE = buildHeavyTable();
var FACTORIAL = [1, 1, 2, 6, 24, 120];   // 0!..5!

function buildLightTable() {
  // 轻型公式：max( min(6 - n, x), x * (1 - 0.1n) - n )，向下取整、最小 1
  var t = [];
  for (var x = 0; x <= 120; x++) {
    var row = new Int32Array(6);
    for (var n = 0; n <= 5; n++) {
      var v = Math.max(Math.min(6 - n, x), x * (1 - 0.1 * n) - n);
      v = Math.floor(v);
      row[n] = v < 1 ? 1 : v;
    }
    t.push(row);
  }
  return Object.freeze(t);
}

function buildHeavyTable() {
  // 重型公式：n = 0 时取 x；n >= 1 时取 x * 5 / (5 + n!)，向下取整、最小 1
  var t = [];
  for (var x = 0; x <= 120; x++) {
    var row = new Int32Array(6);
    for (var n = 0; n <= 5; n++) {
      var v = (n === 0) ? x : (x * 5 / (5 + FACTORIAL[n]));
      v = Math.floor(v);
      row[n] = v < 1 ? 1 : v;
    }
    t.push(row);
  }
  return Object.freeze(t);
}

// 表构建自检：两张表必须各覆盖 121 行 × 6 档（x = 0 为占位行，有效区间 x ∈ [1,120] 共 720 格）
function assertDamageTables() {
  if (LIGHT_TABLE.length !== 121 || HEAVY_TABLE.length !== 121) {
    throw new Error('E_DMG_TABLE_SIZE: 伤害查表必须是 121 行（x = 0..120）');
  }
  for (var x = 0; x <= 120; x++) {
    if (LIGHT_TABLE[x].length !== 6 || HEAVY_TABLE[x].length !== 6) {
      throw new Error('E_DMG_TABLE_ARMOR: 第 ' + x + ' 行的护甲档数必须为 6');
    }
  }
  // 第 8 章节选值的冻结断言（任一处不符即为交付失败）
  if (LIGHT_TABLE[20][2] !== 14 || LIGHT_TABLE[100][4] !== 56) { throw new Error('E_DMG_TABLE_LIGHT'); }
  if (HEAVY_TABLE[10][3] !== 4 || HEAVY_TABLE[120][5] !== 4) { throw new Error('E_DMG_TABLE_HEAVY'); }
}
```

#### 16.2.4　随机流的分流

**P0**。**这是本章最重要的工程约束**：把随机性拆成多条**互相独立**的流，每条流有独立的种子和独立的状态字。原因非常具体——假如全游戏共用一条流，那么「玩家在 tick 5000 造了一台主战坦克触发了 3 次建造音效随机取数」就会把这之后**所有**战斗命中判定整体平移，导致「同一个存档 + 同一串命令」却产生不同战果，回放彻底失效。分流把随机性**局部化**：表现层对流取数多少次，都不影响逻辑流。

| 流 ID | 流名 | 用途 | 消费者 | 是否进状态哈希 | 是否进存档与回放校验 | 算法 |
| --- | --- | --- | --- | --- | --- | --- |
| 0 | map | 地形生成、源质矿脉与晶簇分布、出生点选择、混沌巢穴位置、装饰物 | 地图生成器 | 是 | 是 | mulberry32 |
| 1 | combat | 命中判定、溅射偏移、暴击抑制、解放目标枚举顺序 | 武器系统 | 是 | 是 | mulberry32 |
| 2 | ai | AI 建造顺序扰动、侦察目标选择、进攻波次配比、混沌守护单位游走、奴隶采矿路径择点 | AI 系统与奴役单位预设 AI | 是 | 是 | mulberry32 |
| 3 | fx | 粒子角度、孢子云扩散、爆炸抖动、护盾涟漪 | 渲染与音效 | 否 | 否 | mulberry32 |
| 4 | ambient | 语音播报变体、单位闲谈、毒瘴气泡音 | 音频系统 | 否 | 否 | mulberry32 |

**五条流与「三逻辑 / 两表现」的分工（P0，与第 2 章逐条一致）**：`World.rng` 恒为**五条流** `map` / `combat` / `ai` / `fx` / `ambient`；其中**只有 `map` / `combat` / `ai` 参与状态哈希与存档**，`fx` / `ambient` 是**纯表现流**，既不进状态哈希，也不写入存档（读档时按主种子重新初始化，其取数序列是否与上一局一致不影响任何逻辑结果）。因此存档中的 `rngStreams` 数组**长度恒为 3**，且必须按 `id` 升序遍历。

**奴隶与混沌为什么消费 `ai` 流（P0）**：奴役单位（`dm_slave`）与混沌单位（`ch_*`）都不接受玩家指令，它们的行为完全由预设 AI 决定。若把它们放进 `combat` 流，则「玩家多造一个单位触发的命中判定」会平移奴隶的采矿路径；若放进 `fx` 流，则它们的行为会因为「关掉粒子效果」而改变。因此**全部非玩家控制单位的行为随机必须走 `ai` 流**，这是「同一存档读入两次、跑 600 tick 后残骸与混沌巢穴状态哈希相同」这一验收项的前提。

**种子派生规则（P0，统一写法 `seed ^ 常量`）**：`streamSeed = (masterSeed ^ 常量) >>> 0`，常量以第 2 章为准，逐位不得改动：

| 流 | 常量 |
| --- | --- |
| map | `0x9E3779B9` |
| combat | `0x85EBCA6B` |
| ai | `0xC2B2AE35` |
| fx | `0x27D4EB2F` |
| ambient | `0x165667B1` |

```js
// ============================================================
// RngStreams：随机流管理器（P0）
// 唯一权威算法：mulberry32（第 2 章定义）
// 主种子按 `seed ^ 常量` 派生各流子种子，流之间永不交叉
// ============================================================

var STREAM_MAP = 0;
var STREAM_COMBAT = 1;
var STREAM_AI = 2;
var STREAM_FX = 3;
var STREAM_AMBIENT = 4;
var STREAM_COUNT = 5;

// 五条流的种子派生常量（与第 2 章逐位相同，不得改动）
var STREAM_SEED_XOR = [
  0x9E3779B9,   // map
  0x85EBCA6B,   // combat
  0xC2B2AE35,   // ai
  0x27D4EB2F,   // fx
  0x165667B1    // ambient
];

// 逻辑流集合：只有这三条流参与状态哈希、存档与回放校验
var LOGICAL_STREAMS = [STREAM_MAP, STREAM_COMBAT, STREAM_AI];

// 唯一合法的算法标识（P0）
var RNG_ALGO_MULBERRY32 = 0;

function deriveStreamSeed(masterSeed, streamId) {
  return ((masterSeed >>> 0) ^ STREAM_SEED_XOR[streamId]) >>> 0;
}

function RngStreams(masterSeed) {
  this.masterSeed = masterSeed >>> 0;
  this.states = new Array(STREAM_COUNT);
  this.counters = new Uint32Array(STREAM_COUNT);
  this.algo = new Uint8Array(STREAM_COUNT);
  this.resetAllStreams();
}

// 五条流全部用 mulberry32 初始化（fx / ambient 也在此初始化，只是不进存档）
RngStreams.prototype.resetAllStreams = function () {
  for (var i = 0; i < STREAM_COUNT; i++) {
    this.states[i] = Mulberry32.create(deriveStreamSeed(this.masterSeed, i));
    this.counters[i] = 0;
    this.algo[i] = RNG_ALGO_MULBERRY32;
  }
};

RngStreams.prototype.u32 = function (streamId) {
  this.counters[streamId] = (this.counters[streamId] + 1) >>> 0;
  return Mulberry32.nextU32(this.states[streamId]);
};

RngStreams.prototype.int = function (streamId, n) {
  if (n <= 0) { return 0; }
  return this.u32(streamId) % n;
};

RngStreams.prototype.range = function (streamId, lo, hi) {
  if (hi <= lo) { return lo; }
  return lo + this.int(streamId, hi - lo + 1);
};

RngStreams.prototype.chance = function (streamId, permille) {
  return (this.u32(streamId) % 1000) < permille;
};

// 存档用：只序列化三条逻辑流（长度恒为 3），每条都带算法标识
RngStreams.prototype.serialize = function () {
  var out = [];
  for (var k = 0; k < LOGICAL_STREAMS.length; k++) {
    var i = LOGICAL_STREAMS[k];
    out.push({
      id: i,
      algo: this.algo[i],
      state: Mulberry32.snapshot(this.states[i]),
      count: this.counters[i]
    });
  }
  return out;
};

// 读档：先按主种子重建全部五条流，再用存档记录覆盖三条逻辑流
RngStreams.prototype.deserialize = function (arr) {
  this.resetAllStreams();
  for (var k = 0; k < arr.length; k++) {
    var rec = arr[k];
    if (rec.algo !== RNG_ALGO_MULBERRY32) {
      throw new Error('E_SAVE_RNG_ALGO: 存档记录了未知 PRNG 算法标识 ' + rec.algo);
    }
    if (LOGICAL_STREAMS.indexOf(rec.id) < 0) {
      throw new Error('E_SAVE_RNG_STREAM: 存档包含非逻辑流 id ' + rec.id);
    }
    this.algo[rec.id] = rec.algo;
    this.counters[rec.id] = rec.count >>> 0;
    this.states[rec.id] = Mulberry32.restore(rec.state);
  }
};

// 逻辑流状态指纹：进状态哈希（fx / ambient 不参与）
RngStreams.prototype.logicalFingerprint = function (hash) {
  for (var k = 0; k < LOGICAL_STREAMS.length; k++) {
    var i = LOGICAL_STREAMS[k];
    hash = hashU32(hash, i);
    hash = hashU32(hash, this.counters[i]);
    hash = hashU32(hash, Mulberry32.snapshot(this.states[i]));
  }
  return hash >>> 0;
};
```

#### 16.2.5　确定性自检：回放校验机制

**P0**。确定性缺陷的典型表现是「回放到第 8 分钟突然全场单位乱走」，此时玩家已经打完大半局。因此必须在**实时游玩时就持续自检**，而不是只在回放时才发现。

机制：每 **300 tick（15 秒）**计算一次全量状态哈希，把结果写入**当前存档缓冲**与**回放文件的检查点数组**。回放播放时在同样的 tick 上重新计算并比对；一旦不符，立刻暂停回放、弹出提示、并把不一致的 tick 与两个哈希值写入诊断日志。这样缺陷在**第一次出现的那 15 秒窗口内**就被定位。

**残骸与混沌巢穴是本章新增的两个高风险分组（P0）**：残骸有一个「剩余存在时间（tick）」字段，它每 tick 递减；混沌巢穴有「已刷新单位列表」与「是否已被清空」两个字段，它们在清巢时同时改写。这两组状态如果漏进哈希，就会出现「残骸早已消失但两侧世界仍认为它存在」这类只在长局末端暴露的错位，因此哈希分组 9 与分组 10 是**强制项**。

```js
// ============================================================
// ReplayGuard：确定性自检（P0）
// 每 300 tick 写入一个哈希检查点
// ============================================================

function ReplayGuard() {
  this.checkpoints = [];      // [{ tick, hash }]
  this.failures = [];         // [{ tick, expected, actual }]
  this.lastCheckTick = 0;
  this.verifyMode = false;    // 回放播放时为 true
  this.suspectSystems = null; // 首次不一致时抓取的子系统哈希快照
}

// 实时模式：记录检查点
ReplayGuard.prototype.onTickLive = function (world) {
  if (world.tick - this.lastCheckTick < HASH_INTERVAL) { return; }
  this.lastCheckTick = world.tick;
  var h = computeStateHash(world);
  this.checkpoints.push({ tick: world.tick, hash: h });
};

// 回放模式：比对检查点
ReplayGuard.prototype.onTickReplay = function (world) {
  if (world.tick - this.lastCheckTick < HASH_INTERVAL) { return; }
  this.lastCheckTick = world.tick;
  var expected = this.findCheckpoint(world.tick);
  if (expected === null) { return; }
  var actual = computeStateHash(world);
  if (actual !== expected) {
    // 抓取子系统哈希用于定位（只做一次，避免卡顿）
    if (this.suspectSystems === null) {
      this.suspectSystems = computeSubsystemHashes(world);
    }
    this.failures.push({ tick: world.tick, expected: expected, actual: actual });
    onDeterminismMismatch(world.tick, expected, actual);
  }
};

ReplayGuard.prototype.findCheckpoint = function (tick) {
  for (var i = 0; i < this.checkpoints.length; i++) {
    if (this.checkpoints[i].tick === tick) { return this.checkpoints[i].hash; }
  }
  return null;
};

function hex8(v) {
  var s = (v >>> 0).toString(16);
  while (s.length < 8) { s = '0' + s; }
  return s;
}

function onDeterminismMismatch(tick, expected, actual) {
  Paused = true;
  showDialog('回放校验失败',
    '在第 ' + tick + ' tick（约 ' + (tick / 20).toFixed(1) + ' 秒）检测到状态不一致。\n' +
    '期望哈希 ' + hex8(expected) + '，实际哈希 ' + hex8(actual) + '。\n' +
    '回放已暂停，此存档无法可靠复现。');
}
```

**分系统哈希（P1）**用于快速定位：`computeSubsystemHashes(world)` 返回**八个**子哈希 —— 「单位与建筑」「抛射物与残骸」「经济与电力」「奴役与解放」「混沌巢穴」「老兵与命令队列」「RNG 状态与触发器」「战争迷雾」。八个子哈希的分组必须与「状态哈希」一节的 **14 个分组**逐组对应（同一子哈希可覆盖多组，但不允许出现只在大哈希里、不在任何子哈希里的分组）；不一致时先看哪一个子系统先偏离，可把排查范围从 200 个单位缩小到几十行代码。

### 16.3　状态哈希

**P0**。哈希算法选择 **FNV-1a 32 位**：无需查表之外的额外内存、天然流式、实现不到 20 行、在 200 单位规模下单次全量哈希实测约 **0.4 至 1.4 毫秒**，完全满足 100 毫秒预算。不选 xxhash 是因为它需要 4 个 32 位累加器与更多轮混合，收益（快约 2 倍）在本场景无意义，而代码量翻倍。**P2** 若后期需要更高的碰撞安全性（例如联机反作弊），可平滑升级到 xxhash32 并保留同一套字段顺序定义。

**残骸表的字段（P0，整体进存档与哈希）**：残骸不是实体，而是一张独立的表 `world.corpses`，每项 8 个字段 —— `id`、`x1000`、`y1000`、`originalType`（原始单位类型键名）、`originalTypeHash`、`maxHp`（最大体力）、`baseCost`（初始造价）、`ttlTicks`（剩余存在时间，初始 1200，即 60 秒，每 tick 递减 1，归零即移除）。哈希分组 9 使用其中 7 个数值字段（`originalType` 由 `originalTypeHash` 覆盖）。**残骸表必须整体进存档**：只存哈希不存表会让读档后的侵蚀无法回收、混沌无法吞噬。

**混沌状态表的字段（P0，整体进存档与哈希）**：`world.chaosLairs` 每项 8 个字段 —— `id`、`tileX`、`tileY`、`alive`（巢穴建筑是否存活）、`scalePermille`（数值倍率千分比，0.8 至 1.6 对应 800 至 1600）、`cleared`（是否已被清空）、`spawnedTypes`（已刷新单位类型哈希列表）、`respawnCount`（累计刷新次数，本作恒为 0，因为混沌清空后不再生）。哈希分组 10 使用前 6 项加 `spawnedTypes` 的长度与逐项。

**朝向与进度的表示约定（P0）**：

- **朝向一律 8 向（0..7，0 = 正东，逆时针每 45° 一档）**，与第 2 章、第 3 章、第 20 章附录 C 一致；`facing` 与 `turretFacing` 的存档值必须是 0..7 的整数。若实现内部为了渲染插值使用 256 分度，**256 分度仅为内部角度存储**：写入实体字段、对外接口与存档时一律折算为 8 向，取最近档 `facing8 = Math.round(facing256 / 32) & 7`。
- **`progress` 系列字段一律为 0..1 浮点**（`buildProgress`、`productionProgress`、`QueueItem.progress` 等）。UI 显示时 ×100 取整再加百分号。哈希与存档写入量化值 `Math.round(progress * 1000)`（0..1000 整数），保证进位边界唯一。字段名带 `Permille` 的字段（`scalePermille`、`stealthCharge` 等）例外，它们本身就是 0..1000 的千分比整数。

```js
// ============================================================
// FNV-1a 32 位哈希基元与全量状态哈希（P0）
// ============================================================

var FNV_OFFSET = 0x811C9DC5;
var FNV_PRIME = 0x01000193;
var HASH_SALT = 0x4F4E454C;   // 'ONEL'

function fnv1aInit() {
  return HASH_SALT >>> 0;
}

// 逐字节混合一个 u32（小端序固定，与平台无关）
function hashU32(h, v) {
  v = v >>> 0;
  h = Math.imul(h ^ (v & 0xFF), FNV_PRIME) >>> 0;
  h = Math.imul(h ^ ((v >>> 8) & 0xFF), FNV_PRIME) >>> 0;
  h = Math.imul(h ^ ((v >>> 16) & 0xFF), FNV_PRIME) >>> 0;
  h = Math.imul(h ^ ((v >>> 24) & 0xFF), FNV_PRIME) >>> 0;
  return h >>> 0;
}

// 有符号整数安全哈希：转成 u32 位模式
function hashI32(h, v) {
  return hashU32(h, v | 0);
}

// 字符串哈希：按 UTF-16 码元低 8 位逐字节
function hashStr(h, s) {
  for (var i = 0; i < s.length; i++) {
    h = Math.imul(h ^ (s.charCodeAt(i) & 0xFF), FNV_PRIME) >>> 0;
    h = Math.imul(h ^ ((s.charCodeAt(i) >>> 8) & 0xFF), FNV_PRIME) >>> 0;
  }
  return h >>> 0;
}

// 终末雪崩：把低位差异扩散到全字，降低碰撞率
function hashFinalize(h) {
  h = (h ^ (h >>> 16)) >>> 0;
  h = Math.imul(h, 0x85EBCA6B) >>> 0;
  h = (h ^ (h >>> 13)) >>> 0;
  h = Math.imul(h, 0xC2B2AE35) >>> 0;
  h = (h ^ (h >>> 16)) >>> 0;
  return h >>> 0;
}

// 类型名到类型哈希的缓存表：避免每次哈希都做字符串运算
var TYPE_HASH_CACHE = Object.create(null);
function typeHash(typeName) {
  var v = TYPE_HASH_CACHE[typeName];
  if (v === undefined) {
    v = hashStr(FNV_OFFSET, typeName);
    TYPE_HASH_CACHE[typeName] = v;
  }
  return v;
}

// 0..1 浮点进度 -> 0..1000 量化值（哈希与存档统一用它）
function quantizeProgress(p) {
  if (typeof p !== 'number' || p <= 0) { return 0; }
  if (p >= 1) { return 1000; }
  return Math.round(p * 1000);
}

// 单位命令队列（最多 8 项）逐项哈希
function hashOrderQueue(h, queue) {
  var q = queue || [];
  var n = q.length > 8 ? 8 : q.length;
  h = hashU32(h, n);
  for (var i = 0; i < n; i++) {
    h = hashU32(h, q[i].kind);
    h = hashI32(h, Math.round(q[i].x * 1000) | 0);
    h = hashI32(h, Math.round(q[i].y * 1000) | 0);
    h = hashU32(h, q[i].targetId || 0);
    h = hashU32(h, q[i].queued ? 1 : 0);
  }
  return h >>> 0;
}

// 建筑生产队列（最多 9 项）逐项哈希
function hashProductionQueue(h, queue) {
  var q = queue || [];
  var n = q.length > 9 ? 9 : q.length;
  h = hashU32(h, n);
  for (var i = 0; i < n; i++) {
    h = hashU32(h, typeHash(q[i].type));
    h = hashU32(h, quantizeProgress(q[i].progress));
    h = hashU32(h, q[i].paused ? 1 : 0);
  }
  return h >>> 0;
}

// 混沌巢穴已刷新单位列表逐项哈希
function hashSpawnedTypes(h, list) {
  var a = list || [];
  h = hashU32(h, a.length);
  for (var i = 0; i < a.length; i++) {
    h = hashU32(h, a[i] >>> 0);
  }
  return h >>> 0;
}

function computeStateHash(world) {
  var h = fnv1aInit();

  // 2 时间与 3 模式
  h = hashU32(h, world.tick);
  h = hashU32(h, world.gameMode);
  h = hashU32(h, world.victoryState);
  h = hashU32(h, world.difficulty);

  // 4 分配器
  h = hashU32(h, world.nextEntityId);
  h = hashU32(h, world.nextProjectileId);
  h = hashU32(h, world.nextCorpseId);

  // 5 玩家：按 id 升序（数组本身即按 id 建立，不依赖对象键顺序）
  var players = world.players;
  h = hashU32(h, players.length);
  for (var p = 0; p < players.length; p++) {
    var pl = players[p];
    h = hashU32(h, pl.id);
    h = hashStr(h, pl.faction);            // 'PRIMORDIAL' / 'DOMINATOR' / 'EROSION' / 'CHAOS'
    h = hashU32(h, pl.essence);
    h = hashU32(h, pl.powerProduced);
    h = hashU32(h, pl.powerUsed);
    h = hashU32(h, pl.techMask);
    h = hashU32(h, pl.unlockedByDestroyMask);
    h = hashU32(h, pl.isAI ? 1 : 0);
    h = hashU32(h, pl.aiDifficulty);
    h = hashU32(h, pl.defeated ? 1 : 0);
    h = hashU32(h, pl.radarOnline ? 1 : 0);
    h = hashU32(h, pl.lowPowerTicks);
    h = hashU32(h, pl.startPosition);
    h = hashU32(h, pl.liberationCount);
    h = hashU32(h, pl.salvageEssence);
    h = hashU32(h, pl.devourTotal);
    h = hashU32(h, pl.collapseTick);
    var bq = pl.buildQueue || [];
    h = hashU32(h, bq.length > 6 ? 6 : bq.length);
    for (var bi = 0; bi < bq.length && bi < 6; bi++) {
      h = hashU32(h, typeHash(bq[bi].type));
      h = hashU32(h, quantizeProgress(bq[bi].progress));
      h = hashU32(h, bq[bi].paused ? 1 : 0);
      h = hashU32(h, bq[bi].cost);
    }
    h = hashI32(h, pl.rallyPointX);
    h = hashI32(h, pl.rallyPointY);
  }

  // 6 单位：必须先按 id 升序排序，排序使用显式数值比较器
  var units = world.units;
  var unitIds = world.unitIdsScratch;   // 复用的 Uint32Array，避免每 300 tick 分配内存
  unitIds.length = units.length;
  for (var u = 0; u < units.length; u++) { unitIds[u] = units[u].id; }
  var order = world.unitOrderScratch;
  order.length = units.length;
  for (var q = 0; q < order.length; q++) { order[q] = q; }
  order.sort(function (a, b) { return unitIds[a] - unitIds[b]; });

  h = hashU32(h, units.length);
  for (var k = 0; k < order.length; k++) {
    var e = units[order[k]];
    // 基础 14 个字段
    h = hashU32(h, e.id);
    h = hashU32(h, typeHash(e.type));
    h = hashU32(h, e.owner);
    h = hashI32(h, Math.round(e.x * 1000) | 0);
    h = hashI32(h, Math.round(e.y * 1000) | 0);
    h = hashU32(h, e.hp);
    h = hashU32(h, e.facing & 7);              // 8 向，0..7
    h = hashU32(h, e.turretFacing & 7);        // 8 向，0..7
    h = hashU32(h, e.veterancy);
    h = hashStr(h, e.stance);                  // 'Aggressive' 等字符串
    h = hashU32(h, e.targetId);
    h = hashU32(h, e.coolDown);
    h = hashU32(h, e.orderKind);
    h = hashU32(h, e.flags);
    // 扩展 22 个字段（N = 22）
    h = hashU32(h, e.xp);
    h = hashU32(h, e.kills);
    h = hashOrderQueue(h, e.orderQueue);
    h = hashU32(h, e.cargo);                   // 携带源质 0..240
    h = hashU32(h, e.shield);                  // 主宰护盾当前值
    h = hashU32(h, e.shieldMax);               // 主宰护盾上限
    h = hashU32(h, e.stealthCharge);           // 潜行刺隐形计时 0..1000
    h = hashU32(h, e.burrowState);             // 钻地状态 0..3
    h = hashU32(h, e.devourCount);             // 吞噬次数 0..3
    h = hashU32(h, e.isSlave ? 1 : 0);         // 是否奴役单位
    h = hashU32(h, e.liberatedFrom);           // 被解放来源
    h = hashU32(h, e.controlNodeId);           // 所属奴役控制节点
    h = hashU32(h, e.isOnOre ? 1 : 0);
    h = hashI32(h, Math.round(e.moveTargetX * 1000) | 0);
    h = hashI32(h, Math.round(e.moveTargetY * 1000) | 0);
    h = hashU32(h, e.pathIndex);
    var nodes = e.pathNodes || [];
    h = hashU32(h, nodes.length > 64 ? 64 : nodes.length);
    for (var pn = 0; pn < nodes.length && pn < 64; pn++) {
      h = hashU32(h, nodes[pn] | 0);
    }
    h = hashU32(h, e.groupId);
    h = hashU32(h, e.lastAttackerId || 0);
    h = hashU32(h, e.lastHitTick || 0);
    h = hashStr(h, e.state);                   // UnitState 字符串枚举
    h = hashU32(h, e.spawnTick);
  }

  // 7 建筑
  var buildings = world.buildings;
  var bIds = world.bldIdsScratch;
  bIds.length = buildings.length;
  for (var b = 0; b < buildings.length; b++) { bIds[b] = buildings[b].id; }
  var bOrder = world.bldOrderScratch;
  bOrder.length = buildings.length;
  for (var b2 = 0; b2 < bOrder.length; b2++) { bOrder[b2] = b2; }
  bOrder.sort(function (a, b) { return bIds[a] - bIds[b]; });

  h = hashU32(h, buildings.length);
  for (var m = 0; m < bOrder.length; m++) {
    var g = buildings[bOrder[m]];
    // 基础 11 个字段
    h = hashU32(h, g.id);
    h = hashU32(h, typeHash(g.type));
    h = hashU32(h, g.owner);
    h = hashU32(h, g.tileX);
    h = hashU32(h, g.tileY);
    h = hashU32(h, g.hp);
    h = hashU32(h, quantizeProgress(g.buildProgress));
    h = hashU32(h, g.powered ? 1 : 0);
    h = hashU32(h, g.productionType ? typeHash(g.productionType) : 0);
    h = hashU32(h, quantizeProgress(g.productionProgress));
    h = hashU32(h, g.flags);
    // 扩展 9 个字段（M = 9）
    h = hashU32(h, g.isBlueprint ? 1 : 0);
    h = hashProductionQueue(h, g.productionQueue);
    h = hashI32(h, g.rallyPointX);
    h = hashI32(h, g.rallyPointY);
    h = hashU32(h, g.selling ? 1 : 0);
    h = hashU32(h, g.repairHp);
    h = hashI32(h, g.powerOut);                // 电力产出（仅主宰反应堆为 32）
    h = hashI32(h, g.powerUse);                // 电力占用（仅主宰为负值）
    h = hashU32(h, g.salvageValue);            // 回收返还基数
  }

  // 8 抛射物
  var projs = world.projectiles;
  h = hashU32(h, projs.length);
  for (var i = 0; i < projs.length; i++) {
    var pr = projs[i];
    h = hashU32(h, pr.id);
    h = hashU32(h, typeHash(pr.type));
    h = hashI32(h, Math.round(pr.x * 1000) | 0);
    h = hashI32(h, Math.round(pr.y * 1000) | 0);
    h = hashU32(h, pr.owner);
    h = hashU32(h, pr.damage);
    h = hashU32(h, pr.ttl);
  }

  // 9 残骸（新增且强制）：位置、原始类型、最大体力、初始造价、剩余存在时间
  var corpses = world.corpses;
  var cIds = world.corpseIdsScratch;
  cIds.length = corpses.length;
  for (var c = 0; c < corpses.length; c++) { cIds[c] = corpses[c].id; }
  var cOrder = world.corpseOrderScratch;
  cOrder.length = corpses.length;
  for (var c2 = 0; c2 < cOrder.length; c2++) { cOrder[c2] = c2; }
  cOrder.sort(function (a, b) { return cIds[a] - cIds[b]; });

  h = hashU32(h, corpses.length);
  for (var ci = 0; ci < cOrder.length; ci++) {
    var cp = corpses[cOrder[ci]];
    h = hashU32(h, cp.id);
    h = hashI32(h, cp.x1000 | 0);
    h = hashI32(h, cp.y1000 | 0);
    h = hashU32(h, cp.originalTypeHash);
    h = hashU32(h, cp.maxHp);
    h = hashU32(h, cp.baseCost);
    h = hashU32(h, cp.ttlTicks);
  }

  // 10 混沌巢穴（新增且强制）：存活、倍率、已刷新列表、是否已清空
  var lairs = world.chaosLairs;
  h = hashU32(h, lairs.length);
  for (var li = 0; li < lairs.length; li++) {
    var lr = lairs[li];
    h = hashU32(h, lr.id);
    h = hashU32(h, lr.tileX);
    h = hashU32(h, lr.tileY);
    h = hashU32(h, lr.alive ? 1 : 0);
    h = hashU32(h, lr.scalePermille);          // 800..1600
    h = hashU32(h, lr.cleared ? 1 : 0);
    h = hashSpawnedTypes(h, lr.spawnedTypes);
  }

  // 11 RNG 逻辑流（仅 map / combat / ai）
  h = world.rng.logicalFingerprint(h);

  // 12 触发器
  var trg = world.triggers;
  h = hashU32(h, trg.length);
  for (var t = 0; t < trg.length; t++) {
    h = hashU32(h, trg[t].id);
    h = hashU32(h, trg[t].state);
    h = hashU32(h, trg[t].fireCount);
    h = hashU32(h, trg[t].timerTick);
  }

  // 13 战争迷雾：增量维护的位图滚动哈希 + 已探索格计数
  for (var f = 0; f < players.length; f++) {
    h = hashU32(h, world.fogStateHash[players[f].id] | 0);
    h = hashU32(h, world.fogExploredCount[players[f].id] | 0);
  }

  return hashFinalize(h);
}
```

**哈希使用规则（P0）**：

- 状态哈希**必须**在每个 300 tick 的边界上计算，且计算过程**禁止**修改任何世界状态（`computeStateHash` 必须是纯读函数，`unitOrderScratch`、`bldOrderScratch`、`corpseOrderScratch` 是预分配的可复用缓冲区，不属于逻辑状态）。
- 排序使用 `order.sort(function (a, b) { return unitIds[a] - unitIds[b]; })` 这种**索引排序**而不是对实体对象排序，因为实体对象上挂着大量属性，直接排序会破坏对象数组的物理顺序并让后续逻辑的遍历顺序也变化——那样确实仍然确定，但会让调试变困难。
- 哈希值在前端以 8 位小写十六进制字符串显示（例如 `a3f19b02`），便于人工比对。
- **`lightTable` / `heavyTable` 禁止进哈希**：它们是只读常量，把它们混进哈希会让「换一台机器重新构建表时的内存布局差异」变成假的确定性缺陷，从而掩盖真正的 bug。
- **P1**：在开发者模式下按 `F9` 立刻打印当前 tick 与哈希，用于手工比对两台机器。

### 16.4　存档格式规格

#### 16.4.1　顶层 JSON 结构

存档在磁盘上是**一个压缩后的字节串**，解压后是一个 JSON 文本。JSON 的顶层对象结构如下（字段的完整清单见后续表格）。

```text
SaveGame (JSON, UTF-8)
├── 头部元数据：magic, formatVersion, gameVersion, contentHash, payloadCRC32
├── 时间与身份：savedAtTick, savedAtEpochMs, saveName, slotKind
├── 地图：mapSeed, mapWidth, mapHeight, terrainBase, terrainDiff, terrainDiffCount
├── 世界：tickIndex, gameMode, difficulty, victoryState, elapsedTicks
├── 分配器：nextEntityId, nextProjectileId, nextCorpseId
├── 玩家：players[]（含经济、电力、科技、腐蚀掠夺解锁、建造队列、集结点）
├── 实体：units[], buildings[], projectiles[]
├── 残骸：corpseCount, corpses[]（位置、原始单位类型、最大体力、初始造价、剩余存在时间）
├── 混沌：chaosLairCount, chaosLairs[]（存活、倍率、已刷新单位列表、是否已清空）
├── AI：aiStates[]
├── 触发器：triggers[]
├── 随机数：rngStreams[]（只含 map / combat / ai 三条逻辑流）
├── 视图：camera{x,y,zoom}, uiSidebarTab, speedSetting, selectionGroups[]
└── 校验：stateHash, hashCheckpoints[]
```

**坐标序列化的强制校验（P0）**：运行时坐标是浮点，**只有序列化时才变成整数**——存档中的 `x`、`y`、`moveTargetX`、`moveTargetY`、`cameraX`、`cameraY`、`rallyPointX`、`rallyPointY`、以及**残骸的 `x` / `y`** 一律是 `Math.round(v * 1000)` 之后的整数（千分之一格）。写入前必须执行该换算，读档时必须校验 `Number.isInteger`，不满足则判定存档损坏；地图范围外的坐标（绝对值大于 `mapWidth * 1000` / `mapHeight * 1000`）同样判定为损坏。**禁止在逻辑层把坐标当作整数存储**，也禁止把「坐标为千分之一格整数」当作运行时约定。

```js
// 运行时浮点坐标 <-> 存档整数坐标 的唯一入口与出口
// 入口：序列化时调用（每 tick 的量化也复用同一换算，保证两处口径一致）
function toWorldInt(tileFloat) {
  return Math.round(tileFloat * 1000) | 0;
}
// 出口：读档时调用，还原为浮点 Number
function fromWorldInt(v) {
  return (v | 0) / 1000;
}
function validateCoord(v, mapSizeTiles) {
  return Number.isInteger(v) && v >= 0 && v <= mapSizeTiles * 1000;
}
// 逻辑层每 tick 结束时的量化（不是序列化，仍然是浮点）
function quantizeCoord(v) {
  return Math.round(v * 1000) / 1000;
}
```

#### 16.4.2　压缩策略

**P0**。链路固定为：**逻辑对象 → `JSON.stringify` → `TextEncoder` 得 `Uint8Array` → 可选 `CompressionStream('deflate-raw')` → base64 → `localStorage.setItem`**。

`CompressionStream` 的 `deflate-raw` 在 Chrome 80+ 与 Edge 80+ 提供；Firefox 113+、Safari 16.4+ 亦提供。必须做能力探测并**优雅降级为不压缩**（`compressed = 0`），因为不压缩的存档（**157480 字节 = 157480 / 1024 ≈ 153.8 KB，即约 154 KB**，见下方体积估算表）依然远低于 512 KB 上限，降级是安全的。本章所有关于存档体积的表述统一使用这一组数字，不再出现第二个口径。

```js
// ============================================================
// 压缩与解压（P0，带能力探测与降级）
// ============================================================

var HAS_COMPRESSION_STREAM = (typeof CompressionStream !== 'undefined' &&
                              typeof DecompressionStream !== 'undefined');

function concatU8(a, b) {
  var out = new Uint8Array(a.length + b.length);
  out.set(a, 0);
  out.set(b, a.length);
  return out;
}

async function readAll(readable) {
  var reader = readable.getReader();
  var chunks = [];
  var total = 0;
  while (true) {
    var r = await reader.read();
    if (r.done) { break; }
    chunks.push(r.value);
    total += r.value.length;
  }
  var out = new Uint8Array(total);
  var off = 0;
  for (var i = 0; i < chunks.length; i++) {
    out.set(chunks[i], off);
    off += chunks[i].length;
  }
  return out;
}

async function compressBytes(u8) {
  if (!HAS_COMPRESSION_STREAM) {
    return { data: u8, algo: 'none' };
  }
  try {
    var cs = new CompressionStream('deflate-raw');
    var writer = cs.writable.getWriter();
    writer.write(u8);
    writer.close();
    var out = await readAll(cs.readable);
    // 压缩无效时保留原数据，避免小存档反而变大
    if (out.length >= u8.length) {
      return { data: u8, algo: 'none' };
    }
    return { data: out, algo: 'deflate-raw' };
  } catch (err) {
    return { data: u8, algo: 'none' };
  }
}

async function decompressBytes(u8, algo) {
  if (algo === 'none') { return u8; }
  var ds = new DecompressionStream('deflate-raw');
  var writer = ds.writable.getWriter();
  writer.write(u8);
  writer.close();
  return await readAll(ds.readable);
}
```

| 情形 | 检测方式 | 处理策略 | 玩家可见反馈 | 优先级 |
| --- | --- | --- | --- | --- |
| 单槽写入抛 QuotaExceededError | try catch 捕获 name 为 QuotaExceededError | 依次删除最旧的 auto5 到 auto1，重试最多 3 次 | 提示「自动存档已轮换旧档」 | P0 |
| 重试仍失败 | 三次重试后仍抛错 | 删除 oneleaf.replay.recent 后重试一次 | 提示「已清理回放缓存以完成保存」 | P0 |
| 仍然失败 | 最终失败 | 改为下载 `.oleaf` 文件（需 File System Access 或 a 标签下载） | 提示「浏览器存储已满，已改为导出文件」 | P1 |
| 无 File System Access 且存储满 | 能力探测 | 标记本局不再自动存档，仅允许手动导出 | 顶部横幅常驻提示 | P1 |
| 单槽二进制超过 512 KB | 写入前检查 rawByteLength 与压缩后长度 | 拒绝保存并提示玩家 | 提示「存档超出上限，请减少单位数量」 | P0 |
| 槽位索引与实际键不一致 | 读档时枚举键名比对 | 以实际键为准重建索引 | 无 | P1 |

**损坏存档的校验流程（P0）**：读档必须依次通过**六道关卡**，任意一道失败即判定为损坏且**绝不部分应用**（防止半加载状态导致世界错乱）。

| 关卡 | 校验内容 | 失败处理 | 错误码 |
| --- | --- | --- | --- |
| 1 | base64 解码成功且长度大于 32 字节 | 判定损坏，尝试下一个槽 | E_SAVE_B64 |
| 2 | 魔数等于 ONELEAF | 判定为非本游戏数据 | E_SAVE_MAGIC |
| 3 | formatVersion 在支持区间内 | 走版本兼容流程 | E_SAVE_VERSION |
| 4 | payloadCRC32 与解压后字节串一致 | 判定为数据损坏 | E_SAVE_CRC |
| 5 | contentHash 与本机权威数据表一致 | 提示数据表不匹配，可选择强制加载 | E_SAVE_CONTENT |
| 6 | stateHash 与重新计算的世界哈希一致 | 判定为逻辑损坏，拒绝加载 | E_SAVE_HASH |

**残骸与混沌表的额外校验（P0，第七道内联校验）**：在关卡 6 之前，读档必须先按 `corpses` 表重建残骸并做两项断言：其一，每具残骸的 `ttlTicks` 必须落在 0..1200；其二，每具残骸的 `originalType` 必须能在权威单位表中找到。随后按 `chaosLairs` 表重建巢穴并断言：`scalePermille` 必须落在 800..1600，且 `chaosLairCount` 必须等于地图数据 `chaosLairs` 的长度。任一断言失败返回 `E_SAVE_HASH`（与关卡 6 同码，因为这类失败必然导致哈希不一致）。

### 16.5　回放格式规格

#### 16.5.1　回放模型

**P0**。回放等于「**地图主种子 + 初始状态快照 + 每 tick 的玩家命令流 + 哈希检查点**」。回放文件内嵌一份**精简版初始快照**（`SaveGame` 的子集：不含镜头、UI、编队与统计字段，只含地图、玩家初始状态、初始单位与建筑、初始残骸（通常为空）、混沌巢穴状态、RNG 初始状态），因此回放**完全不依赖任何外部地图文件或存档**，是自包含的。

之所以必须内嵌初始快照而不能只存种子，是因为命令式同步要求**双方起点逐位一致**：如果初始快照靠「用种子重新生成」，则地图生成代码的任何微小版本差异都会让回放从一开始就错位。内嵌快照把这一风险降到零，代价仅约 18 KB 压缩后体积（单份 73000 字节未压缩，压缩比约 4.1 比 1，见下方体积估算表）。**混沌巢穴的 `scalePermille` 与守护单位列表必须进初始快照**，因为它们是「越靠近中心越强」这条规则在具体一张图上的落地结果，靠种子重算会把浮点钳制差一点点就变成完全不同的战斗。

#### 16.5.2　命令记录结构

```js
function assertCommandEnumTable() {

    }
  }
}

// 逻辑命令键名 -> 回放枚举值（0..33）

  var v = CMD_KEY_TO_ENUM[cmdKey];
  if (typeof v !== 'number') {
    throw new Error('E_CMD_KEY_UNKNOWN: ' + cmdKey);
  }
  return v;

// 回放枚举 -> 逻辑命令键名；enumName 可传枚举值（0..33）或 'CMD_XXX' 名字

  }

}
```

**跳转的实现细节（P0）**：`seekTo(tick)` 不允许「正向快进模拟」以外的任何捷径，因为反向模拟在 RTS 中不可行（信息已丢失）。正确算法是：找到小于等于目标 tick 的**最近哈希检查点**，把世界恢复到该检查点（检查点本身必须携带一份状态快照，而不仅仅是哈希——因此**P1 建议**每 3000 tick 额外存一份完整快照）。P0 的最小实现是：跳转时从 `initialState` 重新模拟到目标 tick，30 分钟一局最坏情况重放 36000 tick，实测约 2.0 秒（比旧项目略慢，因为每 tick 多维护残骸与巢穴表），可接受但不够顺滑。**P1 必须**加入周期性完整快照，但每 3000 tick 一份完整快照（每份压缩后约 46 KB，12 份约 552 KB）会超出回放 256 KB 上限——因此采用折中：**每 6000 tick 存一份、且只存实体位置血量、残骸表与巢穴表等最小字段的紧凑快照（单份未压缩 40000 字节、压缩后约 13000 字节），30 分钟一局共 5 份（tick 6000 / 12000 / 18000 / 24000 / 30000），合计压缩后约 65 KB**，把最坏重放距离从 36000 tick 压缩到 6000 tick（约 0.33 秒）。

```js
// ============================================================
// 回放播放器（P0 核心：跳转、快进、逐帧）
// ============================================================

function ReplayPlayer(replay) {
  this.replay = replay;
  this.world = null;
  this.cursor = 0;          // commands 数组的下一个待投递索引
  this.tick = 0;
  this.paused = true;
  this.speed = 1;           // 取值只能是 0.75 / 1 / 1.5 / 2
  this.speedAcc = 0;        // 速度产生的小数 tick 余量，只影响播放观感
  this.guard = new ReplayGuard();
  this.guard.checkpoints = replay.checkpoints.slice();
  this.guard.verifyMode = true;
}

// 播放速度档位集合与游戏内速度档完全一致
var REPLAY_SPEEDS = [0.75, 1, 1.5, 2];

ReplayPlayer.prototype.setSpeed = function (multiplier) {
  if (REPLAY_SPEEDS.indexOf(multiplier) < 0) {
    throw new Error('E_REPLAY_SPEED: 非法播放速度 ' + multiplier);
  }
  this.speed = multiplier;
  this.speedAcc = 0;
};

ReplayPlayer.prototype.start = function () {
  this.world = deserializeWorld(this.replay.initialState);
  this.world.rng = new RngStreams(this.replay.mapSeed);
  this.world.rng.deserialize(this.replay.initialState.rngStreams);
  this.cursor = 0;
  this.tick = 0;
  this.speedAcc = 0;
  this.paused = false;
};

// 每渲染帧调用：advanceTicks 是本帧「实时」应推进的 tick 数
// 实际推进数 = advanceTicks * speed，小数部分留到下一帧，保证 0.75 / 1.5 也能精确表达
ReplayPlayer.prototype.step = function (advanceTicks) {
  if (this.paused) { return; }
  this.speedAcc += advanceTicks * this.speed;
  var n = Math.floor(this.speedAcc);
  this.speedAcc -= n;
  for (var i = 0; i < n; i++) {
    if (this.tick >= this.replay.durationTicks) {
      this.paused = true;
      showReplaySummary(this.replay.finalStats, this.guard.failures);
      return;
    }
    this.tick++;
    this.world.tick = this.tick;
    this.applyCommandsForTick(this.tick);
    simulateTick(this.tick);
    this.guard.onTickReplay(this.world);
  }
};

ReplayPlayer.prototype.applyCommandsForTick = function (tick) {
  var cmds = this.replay.commands;
  while (this.cursor < cmds.length && cmds[this.cursor].t <= tick) {
    var cmd = cmds[this.cursor];
    if (cmd.t === tick) {
      executeCommand(this.world, cmd);
    }
    this.cursor++;
  }
};

// 跳转：从初始快照或最近紧凑快照重新模拟到目标 tick
ReplayPlayer.prototype.seekTo = function (targetTick) {
  var snap = pickNearestSnapshot(this.replay, targetTick);
  this.world = deserializeWorld(snap.state);
  this.world.rng.deserialize(snap.rngStreams);
  this.tick = snap.tick;
  this.cursor = lowerBoundCommandIndex(this.replay.commands, snap.tick);
  while (this.tick < targetTick) {
    this.tick++;
    this.world.tick = this.tick;
    this.applyCommandsForTick(this.tick);
    simulateTick(this.tick);
  }
  // 进度条与时间显示
  updateReplayProgress(this.tick, this.replay.durationTicks);
};

function lowerBoundCommandIndex(commands, tick) {
  var lo = 0;
  var hi = commands.length;
  while (lo < hi) {
    var mid = (lo + hi) >>> 1;
    if (commands[mid].t < tick) { lo = mid + 1; } else { hi = mid; }
  }
  return lo;
}
```

#### 16.5.6　命令去重与合并优化

**P0**。命令的产生方式必须是**一批单位一条命令**：`u` 携带整批实体 id（上限 60），而不是每个单位一条。这是体积与正确性的共同前提——一次框选 60 台主战坦克下达移动命令只产生 **1 条**命令，而不是 60 条。在此基础上，**在命令入队前**再做合并，规则如下表。合并必须满足**语义等价**：合并后的命令流重新模拟必须得到与未合并时逐位相同的状态哈希（由 `T16` 覆盖）。

合并判等必须同时比较 **`p`（玩家）、`c`（命令类型）、`q`（是否 Shift 追加）、参数数组 `a` 与单位集合 `u`**。**`u` 必须参与判等**：如果只比较参数而不比较 `u`，那么「A 队去 (10,20)」与「B 队去 (10,20)」这两条针对不同单位的命令会被错误地合并成一条，回放结果直接错位。`u` 在入队前统一按实体 id 升序去重规范化，因此「集合相等」等价于「逐元素相等」。

命令按合并语义分成三类，三类名额必须**恰好覆盖全部 34 个枚举（19 + 7 + 8 = 34）**：

- **UNION（并集，19 个）**：同 tick、同玩家、同 `u` 集合、同参数时归并为一条。
- **OVERRIDE（覆盖，7 个）**：同 tick、同玩家、同类型时**后到者替换前者**（真正的替换，不是并集）；选择类命令与编队设定属于这一类，因为它们表达的就是「当前状态是什么」。
- **不合并（8 个）**：单次性、切换性或必须严格保序的命令。

**合并只作用于「记录尾部紧邻的那一条同 tick 命令」，绝不跨类型回溯合并**。这条约束是为了保证**顺序等价**：如果允许回溯合并，`[SELECT_POINT(A), SELECT_ADD(B), SELECT_POINT(C)]` 会被错误地折成 `[SELECT_POINT(C), SELECT_ADD(B)]`，最终选择变成 `{B, C}` 而不是正确的 `{C}`。只折叠尾部紧邻记录时，「被折叠的命令」与「折叠后的命令」在原序列中的位置相同，因此合并前后逐条应用的结果完全一致。

```js
// 启动自检：34 个枚举必须被三类恰好覆盖一次
function assertMergeSetsCoverAll() {
  for (var i = 0; i < 34; i++) {
    var inUnion = MERGEABLE_UNION[i] === true;
    var inOverride = MERGEABLE_OVERRIDE[i] === true;
    var inNone = CMD_NON_MERGEABLE.indexOf(i) >= 0;
    if ((inUnion ? 1 : 0) + (inOverride ? 1 : 0) + (inNone ? 1 : 0) !== 1) {
      throw new Error('E_CMD_MERGE_TABLE: 枚举 ' + i + ' 的合并归类不唯一或不完整');
    }
  }

// u 规范化：按实体 id 升序去重，保证集合可直接逐元素比较
function normalizeUnitIds(u) {
  var copy = u.slice();
  copy.sort(function (x, y) { return x - y; });
  var out = [];
  for (var i = 0; i < copy.length; i++) {
    if (i === 0 || copy[i] !== copy[i - 1]) { out.push(copy[i]); }
  }
  return out;
}

// 单位集合判等（u 必须参与合并判等，否则不同单位的命令会被错误合并）
function unitsEqualForMerge(a, b) {
  if (a.u.length !== b.u.length) { return false; }
  for (var i = 0; i < a.u.length; i++) {
    if (a.u[i] !== b.u[i]) { return false; }
  }
  return true;
}

// 参数判等；CMD_PRODUCE_UNIT(24) 的 a1 是数量，允许后续累加，故跳过不比较
function argsEqualForMerge(a, b) {
  var n = a.a.length > b.a.length ? a.a.length : b.a.length;
  for (var i = 0; i < n; i++) {
    if (a.c === 24 && i === 1) { continue; }
    if ((a.a[i] || 0) !== (b.a[i] || 0)) { return false; }
  }
  return true;
}

// 合并判等：p、c、q、u（单位集合）与 a 全部必须相等
function commandsEqualForMerge(a, b) {
  if (a.p !== b.p || a.c !== b.c) { return false; }
  if ((a.q ? 1 : 0) !== (b.q ? 1 : 0)) { return false; }
  if (!unitsEqualForMerge(a, b)) { return false; }
  return argsEqualForMerge(a, b);
}

// 覆盖判等：同玩家同类型即可覆盖；CMD_GROUP_SET 还必须同编队号且两侧都是「覆盖式设定」
function overrideMatches(prev, cmd) {
  if (prev.p !== cmd.p || prev.c !== cmd.c) { return false; }
  if (cmd.c === 5) {
    var prevAppend = prev.a[1] || 0;
    var cmdAppend = cmd.a[1] || 0;
    if (prevAppend !== 0 || cmdAppend !== 0) { return false; }   // 追加进编队必须保序
    return (prev.a[0] || 0) === (cmd.a[0] || 0);
  }
  return true;
}

function cloneRecord(cmd) {
  return {
    t: cmd.t,
    p: cmd.p,
    c: cmd.c,
    u: normalizeUnitIds(cmd.u),
    a: cmd.a.slice(),
    q: cmd.q ? 1 : 0
  };
}

function pushCommand(record, cmd) {
  var norm = cloneRecord(cmd);
  if (record.length > 0) {
    var prev = record[record.length - 1];      // 只看尾部紧邻的那一条
    if (prev.t === norm.t) {
      if (MERGEABLE_OVERRIDE[norm.c] === true && overrideMatches(prev, norm)) {
        record[record.length - 1] = norm;      // 覆盖语义：后到者替换，位置不变
        return;
      }
      if (MERGEABLE_UNION[norm.c] === true && commandsEqualForMerge(prev, norm)) {
        if (norm.c === 24) {
          prev.a[1] = (prev.a[1] || 1) + (norm.a[1] || 1);   // 生产数量累加
          return;
        }
        prev.q = norm.q;                       // u 与 a 完全相等，保留一条即可
        return;
      }
    }
  }
  record.push(norm);
}

// 同一 tick 内，同一实体若被同类命令覆盖，删除更早记录中的该实体（保留最后一次）
function dedupeTickForEntity(record, tick, entityId, cmdType) {
  for (var i = record.length - 1; i >= 0; i--) {
    var r = record[i];
    if (r.t !== tick) { continue; }
    if (r.c !== cmdType) { continue; }
    var idx = r.u.indexOf(entityId);
    if (idx >= 0) {
      r.u.splice(idx, 1);
      if (r.u.length === 0) { record.splice(i, 1); }
    }
  }
}
```

#### 16.5.7　回放体积估算

**P0**。基准场景：30 分钟一局（36000 tick）、1v1 人机、一名人类玩家平均每分钟下达约 28 条命令（RTS 中位水平），合计约 840 条；其中约 45 百分比被合并规则吸收，落盘约 460 条。

| 数据分区 | 数量 | 单条未压缩字节 | 未压缩合计 | 压缩后估算 | 说明 |
| --- | --- | --- | --- | --- | --- |
| 头部元数据 | 1 | 220 | 220 | 200 | 短键名 |
| 初始状态快照 | 1 | 73000 | 73000 | 17800 | 精简快照，压缩比约 4.1 比 1；含残骸表与混沌巢穴表 |

| 结算统计 | 1 | 480 | 480 | 300 | 双方各 12 项（id 加 11 项统计） |

| 最坏情况（2 小时对局、双方均为人类、命令密集） | — | — | 约 1000000 | 约 245000 | 仍低于 256 KB 上限 |

### 16.6　自动存档与崩溃恢复

**P0**。自动存档必须做到三件事：**固定节奏**（每 1200 tick 即 60 秒）、**不产生可感知卡顿**（利用 `requestIdleCallback` 在帧间空闲期写入）、**崩溃后可发现**（心跳标记）。

| 机制 | 参数 | 实现要点 | 优先级 |
| --- | --- | --- | --- |
| 自动存档间隔 | 1200 tick（60 秒） | 在 postTickHook 中判断 tick 取模 | P0 |
| 落盘时机 | 空闲回调 | 序列化可在 tick 内完成，压缩与写入放到 idle | P0 |
| 环形槽位 | oneleaf.save.auto1 到 auto5 | 写指针循环，索引记在 oneleaf.save.index | P0 |
| 崩溃恢复槽 | oneleaf.save.autosave | 每次自动存档同时写入该槽 | P0 |
| 心跳标记 | oneleaf.crashflag | 每 5 秒写入当前 tick 与时间戳 | P0 |
| 崩溃判定 | 启动时 crashflag 存在且未正常退出 | 正常退出时删除 crashflag | P0 |
| 恢复提示 | 模态对话框 | 提供「恢复」「查看存档列表」「忽略」三个选项 | P0 |
| 残骸与巢穴的落盘一致性 | 存档必须携带完整 `corpses` 与 `chaosLairs` | 自动存档与手动存档共用同一 `buildSavePayload`，不允许任何一处裁剪这两张表 | P0 |
| 存档时机禁入 | 战斗结算帧 | 胜负结算帧内不触发自动存档，避免状态不一致 | P1 |
| 玩家手动锁定 | 手动槽永不被自动覆盖 | 自动槽与手动槽完全分离 | P0 |
| 存档压缩失败 | 降级为不压缩 | 仍写入，只增加体积 | P0 |
| 存档写入失败 | 连续 3 次失败后停止自动存档 | 顶部横幅提示玩家手动保存 | P1 |

```js
// 自动存档、心跳与崩溃恢复（P0）
// ============================================================

var CRASHFLAG_KEY = 'oneleaf.crashflag';
var AUTOSAVE_KEY = 'oneleaf.save.autosave';
var AUTO_SLOT_COUNT = 5;
var autoSlotCursor = 1;

function postTickHook(tick) {
  // 1 回放检查点
  replayGuard.onTickLive(World);
  // 2 录制本 tick 命令（回放录制在命令入队时已完成）
  // 3 自动存档
  if (tick % AUTOSAVE_INTERVAL === 0) {
    scheduleAutoSave(tick);
  }
  // 4 心跳
  if (tick % 100 === 0) {
    writeHeartbeat(tick);
  }
}

function writeHeartbeat(tick) {
  try {
    localStorage.setItem(CRASHFLAG_KEY, JSON.stringify({
      tick: tick,
      epochMs: Date.now(),
      gameVersion: GAME_VERSION,
      corpseCount: World.corpses.length,          // 便于崩溃后核对残骸表规模
      chaosLairCount: World.chaosLairs.length     // 便于崩溃后核对混沌地域数量
    }));
  } catch (err) {
    // 心跳失败不阻塞游戏
  }
}

function clearHeartbeat() {
  try { localStorage.removeItem(CRASHFLAG_KEY); } catch (err) { }
}

function scheduleAutoSave(tick) {
  var doSave = function () {
    saveGameToSlot('auto' + autoSlotCursor, 'auto').then(function (ok) {
      if (ok) {
        autoSlotCursor = (autoSlotCursor % AUTO_SLOT_COUNT) + 1;
      }
    });
  };
  if (typeof requestIdleCallback === 'function') {
    requestIdleCallback(doSave, { timeout: 2000 });
  } else {
    setTimeout(doSave, 0);
  }
}

// 启动时崩溃检测
function detectCrashAndOfferRecovery() {
  var raw = null;
  try { raw = localStorage.getItem(CRASHFLAG_KEY); } catch (err) { }
  if (raw === null) { return false; }
  var flag = null;
  try { flag = JSON.parse(raw); } catch (err) { flag = null; }
  if (flag === null || typeof flag.tick !== 'number') {
    clearHeartbeat();
    return false;
  }
  var auto = readSlotRaw(AUTOSAVE_KEY);
  if (auto === null) {
    clearHeartbeat();
    return false;
  }
  showRecoveryDialog(flag, auto);
  return true;
}

function showRecoveryDialog(flag, auto) {
  var msg = '检测到上次游戏异常退出。\n' +
            '自动存档时间点：' + (flag.tick / 20).toFixed(0) + ' 秒（tick ' + flag.tick + '）\n' +
            '战场残骸 ' + (flag.corpseCount | 0) + ' 具，混沌区域 ' + (flag.chaosLairCount | 0) + ' 处。\n' +
            '是否恢复到该存档？';
  if (window.confirm(msg)) {
    loadGameFromRaw(auto).then(function (ok) {
      if (ok) { clearHeartbeat(); }
    });
  }
}
```

### 16.7　多机同步预留

**P2**。本节定义接口契约，P0 与 P1 阶段**不实现网络层**，但必须保证「命令流」这一数据结构从第一天起就是网络友好的：所有玩家命令统一走 `pushCommand`，逻辑层永远只从命令流读取输入。这样把本机命令流换成网络命令流就是替换一个数据源，而不是重构游戏。

采用**确定性的 lockstep（锁步）模型**：所有客户端在完全相同的初始状态下，按完全相同的顺序执行完全相同的命令流，因此无需广播状态，只需广播命令。

| 项目 | 参数 | 说明 | 优先级 |
| --- | --- | --- | --- |
| 同步模型 | 确定性 lockstep | 只同步命令，不同步状态 | P2 |
| 输入延迟 | 2 tick（100 毫秒） | 命令在发出后第 2 个 tick 才生效，留出网络往返窗口 | P2 |
| 命令广播 | 每 tick 打包一次 | 空 tick 发送心跳包 | P2 |
| 传输通道 | WebRTC DataChannel 可靠有序 | 单文件场景下用 P2 手动信令 | P2 |
| 卡顿判定 | 某玩家连续 4 tick 未上报 | 显示等待指示，暂停推进 | P2 |
| 掉线处理 | 连续 20 tick（1 秒）无响应 | AI 接管该玩家，命令流改为本地生成 | P2 |
| 重连 | 掉线后 60 秒内 | 服务端（房主）发送精简快照与命令流尾部 | P2 |
| 校验 | 每 300 tick 交换状态哈希 | 不一致则记录并广播校准请求 | P2 |
| 反作弊 | 命令合法性校验 | 每条命令在应用前校验源质、视野、冷却；`fire_superweapon` 在本作中一律判非法 | P2 |
| 与回放复用 | 回放文件即为命令流 | 联机对局结束后直接把命令流存为回放，无需额外格式 | P2 |

**关键复用关系**：回放文件结构中的 `commands` 数组、`initialState` 快照与 `checkpoints`，与 lockstep 网络协议中的「命令包」「开局快照」「校验包」是**同一套数据结构**，只是传输载体不同（localStorage 与 DataChannel）。**P2 实现必须复用 `CommandRecord` 与 `computeStateHash`，不得另建一套**。

**《一叶》在联机下多出的两条约束（P2）**：其一，**混沌巢穴是共享的中立状态**，双方客户端必须从同一份 `initialState.chaosLairs` 出发，任何一方对巢穴的伤害与清空都必须由命令流驱动（混沌自身不产生命令，它的行为由 `ai` 流确定，因此天然一致）；其二，**奴役单位的归属变更（解放）必须只由「控制节点被摧毁」这一逻辑事件触发**，不允许由任何一方的本地表现层决定，否则两台机器会在奴隶归属上分叉。

### 16.8　数据结构定义

**P0**。以下 TypeScript 风格接口是本项目的**权威定义**，实施方必须严格照此命名与类型实现（纯 JavaScript 实现时去掉类型标注，但字段名与语义不得改动）。

**与第 20 章附录 C 的差异声明（P0，本章为权威）**：第 20 章附录 C 的「核心数据结构定义（精简参考版）」在以下六点上与本章不一致，**以本章为准，实施方不得照抄附录 C 的旧写法**：

1. `World.rng` 必须是**五条流** `map` / `combat` / `ai` / `fx` / `ambient`；其中只有前三条进状态哈希与存档。
2. 实体不是单一 `entities` 数组配 `nextId`，而是 `units` / `buildings` / `projectiles` / `corpses` 四个数组，分配器字段名是 `nextEntityId`、`nextProjectileId` 与 `nextCorpseId`。
3. `Faction` 是字符串 `'PRIMORDIAL' | 'DOMINATOR' | 'EROSION' | 'CHAOS'`（不是 `'RED' | 'BLUE'`）；`Stance` 是字符串 `'Aggressive' | 'Defensive' | 'HoldGround' | 'HoldFire'`（不是 `0 | 1 | 2 | 3`）；`progress` 系列一律是 **0..1 浮点**（不是 0..1000）。
4. 运行时坐标是浮点 `Number`，只有存档序列化时才 ×1000 取整。
5. `lightTable` / `heavyTable` 是**只读常量**（`readonly Int32Array[]`），不属于 `World`，不进存档、不进哈希。
6. **残骸表 `corpses` 与混沌状态表 `chaosLairs` 是 `World` 的一等成员**，与 `units` / `buildings` / `projectiles` 平级；把它们塞进 `buildings` 或做成纯表现对象都会让读档后的机制失效。

### 16.9　读写流程与体积保障

**P0**。保存与读取的完整调用链固化如下，实施方不得在链路上插入任何额外的深拷贝或格式转换。

```js
// ============================================================
// 存档读写完整链路（P0）
// ============================================================

var SAVE_FORMAT_VERSION = 1;
var GAME_VERSION = '1.0.3';
var MAX_SAVE_BYTES = 524288;      // 512 KB
var MAX_REPLAY_BYTES = 262144;    // 256 KB

function crc32(u8) {
  if (crc32.table === undefined) {
    var table = new Uint32Array(256);
    for (var n = 0; n < 256; n++) {
      var c = n;
      for (var k = 0; k < 8; k++) {
        c = (c & 1) ? (0xEDB88320 ^ (c >>> 1)) : (c >>> 1);
      }
      table[n] = c >>> 0;
    }
    crc32.table = table;
  }
  var crc = 0xFFFFFFFF;
  for (var i = 0; i < u8.length; i++) {
    crc = (crc32.table[(crc ^ u8[i]) & 0xFF] ^ (crc >>> 8)) >>> 0;
  }
  return (crc ^ 0xFFFFFFFF) >>> 0;
}

function bytesToBase64(u8) {
  var B64 = 'ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789+/';
  var out = '';
  var i = 0;
  for (; i + 2 < u8.length; i += 3) {
    var n = (u8[i] << 16) | (u8[i + 1] << 8) | u8[i + 2];
    out += B64[(n >>> 18) & 63] + B64[(n >>> 12) & 63] +
           B64[(n >>> 6) & 63] + B64[n & 63];
  }
  var rem = u8.length - i;
  if (rem === 1) {
    var a = u8[i] << 16;
    out += B64[(a >>> 18) & 63] + B64[(a >>> 12) & 63] + '==';
  } else if (rem === 2) {
    var b = (u8[i] << 16) | (u8[i + 1] << 8);
    out += B64[(b >>> 18) & 63] + B64[(b >>> 12) & 63] + B64[(b >>> 6) & 63] + '=';
  }
  return out;
}

function base64ToBytes(str) {
  var B64 = 'ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789+/';
  var lut = base64ToBytes.lut;
  if (lut === undefined) {
    lut = new Int16Array(256);
    for (var i = 0; i < 256; i++) { lut[i] = -1; }
    for (var j = 0; j < B64.length; j++) { lut[B64.charCodeAt(j)] = j; }
    base64ToBytes.lut = lut;
  }
  var clean = str.replace(/=+$/, '');
  var outLen = Math.floor(clean.length * 3 / 4);
  var out = new Uint8Array(outLen);
  var acc = 0;
  var accBits = 0;
  var p = 0;
  for (var k = 0; k < clean.length; k++) {
    var v = lut[clean.charCodeAt(k)];
    if (v < 0) { continue; }
    acc = ((acc << 6) | v) >>> 0;
    accBits += 6;
    if (accBits >= 8) {
      accBits -= 8;
      out[p++] = (acc >>> accBits) & 0xFF;
    }
  }
  return out.subarray(0, p);
}

// 保存：世界到 localStorage
async function saveGameToSlot(slotName, slotKind) {
  var payload = buildSavePayload(World, slotName, slotKind);
  var json = JSON.stringify(payload);
  var raw = new TextEncoder().encode(json);
  if (raw.length > MAX_SAVE_BYTES) {
    showToast('存档超出上限（' + raw.length + ' 字节），保存被拒绝');
    return false;
  }
  var packed = await compressBytes(raw);
  payload.compressed = (packed.algo === 'none') ? 0 : 1;
  payload.compression = packed.algo;
  payload.rawByteLength = raw.length;
  payload.payloadCRC32 = crc32(raw);

  // 二次序列化：携带压缩头
  var header = JSON.stringify({
    magic: payload.magic,
    formatVersion: payload.formatVersion,
    gameVersion: payload.gameVersion,
    contentHash: payload.contentHash,
    payloadCRC32: payload.payloadCRC32,
    compressed: payload.compressed,
    compression: payload.compression,
    rawByteLength: payload.rawByteLength,
    stateHash: payload.stateHash
  });
  var headerBytes = new TextEncoder().encode(header);
  var file = concatU8(
    new Uint8Array([headerBytes.length & 0xFF, (headerBytes.length >>> 8) & 0xFF]),
    concatU8(headerBytes, packed.data)
  );

  // 键名规范：oneleaf.save.<slotName>，slotName 为 slot1..slot5 / quick / auto1..auto5 / autosave
  var key = 'oneleaf.save.' + slotName;
  var b64 = bytesToBase64(file);
  try {
    localStorage.setItem(key, b64);

async function handleQuotaExceeded(key, b64, slotName, slotKind, payload) {
  // 策略：先删最旧自动槽，再删回放缓存
  for (var i = AUTO_SLOT_COUNT; i >= 1; i--) {
    try {
      localStorage.removeItem('oneleaf.save.auto' + i);
      localStorage.setItem(key, b64);
      updateSlotIndex(slotName, slotKind, payload);
      showToast('存储空间不足，已轮换旧自动存档');
      return true;
    } catch (err) { }
  }
  try {
    localStorage.removeItem('oneleaf.replay.recent');
    localStorage.setItem(key, b64);
    updateSlotIndex(slotName, slotKind, payload);
    showToast('已清理回放缓存以完成保存');
    return true;
  } catch (err) { }
  showToast('浏览器存储已满，请删除旧存档或导出文件');
  return false;
}

// 读取：localStorage 到世界
async function loadGameFromKey(key) {
  var b64 = null;
  try { b64 = localStorage.getItem(key); } catch (err) { return { ok: false, error: 'E_SAVE_B64' }; }
  if (b64 === null || b64.length < 48) { return { ok: false, error: 'E_SAVE_B64' }; }

  var file = base64ToBytes(b64);
  if (file.length < 34) { return { ok: false, error: 'E_SAVE_B64' }; }
  var headerLen = file[0] | (file[1] << 8);
  var headerJson = new TextDecoder().decode(file.subarray(2, 2 + headerLen));
  var header = null;
  try { header = JSON.parse(headerJson); } catch (err) { return { ok: false, error: 'E_SAVE_B64' }; }
  if (header.magic !== 'ONELEAF') { return { ok: false, error: 'E_SAVE_MAGIC' }; }
  if (header.formatVersion > SAVE_FORMAT_VERSION) {
    return { ok: false, error: 'E_SAVE_VERSION' };
  }

  var body = file.subarray(2 + headerLen);
  var raw = null;
  try {
    raw = await decompressBytes(body, header.compression);
  } catch (err) {
    return { ok: false, error: 'E_SAVE_CRC' };
  }
  if (raw.length !== header.rawByteLength) { return { ok: false, error: 'E_SAVE_CRC' }; }
  if (crc32(raw) !== (header.payloadCRC32 >>> 0)) { return { ok: false, error: 'E_SAVE_CRC' }; }

  var data = null;
  try { data = JSON.parse(new TextDecoder().decode(raw)); } catch (err) {
    return { ok: false, error: 'E_SAVE_CRC' };
  }

  if (data.contentHash !== CONTENT_HASH) {
    return { ok: false, error: 'E_SAVE_CONTENT', data: data };
  }

  if (data.formatVersion < SAVE_FORMAT_VERSION) {
    var mig = migrateSave(data, SAVE_FORMAT_VERSION);
    if (!mig.ok) { return { ok: false, error: 'E_SAVE_MIGRATION_MISSING' }; }
    data = mig.data;
  }

  // 内联校验：残骸表与混沌巢穴表（P0）
  if (!validateCorpsesAndLairs(data)) {
    return { ok: false, error: 'E_SAVE_HASH' };
  }

  var world = deserializeWorld(data);
  var expected = data.stateHash;
  var actual = hex8(computeStateHash(world));
  if (expected !== actual) {
    return { ok: false, error: 'E_SAVE_HASH', expected: expected, actual: actual };
  }
  return { ok: true, world: world, data: data };
}

// 残骸表与混沌巢穴表的内联校验（P0）
function validateCorpsesAndLairs(data) {
  var i;
  for (i = 0; i < data.corpses.length; i++) {
    var cp = data.corpses[i];
    if (cp.ttlTicks < 0 || cp.ttlTicks > CORPSE_TTL_TICKS) { return false; }
    if (UNIT_TYPE_SET[cp.originalType] !== true) { return false; }
    if (!Number.isInteger(cp.x1000) || !Number.isInteger(cp.y1000)) { return false; }
  }
  for (i = 0; i < data.chaosLairs.length; i++) {
    var lr = data.chaosLairs[i];
    if (lr.scalePermille < 800 || lr.scalePermille > 1600) { return false; }
    if (lr.alive !== 0 && lr.alive !== 1) { return false; }
    if (lr.cleared !== 0 && lr.cleared !== 1) { return false; }
  }
  return true;
}
```

**保存与读取的性能红线（P0）**：`localStorage.setItem` 是同步阻塞操作，是唯一可能超过 100 毫秒预算的环节（在存储量接近配额时可能达到 25 至 40 毫秒）。因此规则是：**压缩必须在 tick 边界之外的 `requestIdleCallback` 中完成**，且**不允许在一帧内同时保存到多个槽位**。玩家手动保存时若正在游戏中，允许插入一次约 1 帧（16 毫秒）的轻微停顿，这已被测试证明不可感知。

**残骸与混沌表的体积纪律（P0）**：残骸表的体积随「最近 60 秒内的死亡数」波动，最坏情况可达 400 具。实施方**不得**为了省体积而做以下任何一件事：① 只存残骸哈希不存明细；② 把残骸的 `originalType` 存成字符串（必须用类型哈希，UI 悬停时再反查）；③ 读档后按 `ttlTicks` 重新随机生成残骸。这三条中的任何一条都会让 `T02`（同一存档读入两次后同哈希）失败。

**黄金值附录（P0 测试基准）**：主种子 `12345` 时五条随机流的 **40 个 `nextU32()` 输出已在「随机流的分流」一节的黄金值表里逐位给出具体数值**（派生规则 `streamSeed = (12345 ^ 常量) >>> 0`，常量取 `STREAM_SEED_XOR`），实施方直接把该表转写成断言数据即可，不再需要「先跑一次再固化」。任何改动（更换算法、修改 `STREAM_SEED_XOR` 常量、调整 `mulberry32` 的 finalizer 或加法常量 `0x6D2B79F5`）都会让**所有历史存档与回放失效**，因此必须同时**递增 `formatVersion`** 并写入迁移函数；只改代码不改版本号视为交付失败，这是本项目最容易被忽视的兼容性陷阱。`xorshift128` 不在本测试的判据范围内（它是 P2 备选实现，P0 不启用）。

**验收口径（P0）**：

- 存档与回放功能的验收以「**同一输入序列产生相同状态哈希**」为唯一客观标准，不接受任何主观判断。
- 交付时必须附带一份自检报告，列出 T01 至 T18 的实际结果（哈希值、体积、耗时、1440 格查表比对结果），缺项视为未完成。
- 若出现状态哈希不一致，实施方必须先修复确定性缺陷，**禁止**通过放宽哈希字段、跳过检查点、跳过残骸表或混沌巢穴表、或提高容差来「通过」测试。残骸与混沌巢穴这两张表是《一叶》新增的高风险分组，**把它们从哈希里摘出去会让 T02 与 T06 表面通过、实际失效**，属于最严重的交付缺陷。
