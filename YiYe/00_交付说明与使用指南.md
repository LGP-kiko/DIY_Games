## 二、这份企划案是什么

《一叶》的世界观与全部机制**逐字取自 `Input\一叶.docx`**——世界树叶片上的三方争夺（原初 / 主宰 / 侵蚀）与中立生物混沌。企划案做的是把这些设定**精确化到可直接编码**的程度：

| 设定原文 | 企划案中的精确化 |
| --- | --- |
| 伤害类型：轻型（对单）、重型（对群 AOE） | 两种伤害类型，全部武器二选一；重型武器一律带溅射 |
| 轻甲公式 `x = max(min(6-n, x), x*(1-n*10%) - n)` | 逐字实现；`n` 取目标的**轻型护甲等级**；结果向下取整、最小 1 |
| 重甲公式 `x = 5/(5+n!)*x`（0 级取 x） | 逐字实现；`n` 取目标的**重型护甲等级** |
| （优化：使用查表） | 启动时用公式预计算 **6×200 两张表**，运行时只查表；Excel 与 JSON 直接提供这两张表 |
| 解放 | 摧毁「奴役控制节点」（收割者 / 督军 / 侵蚀之核）→ 半径 10 格（侵蚀同化塔后 20 格）内敌方奴隶转为摧毁者所有 |
| 回收（50% 造价） | 主动拆除己方建筑或单位返还 50%；施工中的蓝图不可回收 |
| 残骸（60 秒，含最大体力与初始造价） | 独立实体，携带 `maxHp` 与 `cost`，可悬停查询，进存档与状态哈希 |
| 效率（实际产值 ÷ 初始设定值） | 顶栏直接显示 120%（原初）/ 140%（主宰）/ 100%（侵蚀） |
| 抗性描述（轻型/重型） | 信息面板与悬停提示统一显示 `n/m`，如 `3/3` |
| 建筑单位初始抗性 3/3 | 全部 32 种建筑统一 3/3 |
| 战争单位免疫正负面效果 | 3 个战争单位（原初之怒 / 督军 / 侵蚀之核）不受老兵、护盾、再生、吞噬、腐蚀、解放、速度增减影响 |
| 奴役单位仅执行预设 AI | 奴隶不进选择集合、不可下令、不占人口；被解放后转为可控 |
| 侵蚀：残骸 10%、摧毁解锁科技、不被中立敌对 | 残骸熔炉提升至 25%；科技表带「腐蚀掠夺」解锁条件列；混沌索敌时排除侵蚀 |
| 主宰：生产力 140%、回收站 50%、护盾、建筑需电力 | 奴隶 56 源质/秒且不占人口；回收站返还 50%；护盾上限 = 体力 × 0.5；**电力是主宰独有机制** |
| 原初：再生、资源 120%、对中立 200%、吞噬 | 脱战 8 秒后单位 2%/秒、建筑 1%/秒；采集 ×1.2；对混沌 ×2.0；吞噬残血混沌永久 +10% 体力与 +1 轻甲 |
| 混沌：残骸恢复 100%、越靠中心越强 | 体力不满时吞残骸按最大体力 100% 恢复；倍率 `clamp(1.6 - 1.2×(d/dMax), 0.8, 1.6)` 同时作用于体力、伤害与护甲等级 |

## 三、如何把这份文档交给下游 AI

### 方案 A：一次性投喂（长上下文模型）

```
请阅读《一叶》游戏企划案（附件），并严格按第 18 章的 8 个阶段依次实现，
产出一个单文件 OneLeaf.html（零依赖、零外部素材、file:// 双击可玩）。
硬性要求：
1. 全部数值必须从 yiye_data_pack.json 直接载入为 DATA 常量，禁止手工转写；
2. 伤害必须查表（LIGHT_TABLE / HEAVY_TABLE，6×200），禁止在结算路径里套公式；
3. 战争单位不得受到任何正负面特殊效果；
4. 玩家不得直接控制奴役单位；
5. 电力只属于主宰；
6. 残骸必须携带最大体力与初始造价并进入存档；
7. 全部完成后按第 19 章逐条自测并输出 SELFTEST.md。
```

### 方案 B：分章投喂（上下文受限）

| 轮次 | 投喂章节 | 本轮目标 |
| --- | --- | --- |
| 1 | 第 1、2 章 | 单文件骨架、固定步长循环、等距投影、镜头、调试面板 |
| 2 | 第 8 章 + 第 3 章 | 载入 `DATA` 并断言 32/35/33 与两张 6×200 查表；精灵工厂；选择系统 |
| 3 | 第 5、6、7 章 | 12 种地形、阻挡图、源质经济、回收与残骸、主宰电力 |
| 4 | 第 9、10 章 | 查表伤害、双维度护甲、A\*、阵型、单位 AI |
| 5 | 第 11、13 章 | 双层迷雾（含残骸三态与巢穴常显）+ 全部 UI（含抗性描述） |
| 6 | 第 12 章 | 三套阵营建造序列 + 混沌中立行为层 + 难度参数 |
| 7 | 第 15 章 | 6 张地图 + 随机地图 + 4 关战役 + 触发器 |

### 方案 C：垂直切片（最稳）

先只要求实现「第 2 章框架 + 第 8 章 DATA + 第 6/7 章经济建造」，产出一个**只能采集、造建筑、处理残骸、但还不能打仗**的版本，确认三条红线没被破坏（固定步长、零依赖、查表化伤害的入口已建立），再追加战斗与 AI。

## 五、已完成的自检与验证

1. **模板契合**：docx 复用 `Input\文档模板.docx` 的完整 OOXML 包（样式、编号、主题、页面设置原样保留），正文使用模板自带的样式；仅替换正文内容并新增页码页脚。
2. **文件有效性**：生成的 docx 用 **Microsoft Word 实际打开校验**（页数、字数、表格数、页脚 `PAGE`/`NUMPAGES` 域均正常，无修复提示）；xlsx 用 **Excel 实际打开校验**（17 个工作表、抽查单元格数值正确）。
3. **数值一致性**：Excel / JSON / 第 8 章三份产物由同一数据源生成；脚本验证 **两张查表 2400 格与设定公式逐格一致**，且**全部 33 把武器的 x 都落在查表范围 1–200 内**。
4. **结构完整性**：全文表格逐张校验列数一致（0 处错行）；**49 处跨章交叉引用全部可解析**；md 与 docx 的标题集合逐项比对一致。
5. **设定忠实度**：对 `Input\一叶.docx` 的每一条机制做了「设定原文 → 精确化实现」的映射表（见本文件第二节），并写明「若与原始设定冲突，以 `Input\一叶.docx` 为准」。
6. **防回归抽样**：校验脚本固化了 11 条「必须存在」的设定要点与 5 条「必须已清除」的旧项目残留（旧游戏名、旧阵营、旧资源名、旧存档前缀、旧伤害矩阵）。

## 六、数值一致性保障机制（本项目的关键设计）

```
                 yiye_data.js  +  yiye_maps.js
                 （唯一数据源，人工维护）
                            │
        ┌───────────────────┼───────────────────┐
        ▼                   ▼                   ▼
 一叶_数值设定表.xlsx   yiye_data_pack.json   第 8 章数据表
   （17 个工作表）        （机器可读）        （正文，自动生成）
```

- **禁止**在任何章节里手写与数据源冲突的数字；正文里的数值都标注了来源（第 8 章或 Excel 工作表）。
- 第 1 章的《数值与结构的唯一权威来源》表规定了每个主题的裁决顺序：**`Input\一叶.docx` > Excel > JSON > 第 8 章 > 其他章节**。
- 若实施方需要新增内容（新单位、新科技），**必须先回到数据源扩充并重新导出**，不得在代码里就地加值。

## 七、下游实现时最容易翻车的 12 个点

1. **把 `min(6-n, x)` 当成伤害上限**——它外层是 `max`，是**保底值**（见第 8.2 节）。
2. **实时套伤害公式**——设定明确要求「优化：使用查表」，且实时套公式会破坏回放确定性。启动时预计算 6×200 两张表。
3. **取错护甲维度**——轻型武器查 `lightArmor`，重型武器查 `heavyArmor`，两者独立。
4. **给原初或侵蚀加了电力**——电力是主宰独有的维护机制，另两阵营的界面不得出现电力条。
5. **让战争单位吃到老兵/护盾/再生**——这是设定原文的红线。
6. **让玩家能框选奴役单位**——奴隶点击只查看，不进选择集合，否则玩家会以为操作失灵。
7. **残骸只做特效不做数据**——残骸必须携带最大体力与初始造价，并参与存档与状态哈希。
8. **残骸与死亡不同帧生成**——侵蚀的自动回收会漏掉，必须同 tick。
9. **解放只在 UI 层换色**——必须在死亡结算阶段真正改 `owner`。
10. **混沌主动攻击侵蚀**——违反「不被中立单位敌对」，除非侵蚀先攻击。
11. **浅毒滩允许履带通行 / 毒瘴被地面单位穿过**——「载具必须走桥」的地图设计会全部失效。
12. **混沌中心强化只加体力**——设定要求「越靠近中心区域数值越高」，体力/伤害/护甲要同时乘倍率。
