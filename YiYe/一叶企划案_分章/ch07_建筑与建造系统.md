## 7　建筑与建造系统

### 7.1　建筑生命周期状态机（P0）

```
[放置合法] --place_building--> blueprint(施工中, hp=1%) --buildTime 到期--> active(完工)
        |                                                                    |
        |<-- 被摧毁(hp=0) --> corpse(残骸, 保留 60 秒, 携带最大体力与初始造价) <--|
        |                                                                    |
        |<-- sell（语义 = 主动回收）--> (腾出占位, 返还造价 50%)               |
        |<-- 被占领(hp<33%) --> active(所有权变更, hp 恢复为 maxHp×33%)         |
blueprint --被摧毁--> (直接消失, 无残骸, 不返还源质)
active --pack_conyard(仅核心建筑)--> 可部署核心单位(建筑单位)
可部署核心单位 --deploy_mcv--> active(核心建筑, 立即完工, hp=100%)
```

| 状态 | 键名 | 可被选中 | 提供建造半径 | 提供/占用电 | 可生产 | 受击伤害 | 可被占领 | 可被主动回收 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 施工中 | `blueprint` | 否 | 否 | 否 | 否 | 是（伤害照常） | 否 | **否**（关键词「回收」明确排除施工中的蓝图） |
| 完工 | `active` | 是 | 是 | 是 | 是 | 是 | 是（hp < 33%） | 是（返还造价 50%） |
| 断电（仅主宰） | `unpowered` | 是 | 是 | 是（仍占用电） | 是（生产 ×0.5） | 是 | 是 | 是（返还造价 50%） |
| 残骸 | `corpse` | 否（可悬停查看） | 否 | 否 | 否 | 否 | 否 | 否 |

> **建筑单位定义（P0，取自第 8 章）**：全部 32 种建筑的 `kind` 均为「建筑单位」，初始抗性统一 `3/3`（防御建筑为 `4/4`），因此**任何己方建筑都能被玩家主动回收**，返还其造价的 50%。建筑与被摧毁的残骸都不是「不可回收物」：前者走 `sell`，后者是侵蚀与混沌的养料。

### 7.2　放置流程（P0）

| 步骤 | 玩家动作 | 系统响应 |
| --- | --- | --- |
| 1 | 点击侧边栏建筑图标 | 进入放置模式；鼠标跟随建筑幽灵；侧边栏该图标高亮；显示造价（源质）与前置要求 |
| 2 | 移动鼠标 | 每帧把屏幕坐标反投影为格坐标，以**鼠标所指格为建筑左下角基准格**（占领 `w×h`），做合法性判定（见第 5 章建造合法性）；幽灵着色绿/红并显示原因 |
| 3 | 左键点击 | 若合法：立即扣除源质、创建 `blueprint` 实体、播放 `build_place` 音效、退出放置模式（按住 Shift 可连续放置）；若不合法：播放 `ui_deny`、保留放置模式 |
| 4 | 右键 / `Esc` | 取消放置模式，若已扣款则全额退款（本设计在扣除前校验，因此通常无款可退） |
| 5 | 放置后 | 蓝图周围显示建造半径虚线圆（核心建筑 8 格、普通建筑 6 格，与第 8 章 `BUILD_RADIUS_CORE` / `BUILD_RADIUS` 一致） |

**建造半径的来源（P0）**：建造半径只由**己方已完工的建筑**提供——核心建筑（`py_core` / `dm_core` / `er_core`）提供 **8 格**，其余建筑提供 **6 格**。`ch_lair` 是中立建筑，**不为任何一方提供建造半径，也不可被建造或占领**。

| 放置细则 | 规定 |
| --- | --- |
| 基准格 | 建筑矩形以「鼠标格的右下方」为基准：占用格为 `[tx, tx+w-1] × [ty, ty+h-1]`；鼠标在建筑中心时体验最佳，实施方需把幽灵绘制在鼠标位置并做 0.5 格偏移，使视觉中心对齐光标 |
| 地形限制 | 12 种地形中只有叶肉、腐土、灰沙可建造；脉络（公路）、岩层、毒瘴、浅毒滩、叶底裂隙、源质矿脉、晶簇、岩桥、孢子林一律不可建造 |
| 连续放置 | `Shift` 保持放置模式；适合防御塔成排建造 |
| 微调 | `Q`/`E` 可原地旋转建筑（本作建筑均为轴对齐，旋转仅影响朝向精灵，不影响占位）；`R` 键 P2 |
| 建造半径可视化 | 放置模式下，己方所有已完工建筑绘制虚线圆 |
| 施工中的蓝图数量上限 | 每方同时最多 **6** 个 `blueprint`（第 8 章 `MAX_BLUEPRINTS`）；超出时新放置被拒绝并提示「施工队列已满」 |
| 电力前置（仅主宰） | 依赖电力的主宰建筑在**电力余额为负**时仍可放置与施工，但生产设施完工后即处于 `unpowered` 状态（见「电力」小节） |
| 4 座核心上限 | `py_core` / `dm_core` / `er_core` 每方上限 **4**；`py_evolve` / `dm_lab` / `er_corrupt` 上限 **2**；`py_pulse` / `dm_radar` / `er_tendril` 上限 **1**；`py_devour` / `er_assimil` 上限 **1**（均取自第 8 章建筑表的「上限」列） |

### 7.3　施工进度模型（P0）

| 规则 | 规定 |
| --- | --- |
| 初始血量 | `hp = max(1, floor(maxHp × 0.01))`（1%） |
| 进度累加 | 每 tick `progress += (1 / buildTimeTicks) × speedMul`，其中 `speedMul = lowPower ? 0.5 : 1.0`（**只有主宰会命中 `lowPower`**，原初与侵蚀恒为 1.0） |
| 血量增长 | `hp = max(1, floor(maxHp × (0.01 + 0.99 × progress)))` |
| 完工阈值 | `progress ≥ 1` → 状态转 `active`，`hp = maxHp`，播放完工音效与播报，更新阻挡图与建造半径，若该建筑提供电力则重算电力 |
| 施工视觉 | 蓝图以 55% 透明绘制，叠加「从下往上填充」的实心剪影（按 `progress` 高度），并有周期性地脉脉冲特效 |
| 施工被打断 | 蓝图被摧毁 → 实体删除，**不退款、不生成残骸**，播放爆炸；若该蓝图是某个单位的前置，则相关生产队列项保留但不推进（等待重建） |
| 施工中的建筑不可回收 | 蓝图**不响应** `sell`（主动回收），必须等完工后才能回收；这是「回收」关键词的明确边界 |
| 暂停施工 | 玩家可点击蓝图 → 侧边栏「暂停施工」按钮（暂停时不消耗任何资源，因为源质已扣）；P1 |
| 加速手段 | 本作**没有**「建造加速」技能，保持经济决策纯粹。逐栋建筑的差异只体现为 `buildTime` 本身：核心 50 秒、卸矿点 32 秒、生产-基础 12 秒、生产-高级 36 秒、科技 38 秒、防御 14–20 秒、侦查 24 秒、特色 22–34 秒（全部取自第 8 章建筑表） |

### 7.4　生产队列（P0）

只有职能为「生产-基础」或「生产-高级」的建筑拥有队列：原初的 `py_hatch` / `py_beast`，主宰的 `dm_foundry` / `dm_heavy`，侵蚀的 `er_spawn` / `er_aberr`。核心建筑不具备生产建筑的能力。

| 规则 | 规定 |
| --- | --- |
| 队列上限 | 每栋建筑 **9** 项（第 8 章 `MAX_QUEUE`） |
| 生产起点 | 队列第 1 项在**建筑完工后**立即开始；每栋生产建筑同时只能生产 1 个单位 |
| 多工厂分流 | 下达生产命令时若该类型有多个可生产建筑，**自动分配到队列最短的建筑**；玩家可在侧边栏切换目标建筑（P1） |
| 进度累加 | 与施工同构：`progress += (1 / buildTimeTicks) × speedMul`；主宰断电时 `speedMul = 0.5` |
| 产出位置 | 单位的出生点 = 建筑外接矩形边缘、朝向集结点方向的可通行格；若被占用则依次尝试左右各 2 格；全部被占则推迟到有空格为止（不卡死队列） |
| 产出后行为 | 若建筑设置了集结点 → 自动 `move` 到集结点并转入 `Defensive` 姿态；未设置 → 在出生点原地 `guard` |
| **奴隶不在生产队列中** | `dm_slave` **不可被生产**，不出现在任何生产建筑的按钮里；它由 `dm_extract`（矿产中心）**每 20 秒自动生成 1 名**，不占人口、不花源质（详见「主宰：奴隶与免费单位」小节） |
| 取消 | 队列项右键取消 → 全额退款（未开始）或按进度退款（进行中 = `造价 × 50% × (1 − 进度)`） |
| 暂停 | 队列项左键切换暂停/继续，暂停时进度冻结且不退款 |
| 队列显示 | 侧边栏每栋建筑显示一条 200×8 像素进度条 + 剩余秒数（`ceil(剩余 tick / 20)`），最多显示 5 项，超出显示「+N」；主宰建筑在断电时队列表头显示「电力不足，生产速度下降」 |
| 单位产出播报 | 每个单位出厂播放 `unit_ready` 音效；战斗单位出厂播报「单位已就绪」（节流 3 秒）；战争单位出厂播报「战争单位已就绪」并按最高优先级处理 |

### 7.5　集结点（Rally Point）规则（P0）

| 规则 | 规定 |
| --- | --- |
| 设置方式 | 选中建筑 → 右键点击地面/目标（第 4 章决策树第 8 条） |
| 指向地面 | 新单位出厂后前往该格，抵达后转为 `guard` |
| 指向资源点 | 仅对采集单位有效：新出厂的 `py_gatherer` / `er_drinker` 出厂后直接进入 `harvest` 状态 |
| 指向单位 | 新单位出厂后**跟随**该单位（每 2 秒更新一次目标位置，跟随距离 2 格）；P1 |
| 指向敌方单位 | 新单位出厂后 `attack_move` 到该目标的当前位置（一次性，不持续追踪） |
| 指向残骸 | 任何阵容都可以把集结点指到残骸上：侵蚀的新单位出厂后前往该残骸执行回收；其他阵容的新单位出厂后按「残骸不产生命令」的原则忽略该指向并落到残骸旁最近的空格（UI 必须给出「残骸不可作为集结点目标」的提示文本） |
| 视觉 | 建筑到集结点绘制阵营色虚线 + 菱形标记；集结点在新单位抵达后**不消失**（持续有效） |
| 默认集结点 | 建筑完工时默认集结点 = 建筑正面外侧 2 格 |

### 7.7　防御建筑行为细则（P0）

| 规则 | 规定 |
| --- | --- |
| 自动索敌 | 射程内自动选择目标（优先级：正在攻击己方建筑的敌人 > 最近的敌人） |
| 目标优先级 | 对空建筑（`py_spore` / `dm_aegis` / `er_cloud`）优先打空中单位；对地建筑（`py_spike` / `dm_sentry` / `er_acidvent`）的武器 `可对空 = 否`，**忽略空中单位** |
| 断电开关（仅主宰） | 只有主宰的防御建筑（`dm_sentry` / `dm_aegis`）参与电力系统；电力余额为负时射速 ×0.5、不索敌。原初与侵蚀的防御建筑**没有断电状态**，但可以被玩家主动回收（`sell`）换成源质 |
| 低电惩罚 | 仅主宰适用；低电时射速 ×0.5。**射程不变**（本作低电不缩射程），这与第 8 章电力规则的表述一致 |
| 建筑被摧毁 | 播放大型爆炸、生成**残骸**（保留 60 秒，携带最大体力与初始造价，不再永久堵路），扣除其电力产出与占用并重算电力 |
| 建筑血条 | 受击后显示 5 秒；选中时常显；主宰建筑同时显示电力收支（如聚变反应堆 `+32`、矿产中心 `−5`） |
| 防御武器的数值来源 | 射速与伤害全部取自第 8 章武器表：`w_py_spike`（轻型 35，2 连发）、`w_py_sporetower`（轻型 50，可对空）、`w_dm_sentry`（轻型 32，3 连发）、`w_dm_aegis`（轻型 55，可对空）、`w_er_acidvent`（**重型 42**，唯一带溅射的防御塔）、`w_er_cloud`（轻型 46，可对空） |

### 7.8　工程与占领（P0）

《一叶》没有通用的「工程师」单位，工程职能由三个阵营各自的基础单位承担：`py_shaper` 塑形者（400 源质）、`dm_drone` 工蜂无人机（400）、`er_sporework` 孢子工（400）。它们都能建造、修理与占领。

| 规则 | 规定 |
| --- | --- |
| 工程单位 | `py_shaper` 100 体力 / `dm_drone` 90 体力 / `er_sporework` 100 体力；均无武器、抗性 1/0、人口 1 |
| 占领条件 | 目标为**敌方建筑**且 `hp / maxHp < 0.33`；否则右键提示「无法占领该建筑」 |
| 占领过程 | 工程单位移动到建筑边缘 → 进入（工程单位实体删除）→ 建筑所有权变更为己方，血量恢复为 `maxHp × 0.33`，状态 `active`，`constructionProgress` 已满 |
| 占领反馈 | 播放 `capture_success`，播报「建筑已占领」，建筑精灵立即换成己方阵营色（重新 tint） |
| 修理 | 工程单位右键己方受损建筑或单位 → 进入并消失，恢复 `maxHp × 0.5` 体力（可超过当前维修上限，不消耗源质）；也可对**战争单位**执行修理（修理不是「特殊效果」，免疫不阻挡修理） |
| 反制 | 建筑体力 ≥ 33% 时无法被占领；维修可保持建筑高体力来防占领 |
| **占领不是「解放」** | `capture` 只对**建筑**生效；奴役单位（`dm_slave`）不能通过占领易主，只能通过摧毁**奴役控制节点**（`dm_reaper` / `dm_warlord` / `er_core_unit`）触发「解放」（半径 10 格，`er_assimil` 建成后 20 格） |
| 混沌巢穴例外 | `ch_lair` 是中立建筑，**不可被占领**；右键点击它时提示「混沌巢穴无法占领」 |

### 7.9　核心再部署（P0）

《一叶》没有传统意义上的基地车与建造厂两级结构，核心建筑本身就是唯一可移动的基地：**`pack_conyard` 把它打包成可部署核心单位，`deploy_mcv` 再展开成新的核心建筑**。这是扩张分基地的唯一手段。

| 动作 | 前置条件 | 耗时 | 结果 |
| --- | --- | --- | --- |
| 打包 `pack_conyard` | 核心建筑（`py_core` / `dm_core` / `er_core`）已完工，且其生产队列为空；当前格无单位阻挡 | 1.5 秒（30 tick） | 核心建筑删除，原位生成对应的可部署核心单位（`py_core` → 迁徙母巢、`dm_core` → 指挥车、`er_core` → 腐蚀囊）；该单位属于「建筑单位」，**没有武器、可被主动回收** |
| 部署 `deploy_mcv` | 核心单位静止、当前格 3×3 全部可建造、无单位阻挡 | 1.5 秒（30 tick） | 核心单位删除，原位生成 `active` 满血的核心建筑，恢复 8 格建造半径 |
| 打包时的建筑半径 | 打包后原有的 8 格建造半径来源消失；若场上无其他己方建筑，玩家将无法建造新建筑 | — | UI 必须提前提示「打包后将失去 8 格建造范围」 |
| 常见用法 | 扩张分基地：打包 1 座核心 → 开到远处源质矿脉或晶簇旁 → 部署 → 在新位置建卸矿点与防御塔 | — | AI 也会使用（见第 12 章） |
| 与「回收」的区别 | `pack_conyard` **不返还源质**（建筑还活着，只是换了形态） | — | `sell`（主动回收）把建筑直接拆掉并返还 50% 源质。两者不可混用，UI 必须用不同图标与文案区分 |

### 7.10　电力（仅主宰）（P0）

**电力只属于主宰。** 32 种建筑中只有主宰的建筑带 `power` 字段，原初与侵蚀的 20 种建筑**没有任何电力需求**，它们的界面里没有电力条，断电这一状态在原初与侵蚀的代码路径上**不存在**。

| 阵营 | 是否有电力 | 电网来源 | 说明 |
| --- | --- | --- | --- |
| 主宰 | 是 | `dm_reactor` 聚变反应堆 `+32` | 其余主宰建筑为负值占用（见下表） |
| 原初 | **否** | — | 10 种建筑全部 `power = —`；生产与防御恒速 |
| 侵蚀 | **否** | — | 10 种建筑全部 `power = —`；侵蚀的代价是**没有采集加成**（40/秒基准），靠残骸回收补经济 |
| 混沌 | 否 | — | `ch_lair` 无电力字段 |

**主宰建筑电力字段（P0，取自第 8 章建筑表）**

| 建筑 | 电力 | 建筑 | 电力 |
| --- | --- | --- | --- |
| `dm_reactor` 聚变反应堆 | **+32** | `dm_radar` 雷达站 | −20 |
| `dm_extract` 矿产中心 | −5 | `dm_shield` 护盾发生器 | −20 |
| `dm_foundry` 铸造厂 | −5 | `dm_recycler` 回收站 | −10 |
| `dm_heavy` 重装工厂 | −15 | `dm_core` 指挥核心 | — |
| `dm_lab` 研究所 | −30 | `dm_sentry` / `dm_aegis` | −5 / −10 |

**自洽性校验（P0，实施方必须断言）**：`dm_core + dm_reactor + dm_extract + dm_foundry` 的电力余额 = `0 + 32 − 5 − 5 = +22`（必须为正），与第 8 章数据一致性检查清单一致。

**断电惩罚表（P0）**

| 影响项 | 倍率 | 表现 |
| --- | --- | --- |
| 生产速度 | ×0.5 | 施工与生产每 2 tick 才累加 1 次；队列表头显示「电力不足，生产速度下降」 |
| 防御射速 | ×0.5 | `dm_sentry` / `dm_aegis` 的 `射速(tick)` 翻倍；不缩射程 |
| 雷达 | 失效 | `dm_radar` 停止提供小地图实时敌对显示，小地图退回「最后已知位置」 |
| 不受影响项 | — | 单位移动、单位武器、护盾回复、生命值、资源采集、主动回收返还比例均不受电力影响 |

**电力重算时机（P0）**：任何主宰建筑完工、被摧毁、被占领、被主动回收、被 `pack_conyard` 打包时，必须立即重算该玩家的电力余额；重算结果在**同一 tick 内**生效，不允许延迟一帧。

### 7.11　主动回收（P0）

「回收」是《一叶》的关键词之一：**以 50% 的造价回收资源**。它适用于**任何己方建筑与任何己方单位**（含建筑单位、一般单位、战争单位、已解放的奴隶），由玩家主动触发。

| 规则 | 规定 |
| --- | --- |
| 触发方式 | 侧边栏「回收」按钮 + 左键点己方目标（命令键名 `sell`，见第 4 章）；选中单位时按 `Delete` 是**自毁**（不返还），两者必须区分并给不同文案 |
| 返还比例 | **50%**（第 8 章 `SALVAGE_RETURN`）；`refund = floor(cost × 0.5)` |
| 返还形式 | 直接计入源质，**立即到账**，不受电力、距离、是否有卸矿点影响 |
| 可回收 | `active` 状态的己方建筑、全部己方单位、`unpowered` 状态的主宰建筑 |
| **不可回收** | `blueprint`（施工中的蓝图）、残骸、敌方目标、中立目标、混沌巢穴 |
| 回收过程 | 1.0 秒（20 tick）拆解动画（建筑精灵逐层剥落、单位精灵逐渐透明），期间该目标**仍可被攻击**；拆解被摧毁则**不返还**，并照常生成残骸 |
| 与占领的交互 | 被敌方工程单位占领中的建筑不可回收；回收中的建筑不可被占领 |
| 与人口的关系 | 回收的单位立即释放其人口占用；回收建筑立即释放其电力占用（主宰）并触发电力重算 |
| 与残骸的关系 | 主动回收**不留残骸**（已经变回源质了）；被摧毁才留残骸。这是「回收」与「残骸」两条经济通路的边界 |
| UI 数值 | 回收按钮必须显示实际返还额（例：回收 `dm_shield` 显示 `+750 源质`），由此让玩家直观理解「50% 造价」 |

**典型用法**：主宰在 T2 阶段靠 `dm_extract` 白嫖了 6 名奴隶，源质吃紧时不需要等敌人来拆——把用不到的 `dm_shield` 与一座 `dm_sentry` 主动回收，立刻拿回 `1500×0.5 + 600×0.5 = 1050` 源质去点 `dm_heavy`。原初与侵蚀同理：原初的 `py_regen` 是 1200 源质，临时回收它能换回 600 源质救急，等战局稳定再重建。

### 7.12　残骸（P0）

**任意单位被摧毁后短暂留下残骸，具备最大体力信息和初始造价（保留 60 秒）**。残骸是《一叶》四条机制的公共接口，任何一处实现错误都会同时打坏四套阵容。

| 规则 | 规定 |
| --- | --- |
| 生成 | 任意实体（单位或建筑、任何阵营、含战争单位与奴役单位与混沌单位）体力归零即在原地生成残骸；**蓝图被摧毁不生成残骸** |
| 携带信息 | ① 该单位的**最大体力**；② 该单位的**初始造价**。悬停残骸显示「原始单位名 / 最大体力 / 初始造价 / 剩余秒数」 |
| 保留时长 | **60 秒 = 1200 tick**（第 8 章 `CORPSE_TTL_SEC`），到期后残骸消失并释放阻挡格 |
| 阻挡 | 建筑残骸保留其占位的阻挡（≥3×3 的残骸按原占位挡路），60 秒后自动解除，防止战场被永久堵死；单位残骸不阻挡 |
| 残骸位上限 | 同时存在的残骸 ≤ 200，超出时淘汰最先到期者 |
| 用法① 侵蚀回收 | 任意残骸可被侵蚀回收，获得其初始造价的 **10%**；建成 `er_furnace` 后提升至 **25%**，且半径 10 格内**自动**吸收 |
| 用法② 混沌吞噬 | 混沌单位体力不满且 6 格内有残骸时，优先吞噬残骸，按其**最大体力**的 100% 恢复 |
| 用法③ 玩家查看 | 任何玩家悬停残骸都能看到上述三项信息（**这是非侵蚀阵容右键点残骸时唯一的反馈**，见第 4 章决策树第 3 条） |
| 用法④ 战争单位例外 | 战争单位免疫特殊效果，其残骸**不产生可回收价值**（侵蚀回收收益为 0），但**仍会生成残骸供混沌吞噬** |
| 视觉 | 残骸按原单位轮廓绘制为暗色剪影 + 阵营色残边，带 60 秒倒计时环；侵蚀的残骸熔炉范围内残骸显示吸附力场 |

### 7.13　混沌巢穴（P0）

`ch_lair` 是第 8 章建筑表中唯一的混沌建筑，也是全图唯一的中立建筑。

| 规则 | 规定 |
| --- | --- |
| 建造与占领 | **不可建造、不可占领**（第 8 章造价列即为 `0`，因为它从来不是被「买」出来的）；`capture` 对它返回「混沌巢穴无法占领」 |
| 属性 | 体力 1600、抗性 3/3、视野 10、占地 3×3、无电力字段 |
| 守护 | 每片混沌区域由 1 名 `ch_lord`（混沌领主）守护；领主存活时区域内其他混沌单位攻击力 **+25%** |
| 数值倍率 | 巢穴及其守护单位的数值倍率 = `clamp(1.6 - 1.2 × (d / dMax), 0.8, 1.6)`，`d` 为到地图中心的距离；因此中央巢穴为 1.6×、最外围为 0.8× |
| 摧毁后果 | 摧毁后**该区域的混沌不再重生**（第 8 章：混沌「不建造、不生产、不扩张；清空后该区域永不再生」）。这是玩家把混沌从障碍变成资源的关键操作 |
| 一次性奖励 | 摧毁巢穴时按其倍率掉落**一次性源质奖励**，直接计入摧毁者的源质 |

**与「解放」的关系（P0）**：`ch_lair` **不是奴役控制节点**。摧毁它不会触发「解放」（解放的触发者只有 `dm_reaper` / `dm_warlord` / `er_core_unit`），它也不受侵蚀 `er_assimil` 同化塔的腐化影响。混沌巢穴与奴役体系唯一的交集是：混沌单位被摧毁后同样留下残骸，而残骸正是主宰「回收站」与侵蚀「残骸熔炉」的原料。

**一次性奖励的确定规则（设计推导，与第 8 章不冲突）**

第 8 章的巢穴造价列为 `0`（不可建造），因此奖励不能引用「造价」字段，必须由设计推导出一个确定的**造价基准**。推导锚点：三座核心建筑（`py_core` / `dm_core` / `er_core`）都是 **体力 2200 / 造价 2500**，即 `2500 ÷ 2200 ≈ 1.136 源质/体力`；取整为便于记忆的整数比，把**造价基准定义为与巢穴体力等值的 1600 源质**（`1 源质/体力`），使「巢穴造价基准 = 1600」成为一条可背诵的设计常量。

**奖励 = 1600 × 倍率**，于是倍率与奖励一一对应（全部为整数，无需取整歧义）：

| 倍率 | 0.8 | 0.9 | 1.0 | 1.1 | 1.2 | 1.3 | 1.4 | 1.5 | 1.6 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 一次性奖励（源质） | 1280 | 1440 | 1600 | 1760 | 1920 | 2080 | 2240 | 2400 | 2560 |

**与第 8 章的兼容性检查（P0）**：奖励区间为 **1280–2560 源质**，与第 8 章的建筑造价区间（0–2500）**同量级、不越阶**——最高奖励 2560 与「一座核心建筑的造价 2500」相差不足 3%，与「基准采集速率 40/秒 × 60 秒 = 2400 源质」也同量级，因此不会出现「打一个巢穴比开采一分钟还赚」的失衡；而最低奖励 1280 已高于除核心、卸矿点、生产-高级、科技之外的任何单座建筑（防御塔 600、侦查 900），保证拆除巢穴在任何阶段都值得。奖励是**一次性**的，巢穴不重生，因此它不能作为可循环经济来源——真正可循环的残骸经济只有侵蚀与混沌两套。

**典型数额（取自内置地图的巢穴倍率）**：`ash_outpost` 中央巢穴 0.90 → **1440 源质**；`miasma_river` 两座巢穴各 1.10 → **1760 源质**；`leaf_vein_corridor` 中央巢穴 1.30 → **2080 源质**；`ring_growth` 中央巢穴 1.60 → **2560 源质**，另外两座 1.20 → **1920 源质**。

### 7.14　建筑摧毁与残骸（P1）

| 规则 | 规定 |
| --- | --- |
| 摧毁动画 | 体力归零 → 播放 `explosion_large`（1.2 秒）→ 建筑精灵在 0.6 秒内渐隐并下沉 → 原地留下残骸 |
| 残骸内容 | 携带该建筑的**最大体力**与**初始造价**，保留 60 秒，供侵蚀回收 / 混沌吞噬 / 玩家查看 |
| 残骸占位 | 大型建筑（≥3×3）的残骸保留阻挡 60 秒，60 秒后残骸消失、阻挡解除（防止战场被永久堵死） |
| 残骸不返还 | 被摧毁的建筑**不返还源质**——只有玩家主动回收（`sell`）才返还 50%。这个对比是《一叶》经济决策的核心张力：守住建筑 = 保住 50% 的造价，放弃建筑 = 看着它变成别人的残骸 |
| 死亡统计 | 每次摧毁计入该玩家的 `kills` 与对方的 `losses`，用于结算面板；侵蚀额外累计「腐蚀掠夺」的摧毁计数（整局累计，不因单位损失回退） |
| 连锁爆炸 | 本作**没有**会连锁引爆的电力建筑；`dm_reactor` 被摧毁只损失 32 点电力产出，不造成范围伤害 |
