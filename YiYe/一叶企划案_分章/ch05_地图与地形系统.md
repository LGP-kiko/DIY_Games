## 5　地图与地形系统

### 5.1　网格与尺寸规格（P0）

| 参数 | 规定 |
| --- | --- |
| 网格类型 | 正交方格（非六边形），索引 `(tx, ty)`，`tx` 向右（屏幕右下），`ty` 向下 |
| 尺寸档位 | 64×64（灰烬哨站） / 96×96（默认） / 128×128（环形年轮） |
| 单格世界尺寸 | 1.0 × 1.0 世界单位 |
| 单格像素尺寸 | 64×32 像素（缩放 1.0），即 2:1 菱形 |
| 高度层 | `z ∈ [0, 4]`，整数；每层抬升 12 像素 |
| 每格数据 | 地形类型（1 字节）+ 高度（1 字节）+ 资源余量（2 字节，仅资源格有效）+ 归属占位（运行时表，不入地图数据） |
| 地图存储 | 三个平铺数组：`terrain: Uint8Array(w*h)`、`height: Uint8Array(w*h)`、`ore: Uint16Array(w*h)` |

> **重要**：格子渲染与逻辑分离——逻辑只关心 `terrain`、`height`、`ore` 三个数组；渲染额外使用「预渲染分块缓存」（见第 3.4 节）。

### 5.3　通行性矩阵（P0）

移动类型共 5 种：`foot`（步兵，含采集与工程单位）、`track`（履带）、`wheel`（轮式）、`hover`（悬浮 / 两栖）、`air`（飞行）。

| --- | --- | --- | --- | --- | --- |
| `flesh` | ✔ ×1.00 | ✔ ×1.00 | ✔ ×1.00 | ✔ ×1.00 | ✔ |
| `rot` | ✔ ×1.00 | ✔ ×1.00 | ✔ ×1.00 | ✔ ×1.00 | ✔ |
| `ash` | ✔ ×0.95 | ✔ ×0.90 | ✔ ×0.85 | ✔ ×0.95 | ✔ |
| `vein` | ✔ ×1.25 | ✔ ×1.25 | ✔ ×1.25 | ✔ ×1.25 | ✔ |
| `strata` | ✘ | ✘ | ✘ | ✘ | ✔ |
| `miasma` | ✘ | ✘ | ✘ | ✔ ×0.80 | ✔ |
| `shallow` | ✔ ×0.75 | ✘ | ✘ | ✔ ×1.00 | ✔ |
| `rift`（高差 1） | ✔ ×0.60 | ✘ | ✘ | ✘ | ✔ |
| `rift`（高差 ≥2） | ✘ | ✘ | ✘ | ✘ | ✔ |
| `essence` / `crystal` | ✔ ×0.85 | ✔ ×0.85 | ✔ ×0.85 | ✔ ×0.85 | ✔ |
| `bridge` | ✔ ×1.00 | ✔ ×1.00 | ✔ ×1.00 | ✔ ×1.00 | ✔ |
| `spore` | ✘ | ✘ | ✘ | ✘ | ✔ |

**移动类型与单位的对应（P0）**

| 移动类型 | 使用它的单位 |
| --- | --- |
| `foot` | 全部步兵单位、全部采集单位、全部工程单位、`py_burrow` / `er_digger`（侦查）、`dm_slave`（奴隶） |
| `track` | `py_runner`、`py_carapace`、`py_wrath`、`dm_mbt`、`dm_reaper`、`dm_warlord`、`er_stalker`、`er_husk`、`er_core_unit`、`ch_behemoth`、`ch_lord` |
| `wheel` | `dm_drone`、`dm_striker`、`dm_aa` |
| `hover` | 暂无玩家单位使用；保留给 P2 的两栖单位与地图编辑器（**混沌不占用此类型**） |
| `air` | `py_wing`、`dm_bomber`、`er_bloat`、`ch_moth` |

**寻路代价（P0）**：A* 的移动代价统一按**放大 100 倍的整数**计算（完整规则见第 10.2 节）：`stepBase = round(100 / speedMod)`，正交移动代价 = `stepBase`，对角 = `round(stepBase × 1.414)`，高差每上升或下降 1 层额外 `+40`。例：叶肉（1.00）`= 100`；脉络（1.25）`= 80`；灰沙轮式（0.85）`= 118`；浅毒滩步兵（0.75）`= 133`；源质矿脉（0.85）`= 118`。

### 5.4　高度与高差规则（P0）

| 规则 | 规定 |
| --- | --- |
| 通行判定 | 相邻两格高差 ≥ 2 时不可通行（`air` 除外）；高差 = 1 时仅 `foot` 可通行（速度 × 0.6） |
| 建造判定 | 建筑占地格之间高差必须为 0（整块地面必须在同一高度层） |
| 视野 | 位于高度层 `z` 的单位视野 +`2 × z` 格（上限 +4）；高差 ≥ 2 且距离 > 3 格时低地单位看不到高地单位 |
| 射击 | 高差 ≥ 2 时，低地单位对高地单位的**伤害 ×0.85**；高地单位对低地无惩罚 |
| 侧面渲染 | 绘制竖直侧面墙（见 3.4） |
| 坡道 | 坡道格定义为 `vein` 且与两侧高差 ≤ 1；所有移动类型可通行。**坡道只能行驶、不能建造** |

### 5.5　建造合法性判定（P0）

放置建筑时必须同时满足下列**全部**条件，任一不满足则幽灵显示为红色并给出对应原因：

| 序号 | 条件 | 不满足时的反馈文案 |
| --- | --- | --- |
| 1 | 建筑占用的每个格子 `canBuild = true`（只有 `flesh`、`rot`、`ash` 三种地形可建造） | 「该地形无法建造」 |
| 2 | 建筑占用的所有格子高度 `z` 相同 | 「地面不平整」 |
| 3 | 没有任何格子被其他建筑（含蓝图）占用 | 「此处已被占用」 |
| 4 | 没有被不可推动的单位占用（`foot` 单位会被推开，`track`/`wheel` 单位会阻挡） | 「有单位阻挡」 |
| 5 | 建筑矩形外扩 1 格范围内没有任何阻挡格 | 「空间不足」 |
| 6 | 建筑矩形的**任意一格**中心距离己方任一**已完工**建筑的外接矩形边缘 ≤ 6 格 | 「超出建造范围」 |
| 7 | 己方源质 ≥ 建筑造价 | 「源质不足」 |
| 8 | 前置建筑已完工（见第 8 章科技树） | 「缺少前置建筑：XXX」 |
| 9 | 该建筑类型未达上限（`super` 类与核心建筑有限制，其余不限） | 「已达该类建筑上限」 |
| 10 | **仅主宰**：我方电力余额 ≥ 该建筑耗电 | 「电力不足，无法建造」（原初与侵蚀**没有这一条**） |

**建造半径细则（P0）**：
- 每栋**已完工**的己方建筑提供半径 6 格的建造范围（从建筑外接矩形边缘起算）。
- 三个阵营的核心建筑（`py_core` / `dm_core` / `er_core`）提供半径 **8** 格。
- 施工中的蓝图**不提供**建造半径（防止「用蓝图链式扩张」的漏洞）。
- 若提供半径的建筑被摧毁，已建成 / 施工中的建筑不受影响；新的放置会重新判定。
- 判定使用欧氏距离的整数平方比较。

### 5.7　地图数据格式（P0）

地图以 JSON 定义，**必须硬编码在单文件内**（内置地图）或由生成器运行时产生（随机地图）。禁止通过 `fetch` 加载外部地图文件。

> **注意**：下面的 JSON 只用于说明**字段结构**，坐标与数字是随手举例，**不是任何一张内置地图的真实规格**。6 张内置地图的权威数据见 `Export\yiye_data_pack.json` 的 `maps` 字段与第 15.4 节。

```json
{
  "id": "leaf_vein_corridor",
  "name": "叶脉走廊",
  "size": [96, 96],
  "symmetry": "point",
  "terrain": [0, 0, 1, 3, "... 长度 = 96*96 = 9216 的地形编码数组 ..."],
  "height":  [0, 0, 0, 0, "... 长度 = 9216 的高度数组（0–4）..."],
  "ore":     [0, 0, 0, 0, "... 长度 = 9216 的储量数组（非资源格为 0）..."],
  "spawns": [
    { "faction": "PRIMORDIAL", "tile": [14, 80], "facing": 2 },
    { "faction": "DOMINATOR",  "tile": [81, 15], "facing": 6 }
  ],
  "oreFields": [
    { "kind": "essence", "tiles": [[10, 74], [11, 74]], "totalOre": 800 },
    { "kind": "crystal", "tiles": [[46, 46]], "totalOre": 800 }
  ],
  "chaosLairs": [ { "tile": [46, 46], "scale": 1.30 } ],
  "triggers": [],
  "brief": "中央一条 16 格宽的脉络走廊贯穿全图。"
}
```

| 字段 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| `id` | string | ✔ | 唯一键，小写下划线 |
| `name` | string | ✔ | 中文显示名 |
| `size` | [number, number] | ✔ | `[w, h]`，必须等于数组长度的平方根 |
| `symmetry` | `'point'` / `'mirror_x'` / `'mirror_y'` | ✔ | 对称方式；**不提供 `none`**，所有可玩地图必须对称 |
| `terrain` | number[] | ✔ | 长度 = w×h，值见地形编码表 |
| `height` | number[] | ✔ | 长度 = w×h，值 0–4 |
| `ore` | number[] | ✔ | 长度 = w×h，非资源格必须为 0 |
| `spawns` | object[] | ✔ | 出生点数组，至少 2 个，含 `faction` 与 `tile` |
| `oreFields` | object[] | ✖ | 资源簇摘要，`kind` ∈ `essence` / `crystal` |
| `chaosLairs` | object[] | ✖ | **混沌巢穴**：`tile` 坐标 + `scale` 数值倍率（0.8–1.6） |
| `triggers` | object[] | ✖ | 战役关卡的触发器（见第 15 章） |
| `brief` | string | ✖ | 一句话战术说明，显示在遭遇战设置界面 |

**地图加载流程（P0）**：
1. 校验 `size` 与三个数组长度一致；不一致则抛出可见错误（不允许静默失败）。
2. 把 `terrain` / `height` / `ore` 写入 `Uint8Array` / `Uint8Array` / `Uint16Array`。
3. 构建**阻挡图** `blocked`（1 = 不可通行）、**可建图** `buildable`、**静态代价图** `moveCost`（按 `foot` 与 `track` 两套各建一份，`air` 不建）。
4. 校验出生点：3×3 范围必须全部可建造且可通行。
5. 校验连通性：从出生点 0 出发做 BFS，**分别按 `foot` 与 `track` 两套通行性各校验一次**，必须都能到达所有出生点与所有资源簇。
6. 实例化混沌巢穴与守护单位（含数值倍率）。
7. 预渲染地形分块缓存（异步分批，每帧最多 4 块，显示加载进度）。

### 5.8　地图校验规则（P0）

| 校验项 | 判据 | 失败处理 |
| --- | --- | --- |
| 数组长度 | 三个数组长度均等于 `w*h` | 拒绝加载并报错 |
| 出生点合法 | 3×3 全可建、全可通行、高度一致 | 拒绝加载并报错 |
| 对称性 | 按 `symmetry` 检查地形 / 高度 / 资源的镜像一致 | 警告并继续 |
| 连通性 | 出生点之间、出生点与资源簇之间，按 `foot` 与 `track` **各校验一次** | 拒绝加载并报错 |
| 资源总量 | 两侧资源总量差 ≤ 5% | 警告并继续 |
| 资源可达 | 每个资源格的四邻至少 1 格可通行 | 自动把该格改为 `rot` 并警告 |
| 混沌巢穴 | `scale` 必须在 [0.8, 1.6] 内，且巢穴周围 3×3 必须可通行 | 修正为边界值并警告 |

### 5.9　随机器与装饰物（P1）

地图上的纯视觉装饰（叶脉点、碎屑、孢子光点、岩片）使用 `RNG.map` 在加载时生成一次，位置基于格坐标的确定性哈希，**不参与逻辑**，不随存档保存（读档后按同样规则重生成）。装饰物数量上限：每 100 格 ≤ 6 个。

**混沌单位外形的随机化**：每局开局用 `RNG.map` 为每个混沌单位生成一组外形参数（凸起数量、眼球位置、体色偏移 ±8%），使同类混沌在同一局内也各不相同。这组参数**不影响任何数值**。
