## 4　核心循环与命令系统

### 4.1　三层核心循环

《一叶》的经济不是单一资源流，而是**源质（Essence）+ 残骸（Corpse）+ 回收（Salvage）**三条相互供血的通路：源质矿脉与晶簇是稳定的生产端，残骸是战场上被摧毁单位的「二次矿」，《一叶》关键词「回收」则把已经造出来的东西重新变回源质。三层循环分别对应这三条通路的放大：

| 层级 | 周期 | 玩家动作 | 系统反馈 | 设计目的 |
| --- | --- | --- | --- | --- |
| 微循环 | 1–5 秒 | 选中部队 → 下达命令 → 观察执行 | 选择圈、目标点虚线、单位 8 向转向（每 tick 最多 1 档）、命中火花与溅射圈、残骸生成 | 每一次点击都必须有**立即的视觉与听觉反馈** |
| 中循环 | 30–120 秒 | 派拾荒者/奴隶/汲取体采源质 → 放吞矿菌毯等卸矿点 → 排队出兵 → 前线交火并留下残骸 | 侧边栏进度条、单位出厂播报、小地图上的敌我态势变化、残骸倒计时（1200 tick） | 让玩家持续做**有取舍的决策**（源质是拿去造兵，还是留作主动回收的备用金） |
| 宏循环 | 3–8 分钟 | 扩张源质矿脉与晶簇 → 攀科技树（侵蚀还要「腐蚀掠夺」）→ 用残骸经济反哺科技 → 战争单位登场推进决战 | 效率条（实际产值 ÷ 初始设定值）、科技解锁、解放播报、战争单位登场、胜负结算 | 提供**阶段性的成长感**与终局目标；战争单位（`py_wrath` / `dm_warlord` / `er_core_unit`）是宏循环的终点 |

**三条通路的精确数值（P0，全部取自第 8 章）**：源质矿脉每格 400、晶簇每格 800；基准采集速率 40 源质/秒（原初 ×1.2 = 48，主宰奴役 ×1.4 = 56，侵蚀无加成）；采集容量 240、卸货速率 240/秒；主动回收返还造价 **50%**；侵蚀从残骸回收 **10%**（建成 `er_furnace` 后 **25%**）；残骸保留 **60 秒**。

**反馈即时性原则（P0）**：玩家下达的**任何**命令，无论最终能否执行，都必须在**下达当帧**给出反馈——能执行则立即显示目标点与路径，不能执行则播放「命令无效」音效并在光标处显示一行红色原因文本（例如「无法抵达该位置」）。禁止出现「点了没反应」的情况。唯一**不算失败**的例外是右键点在**残骸**上：对非侵蚀阵容，它不产生命令，而是弹出残骸信息气泡（见下节决策树第 3 条），这是**有反馈的「无命令」**，不得播放 `ui_deny`。

### 4.2　玩家命令全集（P0，实现方必须逐条实现）

命令在鼠标/键盘事件产生时进入**命令队列**，在**下一个逻辑 tick 的开头**统一结算，保证同一 tick 内的多次操作按顺序生效。所有命令携带 `playerId`、`issuedTick`、`sequence` 三个字段用于回放与冲突消解。

> **命令键名不可改名（P0）**：下表 34 个键名是《一叶》逻辑层的**唯一权威 API 名**，第 16 章的回放命令枚举与之 **1:1**。本次重写把每条命令的**语义、目标合法性与失败反馈**全部改写到《一叶》设定下，但键名**一字不改、一行不增不减**。其中三个键名（`sell`、`deploy_mcv`、`pack_conyard`）与一个键名（`fire_superweapon`）沿用了实现层的历史拼写，它们是**逻辑层不透明标识符**，其《一叶》语义由本表的「目标选择规则」列定义：`sell` = **主动回收**、`deploy_mcv` = **部署迁徙母巢扩张点**、`pack_conyard` = **打包核心重新部署**、`fire_superweapon` = **战争单位的招牌能力**。

> **命令名与物理按键的权威划分（P0）**：本表定义的是**命令语义与键名**，是全文唯一权威；表中给出的按键是最常用的默认绑定。**完整的物理按键布局（含镜头平移、缩放、标签页、存档、姿态备用键等）以第 13.5 节「键盘操作总表」为准。** 两者若出现字面冲突：命令键名以本章为准，物理按键以第 13.5 节为准。已裁决的关键冲突：`A` = 攻击移动、`S` = 停止、`D` = 展开/打包（仅当选中可部署核心单位）、`G` = 原地防守（HoldGround）、`H` = 守卫（Defensive，无选中时跳回核心）、`Ctrl+G` = 好斗、`Ctrl+H` = 停火；`W`/`A`/`S`/`D` 在**没有选中己方单位时仅作镜头平移**。

### 4.3　右键智能命令决策树（P0）

右键是最高频操作，必须按下列**固定优先级**从上到下判定，第一个命中的分支生效：

```js
function resolveRightClick(world, player, targetInfo, selectedUnits) {
  const T = targetInfo;                       // { kind, entityId, tile, terrain, isOre, isCorpse, corpseFaction }
  // 1. 玩家处于放置模式：右键 = 取消放置
  if (player.placing) { player.placing = null; refund(player); return; }
  // 2. 有选中单位，且点击到敌方实体（且已知/在视野内）
  if (selectedUnits.length && T.kind === 'entity' && isEnemy(T) ) {
    return order(selectedUnits, T.isBuilding ? 'attack' : pickAttackOrForce(T), { targetId: T.entityId });
  }
  // 3. 【《一叶》新增】点击到残骸：按阵容分流
  if (T.isCorpse) {
    if (player.faction === 'EROSION') {
      // 侵蚀：回收残骸（10%，建成 er_furnace 后 25%）；已建成 er_furnace 时 10 格内会自动回收，无需本条命令
      return order(selectedUnits, 'harvest', { corpseId: T.corpseId });   // 复用采集命令的「资源点」语义：残骸对侵蚀是一种可采集资源点
    }
    // 其他阵营：显示残骸信息气泡（原始单位名 + 最大体力 + 初始造价 + 剩余秒数），不产生任何命令
    return showCorpseBubble(T);            // 纯 UI，不入命令队列，不播放 ui_deny
  }
  // 4. 点击到己方卸矿点 且 选中含载矿采集单位 → 强制卸货
  if (selectedUnits.length && T.kind === 'entity' && isAlly(T) && T.isDropoff
      && selectedUnits.some(u => u.isHarvester && u.cargo > 0)) {
    return order(selectedUnits, 'return_ore', { targetId: T.entityId });
  }
  // 5. 点击到己方受损建筑/单位 且 选中含工程单位 → 修理
  if (selectedUnits.length && T.kind === 'entity' && isAlly(T) && T.hp < T.maxHp
      && selectedUnits.some(u => u.isEngineer)) {
    return order(selectedUnits, 'repair', { targetId: T.entityId });
  }
  // 6. 点击到敌方建筑 且 选中含工程单位 → 占领（ch_lair 例外：不可占领）
  if (selectedUnits.length && T.kind === 'entity' && isEnemy(T) && T.isBuilding && !T.isNeutralLair
      && selectedUnits.some(u => u.isEngineer)) {
    return order(selectedUnits, 'capture', { targetId: T.entityId });
  }
  // 7. 点击到源质矿脉 / 晶簇 且 选中含采集单位 → 采集
  if (selectedUnits.length && T.isOre && selectedUnits.some(u => u.isHarvester)) {
    return order(selectedUnits, 'harvest', { tile: T.tile });
  }
  // 8. 点击到己方生产建筑（非右键单位）→ 设置集结点
  if (selectedUnits.length === 1 && selectedUnits[0].isBuilding && selectedUnits[0].canProduce) {
    return order(selectedUnits, 'set_rally', { pos: T.tileCenter });
  }
  // 9. 小地图上右键 → 移动（小地图优先，不参与上述实体判定）
  // 10. 默认：移动
  if (selectedUnits.length) return order(selectedUnits, 'move', { pos: T.tileCenter });
  return; // 无选中：什么都不做，但播放轻微「无效」音效
}
```

| 补充规则 | 规定 |
| --- | --- |
| Shift 队列 | 按住 `Shift` 下达命令时**追加**到命令队列末尾（队列上限 8 条），并在目标点绘制路径点序号 |
| 强制攻击 | `Ctrl + 右键` = 强制攻击（即使目标是己方单位或中立地形）；**侵蚀一旦用强制攻击主动攻击某一支混沌，该区域混沌对侵蚀的「不被主动敌对」保护即被解除**，该区域混沌转为敌对（见第 9 章索敌规则） |
| 攻击 vs 移动 | 右键点敌方**单位** = `attack`；右键点地面 = `move`；A + 左键 = `attack_move`（清空队列） |
| 残骸优先级 | 残骸分支（第 3 条）**优先于**采集与集结点分支：侵蚀玩家右键点「压在残骸上的资源点」时先回收残骸，第二次右键才进入采集；其他阵容右键点残骸上方的资源点直接进入采集（残骸分支只在**直接命中残骸格**时触发） |
| 无选中时的反馈 | 右键无选中：不产生任何命令，播放 30 音量单位的 `ui_deny` 短音，不弹文本 |
| 命令合并 | 同一 tick 内对同一批单位的同类 `move` 命令只保留最后一条；`stop` 清空全部队列 |

> **命令键名与回放枚举的对应（P0）**：本章命令键名（`select_point`、`move`、`attack_move` …）是**逻辑层 API 名**；第 16 章的回放命令枚举（`SELECT_POINT`、`MOVE`、`ATTACK_MOVE` …）是**序列化名**，两者 1:1 对应，完整映射表见第 20 章附录 B。实施方必须保证二者不出现「有枚举但无实现」或反之的情况，启动自检断言 `CMD_ENUM_NAME.length === 34`。

### 4.4　选择系统规则（P0）

| 规则 | 规定 |
| --- | --- |
| 可选中对象 | 己方**可指挥**目标：一般单位、战争单位、建筑单位（施工中的蓝图不可选）、敌方单位（仅可查看，不可下命令，用于「查看敌人」） |
| **奴役单位不可被选中（P0）** | **`dm_slave` 永远不进入选择集合**。单击奴隶只会打开只读的信息面板（显示其携带的源质、剩余体力与「奴役单位：仅执行预设 AI」），不产生选择、不绘制选择圈。因此 `move` / `attack` / `stop` / `harvest` / 姿态类等**一切命令对奴隶无效**；玩家必须在命令结算前把奴役单位从 `u` 列表中剔除，且**禁止**把「剔除」实现为静默丢弃——必须按命令反馈原则给出「奴役单位不可直接控制」的红色提示文本。奴隶被「解放」转为己方可指挥采集单位后，本条不再适用 |
| **战争单位的选择（P0）** | 战争单位（`py_wrath` / `dm_warlord` / `er_core_unit`）**可被选中并指挥**，享受框选、编队、集结点、巡逻等全部指挥功能；但由于「免疫一切正负面特殊效果」，任何**姿态**与**老兵**相关的 UI 对其显示为 **「免疫」**——姿态按钮置灰并显示「免疫」，老兵角标位置显示「免疫」，`hold_ground` / `guard` / `aggressive` / `hold_fire` 四条命令对它们**可下达但不产生任何数值差异**（仅改变 AI 的追击距离判定，不改伤害、不改体力、不改射速） |
| **混沌（中立）单位不可被选中（P0）** | 混沌单位（`ch_wanderer` / `ch_spitter` / `ch_behemoth` / `ch_moth` / `ch_lord`）不属于任何玩家，**不可被选中**（左键点击只显示信息气泡），**只能被攻击**。它们既不出现在编队里，也不出现在「全选战斗单位」的结果里 |
| 框选优先级 | 框内同时存在战斗单位与建筑时，**只选战斗单位**；只有框内没有战斗单位时才选建筑；采集单位视为战斗单位之外的第二优先级（框内只有采集单位时选采集单位） |
| 框选数量上限 | 单次框选最多选中 60 个单位（超出按距离屏幕中心由近到远截断） |
| 选择顺序 | 选中集合按 `entity.id` 升序排列，保证同一操作在不同机器上结果一致 |
| 双击选同类 | 仅限屏幕可视范围内的同类己方可指挥单位；上限 60 |
| 编队 | 每方 9 个编队；编队保存 entityId 列表；编队内单位死亡后自动移除；编队成员跨建筑与单位时只选单位（若编队只有建筑则选建筑） |
| Tab 循环 | `Tab` 在「当前选中的单位类型」之间循环切换，每次只选 1 个（用于逐个放技能） |
| 建筑单选 | 点击建筑时只选中该建筑（不追加），除非按住 Shift |
| 选择变化事件 | 选择集合变化时触发 `ui:selectionChanged`，UI 层据此重绘信息面板；**UI 不得反向修改选择集合以外的逻辑状态** |

### 4.5　单位默认行为（无需玩家操作的自动化，P0）

以下行为由单位 AI 自动处理，玩家无需微操；《一叶》的四大阵容差异**主要就体现在这一层**，这是「四阵容不是换皮」的判定标准：

| 行为 | 触发条件 | 表现 |
| --- | --- | --- |
| 自动索敌 | `stance ≠ HoldFire`，射程内有合法目标 | 炮塔每 tick 最多转 1 档，角度误差 ≤ 22.5° 后开火，不移动（Defensive/HoldGround） |
| 自动反击 | 被攻击且攻击者在追击半径内 | 转向攻击攻击者（优先级高于其他目标） |
| 自动追击 | `stance = Aggressive` 且目标撤离 | 追击至多 8 格后返回原位 |
| 自动让路 | 前方被己方单位阻挡 | 绕行或短暂等待（见第 10 章局部避障） |
| 采集循环 | 采集单位空闲且资源点有矿 | 自动前往最近**源质矿脉（400/格）或晶簇（800/格）**，装满 240 后自动回最近卸矿点（`py_maw` / `dm_extract` / `er_maw`），循环直到玩家下新命令；原初 48/秒、主宰奴隶 56/秒、侵蚀 40/秒 |
| 奴隶预设 AI（主宰独有） | `dm_extract` 每 20 秒生成 1 名 `dm_slave` | 奴隶**完全不接受玩家命令**，由预设 AI 自动完成「前往最近资源点 → 装满 → 回矿产中心卸货 → 循环」；不占人口、不花源质；只在控制节点被摧毁时被「解放」 |
| 原初脱战再生 | 己方单位脱战满 8 秒 | 每秒回复 **2%** 最大体力；己方建筑脱战满 8 秒后每秒回复 **1%** 最大体力；`py_regen`（再生池）半径 8 格内额外每秒 +1.5%，可与脱战再生叠加 |
| 主宰护盾回复 | `dm_reaper` / `dm_warlord` 脱战满 5 秒 | 护盾上限 = 最大体力 × 0.5，以 **10%/秒** 回复；护盾优先吸收伤害，本体体力低（收割者 400）是其主要弱点 |
| 主宰电力自维护 | 建筑电力余额为负 | 生产速度 ×0.5、防御建筑射速 ×0.5、`dm_radar` 雷达失效；单位本身**不需要电力**，断电不影响已出厂单位 |
| 混沌吞噬残骸 | 混沌单位体力不满且 6 格内有残骸 | 优先放弃当前目标，前往吞噬残骸，按残骸的**最大体力**的 100% 恢复（关键词「残骸」的第三套用法） |
| 混沌中心强化 | 混沌单位每 5 tick | 数值倍率 = `clamp(1.6 - 1.2 × (d / dMax), 0.8, 1.6)`，`d` 为到地图中心的距离；`ch_lord` 存活时其区域内混沌攻击力额外 +25% |
| 侵蚀自动回收残骸 | 侵蚀单位 10 格内有残骸（需已建成 `er_furnace`） | 自动吸收残骸，按其**初始造价**的 25% 返还源质；未建成残骸熔炉时只能靠玩家主动右键残骸回收 10% |
| 侵蚀不被中立敌对 | 侵蚀单位进入混沌区域 | 混沌**不会主动攻击**侵蚀，除非侵蚀先攻击过该区域的混沌；这是侵蚀独有、不可被其他阵容复制的路径优势 |
| 自动回防 | 建筑被攻击时（P1） | 屏幕外的己方单位不自动回防；仅在防御半径 12 格内的单位前往支援 |
| 残留命令清理 | 目标死亡 | `attack` 命令目标死亡 → 转为 `guard` 原地待机；`attack_move` 目标死亡 → 继续前往目的地 |
| 残骸生成 | 任意单位（含战争单位、奴役单位、混沌单位）体力归零 | 原地留下残骸，携带**最大体力**与**初始造价**两项信息，保留 **60 秒（1200 tick）**；战争单位的残骸不产生可回收价值，但**仍可被混沌吞噬** |
